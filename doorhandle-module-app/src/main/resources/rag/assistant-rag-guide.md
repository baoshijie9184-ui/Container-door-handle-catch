# 智能助手 RAG 能力说明

## 知识来源和用户问法

RAG 用于帮助解释系统功能入口、操作步骤、状态含义和排查方法。例如：“质检队列的返工任务下一步怎么处理”“检测模型上传后怎样校验和发布”“某个工单的追溯链路怎么看”。查询具体业务结果时应提供真实任务编号、工单号、批次号或筛选条件，并由当前账号有权使用的业务工具取得实时依据。

系统说明来自 `chat-assistant.rag-sources` 指定的手册、助手说明和 ECS 可读取的部署文档。检索上下文保留来源标题；回答应说明所依据的资料，不能把通用说明当作某次检测的实际结果。

启用用户知识资料后，助手还可以引用当前账号可读的资料。私人资料仅本人可读，企业资料按当前权限读取；候选必须再次核对 SQL 中的当前版本、生命周期和文字段落。引用保留资料编号、版本、段落和知识库入口。SQL 文字保存与向量索引就绪分开显示，旧版本或归档资料不参与当前检索。

## 系统说明的检索流程

源码默认使用 Qdrant 作为向量库，通过受保护的 Mem0 内部桥接复用 BGE-M3 的 1024 维 embedding。系统说明、用户知识、Mem0 记忆和已发布经验使用不同集合，不互相混用模型或账号范围。Mem0 的提炼 LLM 与 embedding 配置独立。

系统说明检索的流程是：原始问题 → 按开关选择查询重写 → Qdrant 候选检索 → 按开关选择 rerank → 带来源的上下文 → 助手回答。命中有效的系统上下文缓存时可以复用结果，不必每次重新调用模型。

下面的查询重写和 LLM rerank 针对系统说明；用户知识资料另走当前账号的授权检索与 SQL 引用复核。

## 查询重写和 rerank 都有条件

`chat-assistant.rag-query-rewrite-enabled=true` 时，系统尝试把口语化问题改写为适合检索的表达。例如，“这个质检咋处理”可以补充已有意图中的质检状态、人工复核、返工复检等检索词，但不能编造任务编号、人员或业务事实。关闭开关、模型不可用、调用失败或结果为空时，继续使用原始问题。

`chat-assistant.rag-rerank-enabled=true` 且候选数量超过 `rag-top-k` 时，系统尝试由 LLM 重排候选。关闭开关或候选不多于 top-K 时，按原顺序取候选；模型不可用、调用失败或未返回有效排序时也保留原顺序。关键词降级检索得到的候选同样遵守这个开关。

重排优先保留能够直接回答问题的功能入口、操作步骤、状态解释和排查资料，仅有相同关键词不代表它能回答当前问题。

## 两种启动模式决定何时构建索引

- `REINDEX`：读取 ECS 中可用的 `rag-sources`，将 Markdown 按标题和长度切分为系统片段，使用当前模型空间索引；已存在且文本、元数据一致的片段可复用，不是每次启动都重新请求 embedding。
- `PRESERVE_EXISTING`：只连接固定提交与私有凭证绑定的既有 Qdrant 目标，核对完整目录、模型空间和存储向量证明，不重新读取新文档或重建向量。凭证或集合不匹配时拒绝启动，不自动改写索引。

Chroma 及旧 hash256 向量只保留作明确的历史来源核验，不是新运行后端，也不是 Qdrant 故障时的自动回退。旧资料需要通过候选迁移、重嵌入和独立恢复验证后才能进入新的目标；修改本页不会自动改写保全模式中的旧资料。

## 向量不可用时怎样降级

当向量服务不可用、索引尚未就绪或没有返回候选时，系统尝试对本进程已经加载的系统片段做关键词检索，并将上下文标明为关键词降级。LLM 不可用时，查询重写使用原问题，重排保留候选原顺序。

`PRESERVE_EXISTING` 不加载本地系统片段，因此向量不可用时可能没有系统知识上下文；这不表示保全数据丢失。用户知识资料可在当前授权、当前有效版本的 SQL 文字上单独降级检索。

`chat-assistant.rag-enabled=false` 会停止提供系统 RAG 上下文；用户知识资料的启用和权限独立控制。关闭语义检索不等于自动启用旧 Chroma。

## 资料不足时的回答

如果没有相关片段或实时数据不足，助手应说明缺少依据，并告诉用户需补充哪些编号、页面名称或筛选条件。不得编造页面入口、按钮、模型版本、人员、设备状态、统计数值或检测结论。

可提出核实建议，例如到检测记录、质检队列、模型管理、工单追溯或批次追溯查看实际记录；建议与已经取得的事实分开表达。

## 部署状态和运维入口

本页说明源码中的实现能力与操作条件。实际部署版本、服务状态及旧知识迁移结果，分别查当前固定提交的本地 Jenkins/ECS 回执；文档或配置存在不表示已经上线或完成验收。

应用、中间件、数据和测试都在 ECS，部署复用仓库的 Compose 和本地 Jenkins 流水线；本地只编辑和构建，不在电脑上启动 Qdrant、Chroma、后端或前端预览。运维配置与验收入口见 `docs/ECS-only-runtime.md`、`docs/本地Jenkins-CICD.md` 和 `docs/middleware/semantic-vector-storage.md`，私有凭据不写入知识文档。
