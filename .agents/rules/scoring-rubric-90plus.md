# 本阶段量化评分卡与 90+ 交付目标（`java-cloud`）

本评分卡为全队统一验收标尺。本阶段目标：**全部维度与全部核心页面均达到 ≥ 90 分（百分制），且零红线扣分**。

## 1. 页面视觉高级感与“去繁就简”评分卡（100 分制）

适用对象：Vue 3 主站核心页面 + React 18 独立 Agent UI 核心页面。
评估依据：真实运行环境截图（桌面 `1440×900` + 窄屏 `390×844`）+ 主路径点击步数实测。
**目标线：每页 ≥ 90 分，全站加权均分 ≥ 90 分，红线扣分 = 0。**

| 维度 | 满分 | 90+ 标杆达标标准 | 扣分示例 |
|---|---:|---|---|
| **1. 美观度与视觉规范** | **20** | 配色克制统一（主色/语义色明确，无高饱和乱撞）；字体字号层级规范；图标线宽/风格一致；Vue 主站与 React Agent UI 共享一致设计语言 | 风格割裂（-3~5）；刺眼配色/杂乱边框（-2~4）；文字对比度不足（-2~3） |
| **2. 层次感与信息结构** | **25** | 3 秒内看清核心指标与唯一主按钮；标题/核心数据/辅助信息三层区分清晰；表格列宽与卡片密度均衡，不抢视觉焦点 | 主次不分/按钮权重混乱（-4~6）；信息过载密不透风（-3~5）；标题区臃肿（-2~4） |
| **3. 高级感与细节质感** | **25** | 留白与呼吸感充足；栅格严格对齐；圆角/阴影/分割线克制柔和；空状态、加载态、提示反馈精致，无粗糙框架默认皮 | 拥挤/无呼吸感（-4~6）；对齐偏差/截断省略不当（-2~4）；默认粗糙表单/弹窗（-3~5） |
| **4. 功能不繁琐（去繁就简）** | **30** | 高频主路径 **≤ 3 步直达**；无弹窗套弹窗；低频/高级配置默认折叠或收拢；无重复入口、冗余标签页与无效按钮；表单只保留必要字段 | 主流程 4 步（-4）；弹窗嵌套（-5）；功能堆砌/冗余配置平铺（-4~8）；无用装饰按钮（-2~4） |

### 红线硬扣分项（触碰任一项即判定该页未达标）
- 布局错位、元素遮挡、横向意外滚动条或文字重叠：`-10 分 / 处`
- 控制台 `console.error`、未捕获异常或接口报错白屏：`-15 分 / 处`
- 核心业务主路径超过 5 步或强迫填写非必要字段：`-10 分 / 条`

## 3. Apifox 核心读（QPS）与核心写（TPS）压测评分细则（单机 Docker 环境）

> 硬件/容器基线：`backend` 3G、`mysql` 2G、`redis` 512M、`kafka` 2G、`qdrant` 1G、`mem0` 2G（合计约 12.5 GiB）。

| 压测项 | 代表接口 / 链路 | 压测梯度 | 满分（4 分）目标 | 稳定性底线 |
|---|---|---|---|---|
| **热点读 QPS** | 登录态校验、首页统计概览、设备/模型下拉与配置 | 10→30→50→100 VU（5 min） | **≥ 300 QPS**，P95 ≤ 100ms，Redis 命中率 ≥ 95% | 错误率 < 0.1% |
| **业务分页读 QPS** | 任务列表分页、质检记录详情、报告列表、会话历史 | 10→30→50 VU（5 min） | **≥ 100 QPS**，P95 ≤ 300ms | 无 > 500ms 慢 SQL |
| **核心业务写 TPS** | 人工复核提交与标注、报告草稿保存/提交、消息持久化 | 10→20→40 VU（5 min） | **≥ 40 TPS**，P95 ≤ 500ms | 错误率 0%，幂等 100% |
| **异步检测写 TPS** | 检测任务创建 → MySQL 事务 → Kafka 派发（含 OSS 协调） | 10→20→30 VU（5 min） | **≥ 25 TPS**，P95 ≤ 800ms | Kafka 零丢失，Worker 无雪崩 |
| **AI/向量舱壁隔离** | Qdrant 检索 + Mem0 召回 + Agent TTFT（独立低并发） | 5→15 VU | 建立 P50/P95 基线，验证 Resilience4j 舱壁生效 | 不拖垮核心业务 QPS/TPS |
