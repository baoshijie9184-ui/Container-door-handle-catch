# Agent 对话内工具记录

本轮在原有 AG-UI、A2UI 与 Spark Design 集成之上，按参考截图调整工具调用展示。Vue 主站和 React 独立工作台共用状态归并、历史读取与样式，不增加依赖，不更改部署配置。

## 已实现

- 每条助手回复有独立的工具记录，默认折叠，不再把全部调用堆在对话外。
- 摘要显示唯一调用次数和实际失败次数；同一调用的开始、结束回执按 `callId` 合并，不重复计数。取消与失败区分。
- 展开后使用细线时间轴、语义图标、工具中文名、原始名称、真实耗时，支持单条详情和复制。
- 仅收到调用结束事件不能视为成功，只有实际结果回执才显示“已返回”。连接中断后尚无回执的调用显示“未收到返回”，停止转圈。
- 已有明确运行关联的历史消息在展开时按需读取 `/api/agent/runs/{runId}` 和分页事件；先验证当前会话一致性。运行中的受控会话可读取实时回执，暂停/等待等原有控制功能保留。
- 账号权限撤销或运行归属不匹配时清除记录，旧会话迟到响应不会覆盖当前会话。读取有页数、缓存和展示数量限制，截断时使用“最近记录”文案。
- 保留正文 Markdown、A2UI 动态结果、业务入口、附件及会话管理。支持键盘焦点、响应式布局与减少动态效果。

## 数据来源及边界

工具状态来自已有执行日志的 `TOOL_STARTED`、`TOOL_COMPLETED`、`TOOL_ERROR`、`TOOL_CANCELLED` 以及对应 AG-UI 回执。普通回答里的文字不会被识别成工具记录，不生成“已思考”、命令或文件修改记录。

后端仅补充消息与执行关联元数据：`AgentChatSessionApi.Reply.messageId`、`ChatMessageResponse.runId`、`ChatStreamEvent.execution`，AG-UI 使用 `doorhandle.execution.v1` 发送持久化后的运行编号和消息编号。原构造器保持兼容。Vue SSE 转发实际工具类型、编号、名称和执行助手，不转发工具原始参数和私密错误正文。

已有 `AGENT_CARDS` 消息中的 `runId` 可以在重新打开页面后恢复执行关联。纯 `TEXT` 消息的即时回执在本次页面会话中按确切消息编号缓存，限制 80 条。后续已增加 [消息执行关联持久化](Agent消息执行关联持久化-20261028.md)：显式应用 V66 后，新保存回复可以通过服务端准确关联运行并在刷新后恢复。未迁移环境、迁移前的纯文本旧历史仍不猜测关联；这类记录可通过原执行追溯入口查询。

目前真实工具具有读取文件和生成资料等能力，未提供源文件修改前后内容或补丁回执，因此没有制作截图二中的代码 Diff 面板。后续有经校验的修改回执再接入，不能用文件读取或文件生成冒充代码编辑。
