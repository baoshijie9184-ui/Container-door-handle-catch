## 数据归属与开关

复用 AgentScope Java 2.0.4 的 `ConversationCompactor`、现有结构化摘要校验和运行检查点，没有引入新的执行框架。每个主 Agent、专业子 Agent 各持有自己的压缩器及调用预算。摘要调用使用原任务固定的模型配置和模型路由。

App 模块通过 `AgentContextDataApi` 提供本人会话历史、来源重新鉴权、文件存储和分支消息映射。AI 模块只操作自己所属的上下文、来源与工作台表。私有文件下载时，App 再通过 `ContextFileAccessApi` 向 AI 核对卸载资料的原始来源，不直接访问 AI 表。

新增 V44 的七张 AI 表：摘要头、不可变摘要版本、卸载回执、上下文审计、工具来源、回答来源和任务启动快照；V45 为 App 新增精确附件切点快照。根目录 SQL 与各自模块 classpath 副本同步维护，尚未应用数据库。

```properties
AGENT_DURABLE_CONTEXT_ENABLED=false
AGENT_CONTEXT_OFFLOAD_ENABLED=false
```

默认关闭。启用持久上下文要求工作台、恢复、持久专业任务及上下文压缩已经启用；不兼容旧的一次性专业委派模式。启用卸载还要求文件工作区启用。最终集成验收前不改变生产配置。

## 主 Agent 跨轮历史

新逻辑任务先固定本轮之前的历史切点、真实用户请求及检索参考输入。按消息 ID 分页读取切点以内的历史，加载通过哈希、策略与当前来源权限检查的主会话摘要，再加入未覆盖消息。当前用户请求与参考输入独立拼接，避免把当前问题重复当作历史。

摘要保存覆盖切点、版本、策略、来源编号、历史摘要、结构化 JSON、SDK 消息及被替换的原始前缀。摘要正文、来源及原始前缀共同参与完整性校验。生成前固定预期版本，生成后重新核对历史；保存时锁定摘要头并比较版本，冲突时停止应用。审计和摘要同事务保存。

SDK 继续选择保留近期消息及工具配对的安全切点。结构不合格、内容未缩短或模型摘要失败时不采用该摘要；持久化、审计、版本或完整性失败则中止当前上下文处理。不会截断历史后继续声称已读取全部内容。

现有配置每 Agent 默认最多三次摘要调用；每次重建最多 32 页、每页 128 条，最终工作上下文还有消息数及字符上限。达到边界明确停止，原始聊天仍保留。需要后续验收长会话资源边界及摘要保真度。

运行中的压缩快照按逻辑任务区分；专业摘要按子会话编号隔离。原任务恢复使用 SDK 检查点、工具回执及原始任务输入，不以聊天摘要重新执行已经完成的工具。初始化标记、种子来源和首次上下文检查点同事务保存；已初始化但检查点缺失时拒绝重放。

## 来源与撤权

工具来源从已登记的服务端结果结构提取，包括任务、报告、设备、告警、检测模型、工作区文件、调研来源和子 Agent。文件固定内容 SHA-256，调研资料核对归属、有效期和摘要；角色也参与来源约束。提议卡片是来源记录，不是操作授权。

业务 JSON 的 `source` 字段不能自行声明工具身份。现在仅在实际工具调用返回时，按受信工具名称检查相应结构并登记来源；后续压缩使用持久回执，不再重解析已卸载的文本摘录。普通网页或 Fetch 正文即使包含相似的业务 JSON，也不会据此登记业务来源。受控结果缺少必要编号或结构时明确失败，不保存残缺来源。

业务原图的合成展示编号不当作工作区文件编号。原图来源绑定已关联任务、服务端原图编号及资源版本，由 App 经 contracts 调用业务模块的本地元数据鉴权；不在上下文核对期间重复下载 OSS 图片。文件目录中的业务文件另按真实所属对象、编号及目录元数据摘要核对；取消关联、资源撤权或目录变化后失效。目录摘要不是文件内容摘要，原图资源版本也不声称验证每次 OSS 字节未被外部改写。

父 Agent 读取子任务时，固定当时来源集合，不让后续子任务追问动态改变原回执。展开时检查当前会话归属、循环及数量上限；已完成子任务缺少来源回执时停止。已完成工具复用原来源快照并重新鉴权，不因子任务后来完成或追加要求而重写旧回执。

单次来源历史读取最多 512 条、合并最多 2000 个来源，单份来源 JSON 最多 1 Mi 字符；超限明确停止，不只取前半部分继续推理。来源类型、编号与版本也检查边界，损坏内容不当作空来源。

回答保存时关联该任务实际使用的来源，主 Agent 读取子任务时沿用子任务来源检查。读取摘要、继续推理、读取旧 SDK 工具结果及下载卸载文件时重新鉴权。原资料撤权时，摘要失效；重建历史中的受影响片段只向模型提供不可用提示，原聊天记录不改写。

未记录可信来源的旧助手回答保留在 UI 和数据库，在新模型上下文中使用明确提示替代，关键业务事实需要重新查询。这是旧会话的兼容边界，不把早期回答补造为可信工具证据。来源服务不可用或数据损坏时不按“权限仍然有效”处理。

## 已完成工具结果卸载

完整原始工具回执先由工作台保存。纯文本成功结果超过 16 KiB 时，在当前账号持久文件卷创建 `context` 资料，并保存绑定账号、会话、Agent、工具调用和内容 SHA-256 的卸载回执；来源清单另存摘要校验。沿用文件配额、字节校验与事务失败清理，不创建任意路径接口。

模型收到最多 1,200 个 Unicode 字符的摘录、服务端文件编号、哈希及读取说明，明确摘录不是全文。单份卸载上限 2 MiB，超过时停止处理而不静默截断。失败结果保留原有失败语义，不转换为成功资料。

`read_context_file` 只接受当前 Agent 绑定的文件编号、哈希、偏移和读取长度。偏移按 Unicode 码点计算，每次最多 16,000 字符，返回 `nextOffset` 与 `end`。读取结果不再次卸载，避免递归。不同 Agent 不直接互读资料，主 Agent 通过原有专业任务结果汇总。

普通 `read_workspace_file` 拒绝读取 `context` 文件；本人通过文件面板预览或下载时仍需重新核对原始业务来源。仍被执行证据引用的资料不能通过普通移除接口删除。本文未实现上下文资料保留期或物理清理任务，配额满时须明确失败。

## 分支与界面

Fork 创建空目标会话，然后完整复制原切点之前的消息，不额外插入欢迎语。后端验证父子关系、消息顺序和内容后映射消息编号，继承不超过切点且当前仍授权的主会话摘要，并重新绑定目标历史哈希。原始来源先在父会话固定，再在目标会话重新鉴权，不复制活动子执行和审批。仅继承目标会话在切点已拥有且仍授权的上下文文件；专业资料保留为无活动执行对应的继承范围，不改成主 Agent 可直接读取的资料。候选回执超过 1000 份明确失败，不静默截断。

启用新功能后，保存助手回答时持有账号文件锁，同事务记录当时完整的文件/业务引用快照及校验摘要。消息保存、快照和必要审计任一失败均回滚。Fork 按快照继承仍存在的引用，复制历史回答时同时保留原快照，因此再次从分支的早期回答 Fork 不会带入后续附件。快照最多记录 2,000 份文件和 20 个业务引用，超限明确失败，不保存残缺快照。

旧回答没有精确快照时不伪造回填，只继承严格早于旧切点时间的引用；同秒无法证明先后的附件不自动复制。两入口显示兼容提示，可由用户重新上传或关联。该策略不猜测旧文件先后关系；精确切点的并发与嵌套分支尚待验收。

Vue 与 React 工作台同步增加“上下文资料”文件分组、持久摘要范围、版本、前后字符数及卸载字节数/哈希。字符统计仅为上下文估算，不当作供应商 Token 或账单；不向前端返回 SDK 私有状态或服务器路径。
