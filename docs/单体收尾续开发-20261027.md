# 单体收尾续开发（2026-10-27）

本轮按用户“继续开发，先开发，不测试”的要求，只修改源码、配置样例和文档。以下是实现说明，尚未运行测试、解析/编译校验、构建、应用、真实供应商调用、Jenkins 或部署。上一轮 `c84b4604` 候选的通过结果不代表这些新增改动已经通过验收。

## 执行证据与角色范围

新增 `AgentAnswerEvidence`，通过现有 AgentScope 2.0.4 的 `onActing` / `ToolResultEndEvent` 中间件事件收集本次尝试实际完成的委派或后台登记回执；不增加模型请求，不自动重试工具。主站和独立 Agent 入口共用原执行门面。

当最终文本在句首宣称“我将委派”等已识别的交接动作，而本次尝试没有对应回执、所属逻辑任务也没有已登记的专业子任务时，拒绝把该文本保存为成功回答：追加不含正文的 `ANSWER_REJECTED` 事件，执行转入异常/待核对路径；应用通过契约中的安全异常提示原因。前端执行追溯新增对应文字，不将其误标为模型额度错误。

本轮 guard 只覆盖已识别的无回执委派说法，不是对任意业务事实进行语义校验；流式过程中已经发出的片段也不由此回收。续接同一逻辑任务时核对本人、会话、父任务与逻辑任务绑定的已登记子任务，不把已持久化的委派误当成从未发生。

角色与专业 Agent 共用补充规则：权限或能力范围不足应直接说明，不能当作参数缺失反复追问；越权查询拒绝不用于推断资源是否存在，不索取他人凭据、不建议切换身份、不擅自改查企业总量。员工的任务设备名称不等于企业设备实时在线状态。已有工具白名单和数据权限继续负责实际授权。

等待文案按所属专业子任务的真实状态区分排队、运行、等待回答、等待计划及待核对；不再将所有等待状态称作“后台运行”。本轮未增加自动回答或取消用户问题的逻辑。

## 记忆分类 v6 草案

`memory_service/duplicate_review.py` 从当前 v4 升为新的 v6 开发稿；此前 v5 只读试验失败记录保留，不把该试验当作已采用版本。

一次原有批量模型请求同时返回对象/主题关系、事实是否等价、要求是否不相容和最终标签。新增 `semantic_labels` 校验：

- 对象关系仅限同一对象、有关联上下文、无关、不确定；同一对象的权限规则与展示偏好不能仅因属性不同而被定义为无关。
- 逐项编号、字段、布尔类型及标签必须完整且一致；原文摘录分别绑定原记忆与候选，最多各 80 字。
- DUPLICATE / CONFLICT 需要同一对象及适用范围；RELATED / DISTINCT / UNSURE 与返回的维度分析须一致。
- 任一响应格式、证据或维度矛盾均沿原失败关闭路径返回 UNAVAILABLE，候选维持 UNSURE，不自动再请求模型，也不执行删除或合并。
- 摘录只在本次请求内校验，不另存一份私人正文；结果 JSON 仅保留已校验的维度。人工保留/停用、版本、账号范围、摘要和确认规则保持。

后续诊断入口已接同一生产解析函数，不会只检查最终标签而忽略结构化分析。旧版本候选仍按其旧协议读取；v6 提示词不能在没有 v6 解析器的旧候选上冒充新功能验收。

未改变既有固定集或期望，没有新增实测成绩。原 v4 的 31/32 和 v5 的 47/48 仍只是各自版本的历史结果。旧单元夹具中只返回标签的模拟响应需要在后续测试阶段适配 v6；结构化输出是否改善真实模型质量仍待验证。

## 免费模型配置准备

新增 `deploy/bailian-free.env.example` 配置片段，供后续人工合并到已有私有环境：聊天主模型为既有百炼 DeepSeek Flash，自动备用仅列百炼 Qwen Max 和 GLM，提炼单独选择 Qwen Max。没有修改实际密钥、网关、服务器环境、向量模型或当前部署，也不重放 Flash 的旧请求。

样例不代表应用时仍有额度；每个模型分别核对免费额度和用完即停。该保护由百炼控制台执行，不是写入环境变量后就能由应用保证。没有增加直连付费模型作为自动备用，没有启用可选 LLM 凭据治理或恢复密钥流程。

## 发布准备接线

Jenkins 新增并接入三个输入：

| 参数 | 行为 |
| --- | --- |
| `COMPATIBLE_RUNNER_IMAGE` | 仅隔离演练使用已存在且已审阅的不可变 runner sha256；沿用脚本现有协议和归属保护 |
| `REHEARSAL_MEMORY_EXTRACTION_MODEL` | 仅覆盖隔离副本的提炼模型；由现有脚本继续校验实际注册配置，不变更向量模型 |
| `BUILD_NPM_REGISTRY` | 仅本次远端构建进程使用 npm 官方源或既有镜像源，默认官方源；不修改生产私有环境或锁文件 |

演练报告还会核对显式选择的兼容 backend、runner 和提炼模型；后两项此前脚本支持但流水线未传递。生产发布开关仍默认关闭，兼容基线不等于可以退回原 ci-22；没有通过更换标签、放宽声明或跳过备份来绕过回滚保护。

最终 CI、真实 MySQL、模型质量、两入口、升级/回滚及生产发布后验证仍待进行；一致性备份、迁移方案和已有五个运维单元的实际安装也仍待发布阶段完成。本轮没有运行这些操作。
