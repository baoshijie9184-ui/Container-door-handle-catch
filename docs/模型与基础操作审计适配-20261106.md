## 实际持久化

| 原表 | 当前写入与读取 | 保留边界 |
| --- | --- | --- |
| `model_operation_log` | `ModelOperationAuditStore` → `audit_event` 的 `DETECTION_MODEL_OPERATION` | `detection_model_id` 是当前模型的真实外键；原操作者名称和备注进入显式 payload；原时间转换为 UTC，并保留旧 DATETIME 字符串 |
| `operation_audit_log` | `InfraOperationAuditStore` → `audit_event` 的 `INFRA_OPERATION` | action、resource_type、resource_id、result/outcome、时间使用明确字段；操作者、请求方法、路径、完整 change_summary、IP 和旧时间进入固定结构 payload |

删除两个旧 MyBatis 表 Mapper，实体类只作为 DTO/写入参数使用。没有旧表兼容视图、自动 SQL 重写或新业务表。两个模块复用既有 framework 审计仓储，测试复用项目已有的 MySQL Connector。

原日志只保存操作者名称，无法证明稳定数字账号归属；因此不依据用户名、`system` 字样或默认企业回填 `owner_user_id` / `actor_user_id`。这些字段保持 NULL。检测模型日志仍是原企业共享查询范围，原 HTTP/控制器权限没有放宽。

模型查询继续按模型筛选、时间和记录顺序倒序排列。接口 `id` 现在为共享审计表的游标，原日志主键单独保存在 `legacy_source` / `legacy_key`，并以 DTO 的 `legacyId` 返回，避免把两套编号混用。新记录的业务时间明确按 UTC+8 生成并转换到审计 UTC；返回新记录时转换回现有业务界面使用的 UTC+8。迁移历史记录继续返回保存的原 DATETIME 值。

## 级联例外与事务

模型日志延续 V3 的 `ON UPDATE CASCADE`、`ON DELETE CASCADE`。这属于共享审计通常“只追加”原则的明确例外：修改模型主键会更新此类记录的当前外键；删除模型会删除它的原模型操作日志。其他审计类型和其他模型的日志不受影响。独立的模型文件保留记录与业务操作审计继续承担模型删除后的证据保留职责。

当前模型 ID 不在 payload 或字符串 `resource_id` 重复存储，避免主键级联更新后产生矛盾。公共 `37-audit-guards.sql` 限定只有模型操作类型可以持有 `detection_model_id`，由 `40-relations.sql` 安装真实外键。两份公共文件由根代理维护。

模型日志写入要求调用方的真实数据源事务，发布、设默认、停用、归档、重新校验与模型上传登记的数据库修改和日志一起提交或回滚。基础审计在已有事务中参与同一事务；HTTP 完成回调没有业务事务时单独开启审计事务。基础审计记录 HTTP 完成情况，不把 HTTP 成功等同于后台任务最终成功。

基础审计原有失败类别继续保留，HTTP 失败同时记录原请求方法、路径、状态及服务端看到的远端 IP。不会读取请求体、Cookie 或认证头，也不新增异常消息中的私密值。移除旧的 8,192 字符 JSON 截断，避免截断后的无效 JSON 使证据丢失；长路径完整保存在请求快照，不能放入原 128 字符资源标识时该标识留 NULL。

原 `change_summary` 是独立 JSON 列，不是整个旧行的自由打包。迁移保持原 JSON 值，包括对象、数组和标量；额外的 `changeSummarySqlNull` 明确区分 SQL NULL 和 JSON literal null。保留旧 JSON 列本身已有的数值语义，不宣称恢复源库从未保存的原始 JSON 文本字节。

## 复制与验收入口

- `sql/mysql/compact/copy/40-model-operations.sql` 使用实际 V3、V7 源声明；需模型主表先复制完成。核对两侧模型存在性，保留原双 CASCADE 关系。
- `sql/mysql/compact/copy/41-infra-operations.sql` 使用实际 V15 源声明，保留全部 11 个原字段的事实及 NULL 含义。
- 两脚本要求不同的源库、目标库、源停写、严格 SQL 模式、外键检查开启，以及有证据的源时区偏移。字段类型、NULL、字符集/排序规则、默认值、索引与方向、源外键/检查/触发器采用封闭契约；未知结构不得静默跳过。
- 最终核对包括数量和逐行字段、原时间、固定 payload、NULL 语义及字节级 `legacy_source` / `legacy_key`，失败须在同一连接回滚。
- 时区仅接受明确的 `±HH:MM`，每个原时间都核对实际偏移秒差；MySQL 对超范围时间原样返回时不得误当作已转 UTC。零偏移允许原时间不变。最终对账还逐项要求本类型不使用的公共审计列为 NULL，包括消息关联、链式摘要、计量、策略及观察字段，避免额外注入的内容被漏检。
