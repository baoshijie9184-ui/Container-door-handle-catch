## 第一步：统一任务级质检规则

### 问题与改动

1. 通用流转原来允许进入 `CONFIRMED`，却不生成复核记录。现在只接受主管对已闭环任务执行 `ARCHIVED`；复核、处置、返工及复检阶段必须由对应业务动作产生。
2. 分派原来会把已确认、暂挂、待复检等阶段重置为复核中。现在只有 `PENDING_REVIEW` 分派后进入 `REVIEWING`，其他允许分派的阶段保持原值。
3. 原来“需要复检”布尔值优先于处置动作，会使“返工后复检”直接跳到待复检。现在选择返工先进入 `REWORK_REQUIRED`，回填结果后才按后续要求进入待复检或待复核。
4. 已暂挂任务允许选择后续处置，但不能重复提交暂挂；已关闭、已进入返工或复检的任务不能通过普通处置入口随意改阶段。
5. 放行要求复核结论为正常或误报，且不存在未完成复检要求。放行和报废不能同时携带新的复检要求；原处置要求返工后复检时，回填不能取消该要求。
6. 归档只接受已放行或已报废、具备复核和处置时间记录、动作相符且无复检要求的任务。历史不一致数据保留并拒绝继续归档，不自动补写证据。重复归档不再次更新任务。

### 状态规则

| 动作 | 主要条件 | 产生的阶段 |
| --- | --- | --- |
| 分派 | 检测完成或部分失败；阶段处于待复核、复核中、已确认、待返工、待复检或暂挂 | 待复核变为复核中，其余阶段不变 |
| 人工复核 | 检测结束；待复核或复核中；本轮结论待提交且无已处置标记 | 已确认，并保存复核结论 |
| 放行 | 已人工复核；正常或误报；没有复检要求 | 已放行 |
| 返工 | 已人工复核且允许处置 | 待返工；复检布尔值仅表示后续要求 |
| 复检处置 | 已人工复核且允许处置 | 待复检，不能直接改为待复核 |
| 暂挂 | 已人工复核且允许处置；当前并非已暂挂 | 暂挂，可后续重新处置 |
| 返工回填 | 当前明确处于返工阶段、处置动作是返工，提交非空结果 | 待复核或待复检；不会直接放行 |
| 归档 | 主管、已放行或报废、完整且一致的复核及处置记录 | 已归档 |

`PARTIAL_FAILED` 继续沿用项目现有质检入口；逐图失败处理、证据覆盖和是否允许放行的更细条件属于第二步，不能从本轮任务级状态规则推断已全部完成。

### 实现位置及并发边界

- `DetectionQualityWorkflow` 统一任务级业务前置条件。HTTP 服务和 Agent 分派门面共用规则，不引入第二套状态机。
- 分派继续沿用现有账号锁及分派版本校验；人工复核、处置、返工和归档在事务内按当前账号范围读取并锁定任务行，再判断当前状态。它们沿用原必要业务审计和身份登记。
- Agent 分派确认回执按同一规则核验目标阶段；资源摘要版本标记变为 `assignment-v3-preserve-stage`，旧待确认快照需重新生成并确认。此标记是提议快照哈希的命名空间，不是新增数据库迁移或身份格式版本。
- 进度及结果 DTO 返回 `qualityActions`：动作、`stateAllowed`、主管要求及阻止原因。状态提示不授予账号权限；实际写操作始终重新鉴权。暂未新增归档页面按钮。
- Vue 主页面移除重复的四组提交逻辑，复用已有 `useQualityTaskActions`，与现有质检分页面共享状态校验、提交中保护及更新反馈。旧接口没有动作提示时使用兼容规则，收到无效动作列表时拒绝放宽。
- 页面约束放行/报废/复检的复检开关，保留返工后复检要求；返工操作人显示为当前登录账号记录，不接受手填身份。刷新合并以当前接口的空值、零和 `false` 为准，避免恢复旧的处置字段。

行锁并不等于完整请求幂等或客户端陈旧版本保护。人工复核、处置、返工和归档的统一请求编号、版本冲突及未知写入核对仍由第三步补齐；本轮不声称这些操作已具备完整“恰好一次”保证。

### 开源参考与依赖选择

开发前查阅 [Spring Statemachine 官方仓库](https://github.com/spring-attic/spring-statemachine) 及其 [Apache-2.0 许可证](https://github.com/spring-attic/spring-statemachine/blob/main/LICENSE)。该仓库已归档，本轮不引入依赖，也未复制第三方源码；采用项目既有 `DetectionRetryPolicy` 相邻的策略类方式，减少当前单体的迁移成本。

## 后续验证清单（尚未执行）

- 通用流转不能代替复核或复检，非主管不能归档。
- 五种可分派的既有非待复核阶段不被重置，Agent 预览、确认、回执一致；旧快照不能直接确认。
- 正常/误报放行、确认缺陷拒绝放行、缺少复核时间拒绝处置、暂挂后重新处置。
- 返工加复检先回填，回填不能撤销必要复检；待复检不能直接复核或归档。
- 并发复核、处置、分派及归档按当前状态拒绝冲突；必要审计失败时回滚。
- 主页面与现有质检分页面同步操作提示；刷新不恢复已清空处置、不把零或 `false` 替换成旧值。
- 完整业务回归、真实 MySQL 并发、两入口兼容、候选和生产验收均待后续统一安排。

本轮没有新增迁移或部署依赖，没有修改 ECS、午夜停机任务或生产环境。实际复检的创建、原图关联、检测回执和新一轮复核仍需第二步实现及验收。
