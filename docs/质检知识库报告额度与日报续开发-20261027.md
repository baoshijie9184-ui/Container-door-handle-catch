## 知识库与引用

`QualityKnowledgeService` 归属 App 的知识检索适配层，采用现有 MySQL/JDBC 和账号目录。支持 TXT、Markdown、CSV、JSON、文字型 PDF、DOCX、XLSX、PPTX。Office 提取文字、表格及单元格引用，Excel 不计算公式，缓存结果有明确标记；PDF 保留页码标识。文件中宏、代码及外部链接不会执行。

单文件上限 5 MiB，文字上限 20 万字符；PDF/幻灯片最多 100 页、表格最多 20,000 个单元格，Office 解压总量和条目数量有界。PDF 字符/操作计数和写入长度有界；全局最多两个并发解析。扫描件、图片 OCR、图表视觉理解仍未接入，未提取到正文时拒绝创建可用索引，不将页码或空表标题当作识别成功。

原文件、原始 SHA-256、提取文字摘要和每个内容版本独立保存；当前文档有单独的乐观修订号，避免归档/恢复与追加版本之间互相覆盖。每账号最多 100 份文档、每文档 20 个内容版本，原文件总量 200 MiB、文字总量 2,000 万字符；写入时使用所有者锁及同事务配额检查。命令编号和摘要用于幂等，失败不会自动提交新的写请求。

私人资料仅本人访问；主管也不能读取他人的私人资料。企业资料由主管发布，企业成员可读；主管可修订和归档企业资料。归档资料退出检索，原文件和版本保留。引用读取与下载再次核对当前身份、文档范围和版本；原文件交付核验字节摘要。操作记录最多展示最近 100 条，不宣称完整审计分页已完成。

动态资料使用数据库文字片段匹配，检索结果包含资料编号、版本和段落。聊天在现有 RAG 上增加按当前账号读取的引用上下文，提供定位地址，不跨账号缓存私人检索内容；上下文块有界且不截断单条引用。该索引路径不新增 Embedding 或 LLM 请求。新增资料的向量语义索引、OCR 及模型最终引用遵从度仍属于后续范围。

## 已审批报告的 Office/PDF 交付

原 `POST /api/detection/reports/{id}/export` 增加 `format=docx|pdf|xlsx|md`，缺省仍为 Markdown。旧三参数 Java 调用保留兼容重载。所有格式沿用既有当前身份、报告访问范围、APPROVED 状态、冻结摘要检查及事务审计；新格式在导出审计意见中登记。没有改写检测结果、提交快照或审批状态。

`ReportDocumentRenderer` 只接收已授权文字生成文件，不调用模型或网络。Word 使用段落排版，Excel 以文本单元格保存报告字段避免公式执行，PDF 使用项目内嵌的 IBM Plex Sans SC 中文字体并分页。每次生成有内容量及并发上限；无法表示的字形明确失败，不用错误字符冒充原文。下载校验对应 MIME 类型及扩展名；旧服务仍返回 Markdown 时不将其保存为假的 Word/PDF/Excel 文件。

采用 Apache POI 6.0.0（Java 17）及既有 PDFBox 3.0.8。中文字体 8,443,316 字节已从官方 IBM 仓库下载到项目内，核对 Git blob 和 SHA-256；OFL、Apache 许可和 NOTICE 均已保留，见 [依赖许可](licenses/document-delivery/README.md)。父 POM 管理 POI 所需依赖版本；本轮没有解析或构建 Maven 依赖图，后续需核对其与 Spring Boot/Agent SDK/日志桥接的兼容性。

## 每模型额度

`ModelBudgetService` 在 AgentScope Java 路由的供应商尝试前后保存记录，包括主/子 Agent、备用模型和通过该路由的摘要请求。SDK 未报告输入/输出 Tokens 时保存未知值；缓存 Tokens 单列，不再次叠加到输入消耗。用量字段不包含提示词、回答正文、密钥或连接凭证。

总额度按模型标识分别登记，新增表单按用户当前每模型 1M 的方式预填，但没有向数据库批量插入额度或虚构历史用量。供应商核对要求明确输入剩余值、核对时点和来源说明，历史记录追加保存，空值不会被当作 0。页面分别展示上次供应商观察值、本站已报告消耗、未知尝试和告警。

`liveProviderRemaining` 始终为未知：未接入供应商实时余额接口；独立记忆、独立 RAG、探测、站外及未接入的历史调用不在本站台账覆盖内。不能通过本站累加值推导全账户实际余额，也不把登记的 1M 视为剩余 1M。供应商核对为历史时点值，来源真实性仍依赖实际控制台核对。

最近观察值为零、登记到期或本站已知消耗达到登记上限时，阻止该候选请求并沿用已配置的候选模型切换路径。额度台账失败不静默跳过；未知完成状态保留。`free_only` 是登记策略，供应商免费额度限制沿用既有配置；并发请求未做计费额度预占，本系统不保证绝对 Tokens 上限，不能替代供应商免费模式或费用限制。没有修改凭据治理开关或要求用户提供恢复密钥。

## 日报调度与统计口径

只支持受控质检统计任务，不执行任意脚本、任意工具或任意模型提示词。六段 Cron 的秒位固定为 0；计划日历固定 Asia/Shanghai，新表存储 UTC 的 DATETIME。`APP_QUALITY_AUTOMATION_TASK_TIME_ZONE` 指定旧任务时间列的存储时区，默认 UTC；发布前须核对实际部署的任务写入约定，不凭前端时区猜测历史字段含义。

自动执行统计待执行时点前一日；指定日期生成接受过去十年至今天的日期。统计内容为该日创建任务的当前状态快照，包括任务/图片/成功与失败图片、模型缺陷目标、登记待复核和未登记复核状态。它不表示当日完成量或人工确认缺陷数，不改变放行或审批结果。

计划修改使用版本和幂等命令，手动/自动执行有唯一时点键。并发调度使用事务控制锁和 `SKIP LOCKED` 领取，执行使用租约、令牌与条件更新；中断后只重算无外部副作用的统计读取，不重放业务写操作。执行前、完成落库前及下载时重新核对当前主管身份；权限撤销使执行停止或阻塞。

每账号最多 50 个计划、每天 500 次执行、累计保留 5,000 次执行。超过配额会阻止新执行，自动计划停用并记审计；物理清理和配额扩展管理尚未提供，不通过删除旧日报绕过限制。停用计划停止后续触发，已入队日报继续处理。停机后保留一个原待执行时点，随后计算未来时点，不自动补发全部遗漏周期。

统计快照保存规范化 JSON 与摘要；读取时重新规范化，避免 MySQL JSON 键序/空白变化造成伪损坏。文件只从保存的快照生成，下载有独立审计。没有邮件、短信或外部推送，也没有收费模型请求。
