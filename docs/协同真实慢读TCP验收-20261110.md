# 协同 SSE 的真实慢读 TCP 验收

本次只补单体 ECS-only `CollaborationHttpMySqlTest` 的一条真实网络用例，原九条用例保持。新增用例按 `Order(0)` 先执行，使用原隔离 MySQL、真实认证 Cookie、实际 Tomcat 和生产 `BusinessRealtimeService`；不启动额外组件、不改变生产配置。

客户端是连接原 `/api/realtime/changes` 的真实 `Socket`。只读取 HTTP 响应头，此后没有任何客户端线程消费 SSE 响应体。客户端在连接前请求 1 KiB 接收缓冲，只对该已接受的 Tomcat TCP socket 请求 1 KiB 发送缓冲，并实际读回内核采用值；Linux 可以按其最小值调整请求，因此不把请求值当实际大小。其他原用例及正常观察会话的 socket 配置保持原值。

通过真实 HTTP 写命令及真实 MySQL 事务/必要审计产生通知，最多128次、8秒内的有界试探，并逐次等待正常会话收到相应实际事件；整条用例45秒超时，任一超时都是失败。慢连接背压必须同时满足三次采样：同一生产发送调用仍未返回、对应 writer 栈正在 Tomcat `NioSocketWrapper.doWrite` 的 `Object.wait`、该已核对 socket 四元组的 `/proc/net/tcp` 或 `tcp6` 内核发送队列大于零、连接尚未关闭。采样间隔25毫秒。单纯超时、模拟 Transport、闩锁等待或生成 JSON 不计为网络背压。

在上述实际阻塞持续期间，另一会话还须完成八次真实 HTTP 保存，并逐次在两秒内收到匹配的授权事件。每次核对业务版本、HTTP 审计编号、唯一审计行和唯一命令回执。原慢发送调用必须持续未返回，其真实有界队列中存在待发送帧。每20毫秒采集当前 JVM 堆、线程、实际 writer、发送队列、事件执行器队列和准入槽；该有界试验要求 writer不超过2、发送队列不超过32、事件队列不超过256、准入槽不超过2、观察到的线程增量不超过16、堆使用增量不超过64 MiB。

关闭真实慢客户端 socket 后，必须读回该实际 writer 终止且只剩正常会话的准入槽；正常会话再次成功保存和收到通知。全部客户端关闭后再核对 writer 和准入槽均归零。通过后仅输出有界数值摘要，跟随原测试报告/日志保留，不输出 Cookie、凭据或消息正文。

这是刻意限制单个 TCP socket 缓冲的可复现压力试验，证明该工作负载下的真实发送隔离、观察到的资源上界及释放路径，不代表生产默认缓冲、任意并发或吞吐量容量已验证。功能验收仍须联合原九条 HTTP 用例、完整原生矩阵及真实浏览器/迁移回执。此文记录源码方案，没有本地测试、ECS测试或性能通过结论。

缓冲属性语义参考 [Apache Tomcat HTTP Connector 官方文档](https://tomcat.apache.org/tomcat-10.1-doc/config/http.html)，并已通过项目现有 Tomcat 10.1.19 JAR 的 API/字节码只读检查核对 `NioEndpoint`、真实 socket 选项和阻塞写等待路径。没有复制或引入外部实现。
