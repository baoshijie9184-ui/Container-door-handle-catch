# MCP 安装跨实例协作中断

更新：2026-10-17，`java-cloud`。在 D39 固定 Fetch 持久安装队列基础上，执行节点能够发现其他节点已提交的取消，并尝试中断本机任务。不增加任意进程控制 API，不扩大用户权限，也不引入新的数据库表、依赖或开关。

## 当前行为

开启 `AGENT_MCP_DURABLE_INSTALL_ENABLED=true` 并已执行 V25/V34 时，既有独立调度器每秒一次的调度周期会先检查本机安装任务，执行器忙碌时也检查。查询核对账号 ID、安装编号、`RUNNING` 队列状态、工作令牌，以及当前登记仍处于 `INSTALLING` 且租约有效。SQL 为只读检查，设置 2 秒查询超时，不锁定或改写登记。

本人从节点 B 确认取消，登记撤销、队列取消和审计先在同一事务提交；执行节点 A 下一次成功检查时发现任务不再有效，再调用本机任务的 `cancel(true)`。未提交或已回滚的取消不触发中断；主管仍不能取消其他账号的私有安装。工作令牌失效、登记已更换为新安装和租约过期也会触发检查失败。过期状态与审计仍由原维护事务推进，不把过期伪装为用户取消。

这里的每秒是正常调度间隔，不是停止时限保证。数据库连接等待、查询耗时、调度任务占用和程序是否响应中断都会影响实际延迟。默认关闭持久队列时，仍沿用进程内安装与取消，不承诺跨实例发现撤销。

## 中断与迟到结果

本地任务保存独立停止标记，取消时先设置该标记，再请求线程中断。安装前、安装返回后及提交成功事务前均检查标记，防止安装程序吞掉中断后又返回成功结果。已有数据库安装编号、工作令牌、状态和租约检查继续保留。

`Future` 被取消不代表实际线程已经退出。调度器继续使用执行器的真实活动线程数判断空位；忽略中断的旧安装没有返回前，本进程不会领取下一份安装来挤占同一执行槽。其他实例可以处理各自可领取的任务，旧安装不能覆盖新安装登记。

原 Stdio 运行时在安装程序等待中收到 `InterruptedException` 时，会请求终止安装进程及当时可见的子进程。网关路径沿用 HTTP/SDK 的取消与运行器超时机制；本功能不等于向任意远程容器发送强杀命令。不承诺所有派生进程立即退出、外部副作用回滚或包文件已物理删除。未增加“进程已停止”的成功审计或退出回执；原取消审计表示撤销已提交。

## 控制数据库不可用

执行节点无法读取控制状态时，保守请求中断本机任务，并设置永久停止标记；不把数据库故障记录成用户取消，不输出原始 SQL/连接错误，也不自动重放安装。即使程序忽略中断后返回、数据库随后恢复，该次迟到结果仍不能登记成功。

此时数据库可能仍显示 `INSTALLING / RUNNING`，它记录已领取状态，不证明进程仍在执行。恢复连接后，用户应刷新并核对，可明确取消后重新确认安装；如果不操作，原租约到期后由维护标记 `EXPIRED / INSTALL_LEASE_EXPIRED`。停止标记仅保存在执行节点内存中，重启后已领取任务仍按 D39 规则禁止自动重放。

## 兼容与回退

复用 V25/V34 和持久队列开关；未执行新的 SQL，状态接口、确认请求、权限规则和前端交互不变。多实例应使用相同版本、数据库和队列配置；旧执行节点没有这一轮询检查，只能依靠既有迟到回写保护。混合版本不能承诺每个执行节点都响应远端中断。

回退代码或关闭持久队列会移除执行节点对远端撤销的主动检查。应先让任务完成或由本人取消并核对退出，再回退；保留登记、队列、文件和审计。不自动重放 `RUNNING` 安装，也不清理包文件。

## 与 Agent 对话任务的关系

这里处理的是固定 Fetch 的安装后台任务。Agent 对话目前只有运行取消、持久轨迹和结果读取；可暂停后恢复执行的状态保存、会话消息持久排队及运行中引导均未实现，分别记录在 N06/N17。上述能力需要独立的会话执行协议，不能据此承诺已支持。
