# 质检分派数据格式与兼容回滚

更新：2026-10-22 UTC+8。分支：`java-cloud`。本轮仅开发代码和阅读源码，未运行检查器、测试、构建、迁移、候选演练或生产发布。

## 保护的对象

分派确认 v2 增加责任人账号编号和快照；V40 保存稳定账号关联；V54 增加分派操作人、责任人快照和身份修订记录。新应用能读旧数据，不足以证明旧应用能安全读取、修改新数据。回滚保留数据库，因此不能只恢复镜像标签。

[`assignment-compat.py`](../script/docker/assignment-compat.py) 在现有发布锁内、记忆服务切换及后端停止之前，读取 MySQL 元数据和实际镜像声明。它不执行迁移，不修改业务表，不重放分派命令，不输出账号、确认正文、凭证或完整 Compose 配置。

| 兼容维度 | 新镜像声明 | 数据或配置依据 |
| --- | --- | --- |
| 确认 JSON | `io.doorhandle.assignment-json=2` | v2 策略、新字段，即使字段值为 null；也考虑正在运行及即将启用的确认写入者 |
| 分派身份 | `io.doorhandle.assignment-identity=1` | V54 已有身份值、修订或事件，以及启用后的潜在写入 |
| 稳定身份授权 | 同一身份声明 | V40 已激活 ID 授权，或新配置启用稳定身份能力 |
| 历史回填确认 | `io.doorhandle.identity-review=1` | V55 已有批次/逐条回执，或启用 `DETECTION_IDENTITY_REVIEW_ENABLED`；旧三维 pin 的新增维度按 0 读取 |
| 身份来源保护 | `io.doorhandle.identity-evidence=1` | V56 来源记录、来源模式 ACTIVE 或启用 `DETECTION_IDENTITY_EVIDENCE_ENABLED`；旧三/四维 pin 的新增 evidence 维度按 0 读取 |

没有声明的旧镜像按能力 0 处理，不自动补标签。未知声明、损坏确认 JSON、异常身份模式、缺少必要迁移列或无法读取元数据时拒绝切换。列存在检查不能替代最终迁移的类型、约束和索引签名核对。

`state/assignment-protocol-pin.json` 以私有文件保存单调递增的格式下限，并绑定 Compose 项目及实际 MySQL 命名卷身份。即使新数据随后被清理，也不自动降低下限。替换数据库卷后须人工核对部署状态，不能直接沿用别处的文件。

## 暂停分派写入

`DETECTION_ASSIGNMENT_WRITES_ENABLED` 默认 `true`，保持现有分派入口行为。显式设为 `false` 后，业务表单和 Agent 门面均拒绝新分派或批准执行，仍可读取历史、拒绝或取消提议。这不是全站只读，也不会取消此前已经提交的操作。

当数据库已经存在 V54 身份数据，回滚须保留相应读取开关。不能靠关闭身份功能退回用户名授权；需要暂停时使用分派写入开关。已有审批仍需原业务权限，镜像兼容声明不构成审批授权。

发布快照保存实际后端容器的分派写入开关。恢复兼容基线时，镜像与暂停状态一起恢复，避免新的公共环境文件意外重新开放写入。旧镜像不实现该开关，只在尚无新格式要求且检查通过时允许恢复其原有写入行为。

## 首次启用与候选演练

第一次启用新数据写入前，当前恢复基线也必须声明并实际验证对应读取能力；目标镜像和恢复基线任一个不满足即拒绝切换。可以先准备支持读取的新基线，暂停分派写入并关闭尚未启用的身份功能，再完成独立验收，之后才能推进写入。这里仅提供约束，尚未实现首次兼容基线的自动编排。

Jenkins 隔离演练新增可选参数 `COMPATIBLE_BACKEND_IMAGE`，只能填服务器已有的不可变 `sha256:` 镜像编号。脚本要求其声明当前分派读取能力，并在隔离基线中暂停分派写入；原生产镜像清单保持不变，不拉取或替生产换镜像。该参数本身不会执行审批或证明镜像已验收。

演练报告区分 `originalBackendImage` 和 `compatibleBaselineBackend`。回滚恢复所选基线，随后再次激活候选并恢复原计划的分派写入开关。候选镜像不能同时充当自身的前版回滚证据；使用兼容基线的成绩也不能声称证明回滚原生产旧镜像可行。模型 Secret、Mem0 协议和其他数据格式仍须分别通过原有保护。

## 回执与未完成事项

`assignment-transition.json` 保存镜像编号、观察到的格式、所需下限、写入开关及 UTC+8 时间。`declarationOnly=true` 明确表示它只是兼容声明和元数据门禁，通过不代表功能验收。Jenkins 归档该回执，并在 `deployment.json` 记录 `assignmentWrites` 和所需格式，避免将容器健康误写成分派功能全部开放。

仍待完成首次兼容基线、完整迁移签名核对、旧版本期间新增数据核对，以及真实 MySQL、两入口和隔离升级/回滚验收。五类单体任务没有整体完成，新身份开关仍默认关闭，生产发布仍默认关闭。
