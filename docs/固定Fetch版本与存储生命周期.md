## 固定发布范围

`FetchReleasePolicy` 只接受代码登记的 `mcp-server-fetch 2026.10.10` 及原审核 wheel SHA-256。当前没有声称新增其他上游包版本。今后新增包版本必须同时更新审核登记、安装器、镜像和相应固定摘要，不能由模型或浏览器输入版本、命令、上游地址。

网关的当前目标仍由 `MCP_FETCH_IMAGE` 指定不可变 `sha256:` ID。可用于回退的其他已审核镜像由部署配置 `MCP_FETCH_APPROVED_IMAGES` 登记，最多八项（含当前镜像），Java 和 runner 必须使用同一清单。不能填浮动 tag。签名 execute 凭证绑定安装所选镜像；runner 在运行前检查白名单、实际 image ID 及固定包版本/摘要标签，再运行既定命令。

镜像标签是发布包一致性检查，不能替代发布者对源码、依赖和许可的审核。旧镜像若没有标签，需由运维先核对兼容发布，不能仅加入名单就宣称已可用。管理目录表示获准范围，不保证当前 daemon 已有每个镜像。

## 升级和回退

V48 的 `agent_fetch_installation` 保存不可变 manifest/摘要、包版本、镜像、前一安装和回退引用；`agent_fetch_lifecycle_command` 保存本人请求去重及结果。两份迁移 SQL 分别在根目录与 AI classpath，回滚保留表及数据。

升级沿用 `/install` 的来源/许可确认。事务锁住本人登记，保存旧快照、预留新安装额度、记录审计、切换到新安装编号并停用；后台继续使用既有持久队列和租约。新安装成功后保存 READY 快照，仍需本人启用。

安装失败、主动取消或租约到期时，若有完整前一快照，恢复原安装登记并保持停用。失败候选和审计保留；新候选的迟到结果不能覆盖恢复的旧版本。旧版本若不在当前批准范围，继续提示迁移，不能自动启用。

显式回退接口：`POST /api/agent/mcp/fetch/versions/{installationId}/rollback`。重新校验本人账号、登记版本、历史摘要、发布范围及本地文件；存在未确认退出的工具执行时拒绝。原当前版本转为回退保留，目标恢复为停用登记，不自动发起抓取。

解除回退保留：`POST /api/agent/mcp/fetch/versions/{installationId}/release-retention`。本人另行确认，校验历史版本、当前引用和活动执行；只解除引用，不删除文件。升级中的回退引用不可解除。

## 配额、文件统计和清理

默认本人 MCP 额度 256 MiB，可通过 `AGENT_MCP_STORAGE_QUOTA_BYTES` 配置。网关登记每项未核实安装预留 2 MiB；V58 原生监督安装另需至少 512 MiB，默认额度不被静默修改。逐项预留持久化，不将其已写部分重复计入额度。旧本地文件仍计入文件字节总量，不跟随符号链接读取其他目录；无法核对的扫描拒绝继续处理。

页面分别显示文件字节、计入额度的字节和待核对预留。这是本人文件的逻辑大小，不是宿主磁盘块用量，也不含所有用户共享的运行镜像。

`POST /api/agent/mcp/fetch/storage/{installationId}/cleanup` 清理本人无引用安装目录：

- 当前有效登记、回退保留、安装执行退出未确认或工具执行清理未确认时拒绝。
- 先事务登记 CLEANING、请求编号与审计，再删除固定安装编号映射的目录，最后保存完成或待核对回执。
- 不接收路径，不跟随符号链接，不删除共享运行镜像；manifest、许可证元数据和历史审计继续保存在快照及运行镜像中。
- 进程中断或审计失败不自动再删，保留占用及清理状态。超时后可由本人用新的请求明确核对和清理；同一请求编号不重复物理操作。

回退、解除保留和清理均携带 `expectedRevision`、`requestId`、`confirmed: true`，沿用 `X-MCP-Action: update`。回退版本号对应当前登记，其他操作对应安装历史。重复编号不同内容拒绝，版本过期后先刷新，不自行覆盖。

安装 worker 的 `writerStopped` 只在实际 callable 返回后记录，不用 `Future.isDone()` 或 `cancel()` 证明退出。持久队列中从未领取的任务可在同一登记锁下确认未启动；已经运行且服务重启后丢失执行证明的安装继续待核对，不自动释放预留。
