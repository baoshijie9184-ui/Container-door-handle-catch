## 设计方向

工业质检工作空间：白色作为操作面，蓝色突出动作和当前上下文，绿、橙、红分别表达成功、待处理/风险和失败。主色 `#2563EB`、正文 `#0F172A`、次级文字 `#475569`、背景 `#F6F8FB`、内容 `#FFFFFF`、分隔线 `#E2E8F0`。

字体采用系统已有的 Segoe UI、苹方、微软雅黑，无新增远程字体。业务页标题左对齐，操作紧随业务标题；表格和表单使用稳定的留白与浅分隔，减少重复卡片。聊天保持居中阅读区、会话侧栏和按需工作面板，避免把操作面板常驻挤占正文。

布局：`系统导航 | 页面标题与操作 / 筛选 / 业务内容`；聊天：`历史 | 消息与输入 | 按需工作面板`。小屏复用同一份业务导航，通过抽屉展开。此处理来自用户需求中的“统一侧栏、顶部导航、面包屑、页面标题、内容宽度、用户菜单及手机抽屉”，不是新增独立移动端产品。

图标复用 Element Plus Icons；React 沿用已有 Lucide/Ant Design 图标，统一语义和尺寸。未安装新的图标依赖。适度动画以 150—250ms 为范围，重点用于展开、切换和操作反馈，支持减少动态效果。

## 公共实现

- `design-tokens.css`：两套前端共用颜色、字体、间距、阴影、圆角和动画变量。
- `system-ui.css`：业务表格、筛选、表单、弹窗、状态和小屏布局。
- `agent-unified.css`：Vue/React 对话及 Agent 管理面的共同视觉语言。
- `AppIcon.vue`：现有 Element Plus 图标的统一尺寸、语义入口。
- `PageHero.vue`、`pagePresentation.js`：实际路由对应的业务标题、图标及说明。
- `AppBreadcrumbs.vue`：复用现有面包屑元数据，区分分组与当前页；桌面显示完整路径，窄屏保留最近上级入口，角色过滤仍由原布局与路由决定。
- `WorkspaceNavigation.vue`：桌面侧栏和窄屏抽屉使用同一份角色过滤后的导航。
- `HandleInspectionGraphic.vue`：项目内绘制的门把手区域示意，明确不是实际检测结果。
- `StatusBadge.vue` / `StatusBadge.jsx`、`statusPresentation.js`：两入口共用状态含义和配色，同时保留文字、图标及未知状态。
- `QualityStageGuidance.vue`：根据服务端任务阶段解释下一步，不授予操作权限，不把检测完成当成放行或报告审批。
- `CollectionEmptyState.vue`：统一读取中、读取失败、筛选无匹配和业务尚无记录四种状态，复用开源图标，提供重新读取及清空筛选。
- `countPresentation.js`：将合法的非负整数统计与缺失统计分开，缺失值不转换成零。
- `AgentMarkdown.vue`、`messageMarkdown.js`、`agent-markdown.css`：Vue 消息的文本节点渲染、常用 Markdown 块、局部滚动表格和代码复制。无新增依赖，HTML/SVG 不作为可执行内容插入。
- `EvidenceComparison.vue`、`evidencePresentation.js`：使用已有任务图片 DTO 对照原图与标注；仅按精确且唯一的文件名配对，同名重复及缺图单独提示，保留原有追溯文件表。
- `SessionHistory.jsx`、`sessionPresentation.js`：React 会话搜索、UTC+8 日期分组、置顶/重命名及分支来源；名称长度沿用 Vue 既有 50 字限制并提为共享常量。
- `AgentLifecycleGuide.vue`：Skill 与固定 Fetch 的操作流程说明，明确草稿、审核、安装、启用及清理顺序，不将说明当作已经执行的结果。

- 总览使用现有 `/api/dashboard/quality-workload` 展示六类质量待办，点击进入对应队列；缺失值用“—”，失败时注明旧数据，交叉统计不相加。

- 报告详情的检测完成、审批、接收与操作时间统一通过既有 UTC+8 格式化工具展示；缺失时间不代入当前时间。追溯页改善小字号、筛选控件、选中行和窄屏图标按钮的可访问名称。

## 业务页面交互续改

- 设备、人员、模型、报告和检测历史接入统一空状态；有旧记录时显示读取失败提示，不能把失败当作空数据。列表区增加记录标题和查询总数，查询和重置使用现有接口。
- 设备、人员统计初次缺失用“—”，明确提示不完整或失败，并提供独立重读入口。未使用设备、离职人员使用中性色，不与故障共用红色。
- 设备和人员搜索回到第一页，文本条件支持 Enter；检测历史不再把 DOM 事件传入页码，增加清空筛选，并通过请求序号阻止旧查询覆盖新查询。设备、人员及模型列表同样忽略过期查询响应。
- 模型列表区分查询总记录数与本页发布、评估、使用次数，读取失败时不展示旧的默认模型横幅与统计摘要。
- 上传页增加“选择图片—上传原图—提交检测”操作说明，以及待补全采集信息提示；这些步骤是流程指引，不宣称已执行。上传仍使用既有校验、任务和存储方式。
- 上传进度卡片使用 200ms 出现/消失过渡，遵循全局减少动态效果规则；历史区标明已加载与当前匹配数量，提供清空筛选，并区分读取失败。时间和日期筛选按 UTC+8。
- 任务列表读取在既有返回字段外补充 `ok` / `message`，供上传与检测历史区分读取失败；保持原有 `records` / `total` 结构，无新增 HTTP 接口，不自动重试。

## Agent 消息与组织、审计续改

- Vue 普通消息及业务卡片回答改用 `AgentMarkdown`，不再通过字符串替换拼接 `v-html`。支持常见标题、段落、粗体/斜体、行内代码、围栏代码、平面列表、引用、分隔线及管道表格；复杂 Markdown 仍按文本保留，不宣称完整实现 CommonMark。
- 代码块保留缩进、换行和未闭合围栏中的流式文本，提供手动复制按钮；复制失败给出选中复制说明。复制状态绑定实际内容，流式内容变化后不显示旧的“已复制”。表格及代码在自身区域滚动，可通过键盘聚焦。
- Vue 链接仅呈现受限站内片段和 HTTPS 链接，外链新标签页打开并设置 `noopener noreferrer`；渲染不加载远程图片、不执行 HTML 或脚本，不新增资料访问权限。
- React 普通消息继续使用现有 AgentScope Markdown 组件，业务卡片回答也接入同一已有组件。两套入口保持相同的标题层级、字号、代码行距和状态语义，未更换技术栈。
- 主站历史消息去掉逐条延迟入场，普通出现反馈缩短至 200ms；旧版不可执行操作卡片采用历史提示和中性禁用按钮，保留原有取消接口，不重新开放旧操作。
- 两套业务卡片明确区分检测状态、人工复核及报告审批。缺失处理数、总数、缺陷数显示“—”，缺失复核状态显示未知，时间通过现有 UTC+8 工具转换。
- 组织页增加分组图标、员工状态徽章、清空筛选及关联记录的错误重读；未识别的账号角色或范围不假定为员工/全企业。账号关联、主管权限与提交协议不变。
- 操作审计增加有标签的筛选区、已加载数量、两类记录的加载/失败/空状态。读取更早业务操作沿用上次成功查询的业务域，缺失交付字节和时间明确为未知；原有关于文件响应与真实接收的说明保留。

仅源码阅读与修改；Markdown 的语法覆盖、代码复制、外链、表格溢出、历史卡片、组织关联及审计分页均未运行验证。完整目标继续保留，未标记全部完成。

## 会话侧栏与缺陷证据续改

- 独立 Agent 的侧栏增加已加载标题/摘要搜索，以及置顶、今天、昨天、最近七天、更早和其他时间分组。日期按 UTC+8 划分，时间缺失或异常不放入今天。保留新建、刷新、业务导航与分支来源。
