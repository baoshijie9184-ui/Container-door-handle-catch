日期：2026-10-22，UTC+8。分支：`java-cloud`。

状态：已新增实现代码，尚未编译、测试、执行数据库迁移或部署。本轮遵循“先完整开发，不要进行测试”；以下为实现设计，不是验收报告。

## 固定批准范围与单次写入

V50 在批准事务中保存目标 bucket、固定目录、逐图编号/大小/类型/SHA-256 和清单摘要。路径仅由服务端生成。实际上传前，另一个短事务保存唯一上传令牌、`UPLOADING` 标记及必要审计；提交失败就不调用 OSS。真正的网络传输在事务之外进行。

这条批准链路使用独立 OSS SDK 客户端，`maxErrorRetry=0`，单次请求超时 60 秒。一个已登记的图片不能再次从 `UPLOADING` 回到 `PLANNED`，调用失败或进程中断仅进入待核对，不自动重传。上传确认与执行者身份绑定，迟到的真实确认仍可记录，但不能使终止或待核对任务自动派发。

额外设置 `x-oss-forbid-overwrite`。该请求头不能替代持久写入标记；Bucket 开启或暂停版本控制时，不应据此宣称绝对禁止覆盖。应用仍依赖“登记后仅一次 PUT、禁 SDK 自动写重试、未知结果不重放”约束。管理员或其他系统修改对象也不属于应用能证明的单次写入范围。

SDK 复用现有 Apache-2.0 依赖，通过其公开 API 调用，未引入新执行框架。参考：[SDK 3.17.4 ObjectMetadata](https://github.com/aliyun/aliyun-oss-java-sdk/blob/3.17.4/src/main/java/com/aliyun/oss/model/ObjectMetadata.java)、[OSS PutObject](https://www.alibabacloud.com/help/en/oss/developer-reference/putobject)。

## 本人明确操作

| 操作 | 行为及前提 |
| --- | --- |
| 只读核对 CHECK | 当前命令待核对且存在原目标清单，重新鉴权后登记异步核对；不上传、不创建任务 |
| 完成原创建 FINALIZE | 本人再次确认；核对证据须完整、摘要有效、对应当前命令版本且在五分钟有效窗口内；重查账号、来源与模型后，同事务保存原 taskId/dispatchId 的业务任务、回执、审计和事务消息 |
| 终止创建 ABANDON | 本人确认终止自己的待核对命令；不要求重新读取已经撤权的原资料，不删除 OSS 对象，不把未知结果当作未发生 |

两个入口均在原操作确认区域展示独立核对面板；即使原图片已被移除或撤权，仍能通过最小本人命令信息终止，不返回原图片名、正文、OSS 路径或凭证。完整提议快照仍按来源权限控制。

核对依次读取已发起过上传的固定目标，按实际字节计算 SHA-256，并比较长度、类型及原命令/文件元数据。ETag 和元数据里的 SHA 只是附加关联信息，不能单独作为内容证明。没有上传令牌的目标标为未发起，不扫描后就假定成功。缺失、不一致和读取异常均不能完成创建。

网络读取可能产生 OSS 请求及流量费用，界面提前说明。每条命令最多登记 64 次显式只读核对；刷新仅 GET 状态，不重新发起读取。每个 JVM 的核对使用独立单线程执行器，跨进程通过 MySQL 条件领取保证每条核对只有一个执行者。逐图证据及审计随进度持久化；中断后保留已记录证据，租约失效转为未确认，不自动重跑。

终止会阻止原执行者继续下一张上传或最终创建。正在网络传输中的原请求可能返回迟到确认，界面不能声称“文件均未上传”或“远端已清理”。终止后仍有 `UPLOADING` 未知对象的命令继续占用本人未完成命令额度；不会仅因用户终止就释放未知预留。对象物理清理与无法证明退出的历史传输仍需单独的运维证据处置，本轮入口不提供删除功能。

## 接口、事务与兼容性

- `GET /api/agent/conversations/{session}/detection-creations`：当前账号、当前会话的最小核对 DTO，最多 20 条并优先待核对命令。
- `POST /api/agent/conversations/{session}/detection-creations/{command}/review`：请求编号、命令版本、CHECK/FINALIZE/ABANDON 和适用的核对编号。请求编号与 `X-Request-ID` 一致，要求原工作台操作头和同源限制。
- App 校验账号与会话，通过 `DetectionCreationApi` 调用检测门面，不读取检测业务表。所有状态、证据、请求去重及必要业务审计由检测模块在同一数据库事务维护。
- FINALIZE 复用原始图片、参数、taskId、dispatchId 和幂等命令，不接受浏览器新参数；更改范围须新提议、新确认。复核、放行、报告审批继续通过原业务流程完成。
- V50/V51 只新增列和表，回滚保留全部数据。启用前需核对历史命令及两份 SQL；没有目标清单的旧未知命令不能猜测原目标。尚未接入最终迁移/发布演练。

`DETECTION_CREATION_TRANSFER_EVIDENCE_ENABLED` 与 `DETECTION_CREATION_REVIEW_ENABLED` 默认 false，后者依赖前者。业务原图还需 `DETECTION_AGENT_BUSINESS_IMAGES_ENABLED`。这些开关不代表业务库已迁移。
