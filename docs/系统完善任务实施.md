## UTC+8 约定

- Java 主入口在 Spring 装配前配置 `Asia/Shanghai`；容器入口追加 `-Duser.timezone=Asia/Shanghai`，防止 UTC 宿主机或原 `JAVA_OPTS` 让业务 `LocalDateTime.now()` 按 UTC 写入。
- Jackson 使用 `Asia/Shanghai`。Hikari 每个新 MySQL 连接设置 `time_zone='+08:00'`，同时保留 utf8mb4；Compose MySQL 默认时区为 `+08:00`，无需数据库时区表。连接配置在 JDBC 连接重建后生效，数据库容器配置需其下次受控重建后生效。
- Python 检测 worker 使用固定 `timezone(timedelta(hours=8))` 产生带 `+08:00` 的事件时间，不依赖精简镜像是否安装系统 tzdata；容器同时声明 `TZ=Asia/Shanghai`。
- 前端对带偏移或 Z 的时间先解析为实际时刻，再显示北京时间；无偏移的业务时间按 UTC+8 解析。聊天时钟与会话相对时间、首页更新时间、任务本地时间、模型/设备时间及主要报告导出文件名沿用同一规则，不依赖浏览器所在时区。
- 历史库同时包含开发机导入和云端生成的无时区 DATETIME，不能仅凭日期推断原始时区。本轮不批量加八小时，不改原始审计、确认或检查点时间；历史校正须依据导入与运行证据单独核对。租约、确认有效期和中断恢复在云端时区切换后另行验收，过期确认不得绕过。
- 当前 ECS SSH 连接超时，尚未验证云端生效，未为夜间验证启动新实例；继续开发和本地检查，最终统一发布时记录实际运行时区及 MySQL 会话时区。

## 附件与草稿边界

参考项目内 DeepSeek Harness 的 `ComposerAttachments.tsx`、`QueueDock.tsx`（MIT，保留原参考仓库许可），复用现有 Vue/React 和文件工作区，未引入其执行运行时。只有用户消息中的合法服务端文件引用转成卡片；助手或工具输出中的引用不自动变成可操作文件。每次读取重新走后端鉴权，文件移除或权限变化时卡片停止提供正文。

HTML/SVG 作为源码展示，不执行；图片/PDF 使用 Blob 预览并释放 URL，文本截断至 64000 字节。会话切换及卸载时中止请求，丢弃迟到响应。草稿保存在当前浏览器标签页 `sessionStorage`，按服务端身份和会话区分，只存文字、服务端文件编号和未确认请求编号，不存文件二进制、路径、密钥或 SDK 状态；恢复附件先重新读取授权元数据。关闭标签页、换浏览器或换设备不属于本次草稿恢复范围。
