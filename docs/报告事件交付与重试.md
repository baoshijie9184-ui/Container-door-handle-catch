# 报告事件交付与重试

更新日期：2026-10-14。当前 `java` 分支继续完善 Java 模块化单体。

报告提交、撤回、通过和驳回仍先在业务事务内保存 outbox。事务提交后，独立后台投递器发送到 Kafka，接收端保存去重回执和按版本递增的状态投影。消费不修改报告、审批结果或检测任务，不执行放行，也不向外部人员发送消息。

## 页面与权限

“质检追溯 → 报告与审批 → 查看”新增“状态同步”：分别显示发送状态、尝试次数和接收结果，支持刷新。员工沿用本人报告及任务范围；主管不能查看他人的私人草稿。状态接口不返回正文、原始异常或租约。

主管可对等待重试或失败的事件选择“重新发送”，预览并明确确认后提交。服务端重新核对当前角色、报告范围和尝试次数；人工重试、报告审计和请求结果在同一事务提交，审计失败时回滚。请求键绑定事件与参数，成功重放不重复重置队列或写审计。

- `GET /api/detection/reports/{id}/events`：读取授权报告事件，响应禁止缓存。
- `POST /api/detection/reports/{id}/events/{eventId}/retry`：主管人工重试，要求 `X-Report-Action: update`、`expectedAttempts`、`confirmed: true` 和 `requestId`。仅 `RETRY`、`FAILED` 可操作。

## 投递和故障恢复

投递器使用专属线程，每轮最多处理 20 条，避免 Kafka 等待占用 Agent 日志维护调度器。短数据库条件更新竞争租约，网络发送在事务外。默认租约 60 秒、发送超时 10 秒；配置校验租约大于两倍发送超时。

状态为 `PENDING → PROCESSING → DELIVERED`。发送异常转入 `RETRY`，间隔从 2 秒指数增长至最多 5 分钟，不因达到固定次数删除事件。进程中断后回收过期租约，旧令牌不能完成新尝试。无法验证的事件标记 `FAILED / INVALID_EVENT`，保留供核查，不发布原始内容。

同一报告的较新版本等待早期事件发送完成；无法处理的早期事件阻挡该报告后续事件，但延后候选扫描，使其他报告可继续处理。Kafka 以报告编号为消息键。载荷只包含事件/报告编号、操作账号 ID、状态、报告版本和协议版本，不包含报告意见或文件地址。

数据库和 Kafka 不组成分布式事务，超时或发送成功后的数据库确认失败可能重投。采用至少一次交付，不声称全局恰好一次。消费端核对消息键、严格字段和已提交 outbox 的绑定，用事件编号及报告版本唯一约束去重；回执和状态投影同事务提交。晚到旧版本可记录回执，但不能覆盖较新状态。

消费异常时不提交位点并持续重试，不静默跳过。持续损坏或无法绑定 outbox 的消息可能阻塞所在分区，需要运营核查。死信处理界面、外部通知、容量与多实例时钟偏差演练仍未完成。
