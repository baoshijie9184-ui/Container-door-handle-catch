# Agent 执行追溯工作区

更新日期：2026-10-16。分支：`java-cloud`。入口：Agent 智能系统 → Agent 执行追溯（`/#/agent/trace`）。

## 界面与使用

参考本地 `deepseek-harness` 的三栏布局、Trajectory 事件浏览和详情检查设计，在现有 Vue 与 Element Plus 中实现。左侧选择当前账号的运行，中间按服务器序号查看事件，右侧检查选中事件；手机上运行列表与详情按需展开，支持 Escape 关闭。

| 视图 | 已实现能力 |
| --- | --- |
| 运行历史 | 按会话筛选、查看两个入口的本人运行、搜索已加载记录、读取更早运行 |
| 执行过程 | 模型、工具、角色权限、技能命令与 Agent 分类；搜索名称和调用编号；每页显示 50 条已加载事件 |
| 事件详情 | 服务器记录时间、运行后时间、明确记录的耗时、Token、策略与数据范围；同一工具调用的事件串联、父调用跳转 |
| 关联结果 | 只展示已保存消息中明确带有相同 `runId` 的业务卡片；卡片刷新复用后端鉴权接口 |
| 会话上下文 | 读取运行所属会话，明确说明可能包含多次运行；不通过相近时间猜测某轮输入和回答 |
| 原始事件 | 查看当前已加载的白名单元数据；JSON 导出包含运行与事件，不包含会话正文 |
| 运行管理 | 运行中每 5 秒只读补读一次，后台页面暂停；取消需页面确认，复用原有服务端取消接口 |

主站聊天头部和独立 Agent 侧栏均提供“执行追溯”入口，并携带当前会话编号。追溯页支持 `?runId=...` 直接读取指定的本人运行，即使它不在第一页列表中；无权限时显示错误并清空详情，不回退到别的运行。页内切换、浏览器前进后退与 URL 查询变化保持对应。返回会话时打开原会话。

## 数据正确性

- 使用既有 `/api/agent/runs`、单次运行、事件补读与会话读取接口，没有新增数据库表或服务。
- 同次工具调用按 Agent、父调用编号、调用编号关联，不按工具名称猜测并行调用关系。没有终态时显示“未记录终态”；运行仍在进行时才显示“等待结果”。
- 相对时间和耗时分别显示。缺失值显示“未记录”，显式记录的 `0 ms` 和 `0 Token` 保留，不用模型配置推断实际供应商。
- 用量汇总仅计算已记录的模型完成事件。已加载事件数、用量和调用数不冒充尚未补读部分或整次会话的完整统计。
- 连续序号校验发现未读尾页或缺口时禁止导出。补读从已连续读取的最后序号继续，重复序号去重；读取失败保留重试入口。
- 每次切换运行清空旧详情与会话结果；迟到请求通过独立版本号丢弃。读取权限失效时清空已呈现事件、会话和运行详情。
- 结果关联必须有明确的 `runId`。同一会话中其他运行的卡片不能作为本次运行的结果。

## 调研证据的边界

普通运行事件只记录脱敏元数据，不保存网页 URL、引用正文、工具输入输出或思考正文。2026-10-16 后续开发已增加“模型路由”视图及调用级候选记录，详见 [模型调用路由追溯](模型调用路由追溯.md)。随后新增“调研来源”视图，以独立私有表保存受控摘录与回答引用标记，需 V31 和显式开关，详见 [调研来源与引用追溯](Agent调研来源与引用追溯.md)。Fetch 成功、来源登记和回答引用仍不能证明结论已经核实。

受控来源 DTO、访问权限、可查看期及运行关联已在后续实现中接入。最终重定向 URL、完整快照、精确引文与结论支持度仍待开发或验收。关联结果视图不生成虚构来源卡片；来源另从专用接口读取，现有轨迹导出不包含来源私有内容。当前日志也不等同于不可篡改审计、完整模型正文归档或可恢复执行状态。
