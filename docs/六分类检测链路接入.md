## 本轮完成的代码

- `onnx_detection_engine.py`：CPU ONNX 运行器，按清单校验文件摘要、六类映射、输入输出名称及类型；预处理参数由清单指定，启动先执行一次自检；检测时拒绝非有限数值和非法类别，裁剪越界框并生成标注图。
- `kafka_detection_worker.py`：保留原 DEIM 路径；选择 ONNX 时预加载模型后再注册消费者，校验任务模型 ID，禁止用另一个模型执行并冒用任务所选模型；加入消费者分配状态、健康记录和停止处理。
- `worker_health.py`：仅在模型已加载、分配到 Kafka 分区并且心跳未过期时通过就绪检查。
- `deploy/worker/Dockerfile`、`requirements.txt`：独立非 root CPU worker 镜像，不打包权重或密钥。
- `compose.detection.yml`：叠加现有云部署，只读挂载模型目录，worker 健康后启用后端检测；该叠加文件尚未用于服务器启动。

该运行器期望模型导出包含 `images: float32`、`orig_target_sizes: int64` 两个输入，以及 `labels/boxes/scores` 三个输出。图像输入固定 640×640；原图尺寸按训练 PostProcessor 的 `[width,height]` 传入。模型清单格式：

```json
{
  "schemaVersion": 1,
  "modelFile": "model.onnx",
  "onnxSha256": "实际导出文件的SHA256",
  "classNames": ["Normal", "Bent", "Deformed", "Rusty", "Missing", "Compromised"],
  "inputSize": [640, 640],
  "mean": [0.485, 0.456, 0.406],
  "std": [0.229, 0.224, 0.225]
}
```

以上归一化值来自当前 DINOv3 配置，实际导出前必须再核对原训练工程，不能把示例当作权重自带元数据。模型通过校验后还需经主管模型管理接口上传、发布，取得真实模型 ID；worker 的 `DETECTION_MODEL_ID` 必须与之对应。
