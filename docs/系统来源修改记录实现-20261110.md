# 检测系统来源修改记录

本提交保留模块化单体和既有 29 表。以下是实现与待 ECS 验证的合同，不表示已部署或已通过运行验收。

## 真实执行与原发起人

`SystemChangeAuditApi` 是内部 Java 端口，没有 Controller、HTTP 参数、Agent 工具或可选用户角色入口。来源组件是服务器固定枚举 `DETECTION_WORKER`、`IMAGE_DETECTION_ASYNC`、`IMAGE_DETECTION`。实际执行主体为系统，审计公共 `actor_user_id`、`owner_user_id` 都是 NULL；不会使用线程里的主管身份、构造 SYSTEM 用户角色或重查原发起人的当前资格。

原发起人从任务已保存的 `created_user_id`、`created_identity_name`/`created_by` 读取，独立、可空。用户已删除、降权或后台没有登录上下文不阻断真实完成事实；读取历史仍经过当前读者身份及现有任务资源权限。历史姓名只是原值，不用于恢复当前授权。

## 载荷、唯一性与兼容

`audit_event.kind='OPERATIONS'` 的版本 1、2 格式不改；版本 3 固定 `source='SYSTEM'`、`scope='ENTERPRISE'`、`result='APPLIED'`，增加固定组件、稳定 `sourceEventId`、可空 `initiator`、真实前后版本与有界字段差异。请求号等于该系统事件标识；无合法外部事件号的本地事实使用组件、任务、dispatch、动作计算稳定 SHA-256 标识，不生成每次重试都不同的请求号。

新增同表 generated `operation_actor_key`：原版本为 `USER:<actor_user_id>`，系统版本为 `SYSTEM:<component>`。原收据唯一键首列改用该生成列，其他域/类型/动作/资源/请求/结果维度保持；避免 NULL 在 MySQL 唯一索引中允许重复而漏掉系统重放。旧用户唯一语义保持，系统同号同事实重放返回原审计，内容不同拒绝。没有新增表、SYSTEM 账号或默认主管归属。

schema author 与 baseline、classpath mirror 同步；JSON_SCHEMA_VALID 校验 V3 闭合结构、组件枚举、来源、原发起人形状、非空有界差异、请求一致及前后版本关系。现有 OPERATIONS 追加不可改/不可删触发器也保护 V3。启用修改/历史能力时，启动检查要求真实 generated actor key 及完整唯一索引，旧 V2 compact 结构不会被默认为已经升级。

既有迁移从冻结旧库进入全新 owned 29 表目标，继续使用现有完整 DDL/迁移/恢复门；本提交不增加就地改造生产库的旁路。旧 compact 目标必须经过获准的结构升级/新候选及完整验收，不能只开功能标志来跳过 schema 门。当前未执行数据库升级、DDL、测试或切库。

新 history wire 在 Item/Detail 末尾增加 `source{type,component,eventId,initiator}`，旧 Java 构造器保留。V1 为 UNKNOWN，V2 为 USER，V3 为 SYSTEM 且 `actor=null`。Initiator 的稳定 ID 在 wire 中为字符串。显式资源 history 使用 V2/V3，并重新检查当前资源权限；默认个人历史不会因为 actor 为 NULL 把系统记录当成本人操作。SSE 企业系统事件仍逐资源当前鉴权，PRIVATE 的空执行账号被拒绝。

## 真实入口与事务

- `DetectionTaskServiceImpl.applyFinishedEvent` 锁任务行，先拒绝旧 dispatch、重复 event 和已终态结果，再在同一事务保存实际统计/终态、一次版本推进、必要 V3 审计。中间 UPLOADING_RESULT 不是独立已提交历史。聊天完成提示与修改通知只在提交后发送。
- `failTask` 使用相同行锁/版本/必要审计；dispatch 异常调用额外携带开始时 dispatch 快照，迟到旧 dispatch 不会把新重试写成失败。已终态失败不会因新错误字符串产生第二份历史。
- 图片批量入口先保存 QUEUED，事务提交后调度真正异步执行。`ImageDetectionAsyncService` 进入实际执行时通过事务写入 PROCESSING/开始历史，推理及文件 IO 不持有数据库行锁；真实结束/失败再以新的事务、原 dispatch 和当前状态条件保存。必要审计失败回滚该事实及版本，不把审计持久化失败伪装成新的推理失败。
- 同步单图路径在真实推理完成并登记任务后记录系统完成创建事实，初始版本来自实际新行。远程完成事件中的 startedAt 是 worker 返回的事实字段；没有远程开始回调时，不补造之前已经发布过的独立开始事件。

差异只包含状态、数量、时间、登记标记及 SHA-256 指纹。统计/缺陷大正文、错误原文、OSS 地址、签名 URL、图片、聊天和凭据不进入新审计正文。每次最多 64 个字段，每个字符串最多 512 字符，整体最多 256 KiB。
