# 真实应用隔离升级与回滚演练

适用分支 `java-cloud`，时间使用 UTC+8。复用当前 Compose、生产 Dockerfile、备份验证和记忆兼容保护；不引入新的部署框架。

## 入口与范围

Jenkins 新增 `ACTION=rehearse`。先运行现有完整 CI，再按实际检出提交打包源码，使用服务器缓存构建后端、Vue/React 网页和 Mem0 镜像。整个过程使用 `doorhandle-rehearsal-<随机编号>` 专属项目，生产发布阶段不执行。

备份需要已通过摘要、归档和数据库完整性校验。还原 MySQL 后先核对表行数与校验值，文件卷逐项比较目录及内容摘要。原检测模型仅只读挂载；OSS 对象仍是外部资源，本演练不重复执行检测、分派、审批或对象上传。备份存在待执行 Agent 输入、专业任务或 MCP 安装时阻止启动，避免复制后自动重做。

卷、网络、数据库及缓存密码、JWT、记忆桥接和 MCP 认证均使用独立身份，网页只监听服务器 `127.0.0.1:18089`。不改变生产入口、数据库或文件卷。升级/回滚前后再次核对生产容器编号、镜像、运行状态和挂载不变；这不代表对生产业务表进行了冻结或完整写入审计。

## 演练门槛

1. 备份旧版本启动，四个演示账号登录，主站与独立聊天入口、八项能力可读。
2. 在独立用户目录上传标记文件，记录实际字节摘要。
3. 运行真实 Java 后端与新版记忆桥接；登录、权限及文件保留检查通过。
4. 使用真实 Mem0 提炼一条演示偏好，经 Java 接口明确确认停用，核对 MySQL 审计成功。
5. 回滚旧 Java/网页镜像。持久协议门槛要求保留兼容的新记忆桥接，核对容器身份及原生检索不返回已停用条目。
6. 再激活候选版本并重启完整 Java 后端，检查私有文件、记忆停用状态和版本仍在，其他账号不能读取文件。

默认清理独立容器、卷和网络，保留私有证据；删除前核对随机项目身份与资源标签。`REHEARSAL_KEEP=true` 仅在全部通过后保留环境，便于立即开展两入口真实业务联调。后续使用同一辅助脚本的 `cleanup --root <发布根目录> --project <精确演练编号>` 清理。

私有 Compose 中含凭据，构建和应用诊断日志也可能含业务信息，均留在服务器的私有演练目录，不归档到 Jenkins。Jenkins 仅保存不含凭据的结果摘要。不要将这些私有文件提交仓库。
