# 检测模型文件治理适配

状态：生产代码、V53 复制候选和 ECS 专用测试已编写，尚未执行迁移、测试或部署。统一编译由根代理安排。本文不表示正式文件或业务库已经完成迁移。

## 原协议与实际落点

源码依据为 `ModelFileJournal`、`ModelUploadFiles`、`ModelRegistrationService` 和 `migration-V53-detection-model-file-journal.sql`。

| 原表 | 源字段 | 实际目标 |
| --- | --- | --- |
| `detection_model_file_journal` | 12 列：file_id、actor_user_id、request_id、storage_path、path_sha256、content_sha256、byte_size、model_id、state、revision、created_at、updated_at | `workflow_instance` 的 `MODEL_FILE_UPLOAD` |
| `detection_model_file_retention` | 13 列：retention_id、model_id、actor_user_id、request_id、file_id、storage_path、path_sha256、content_sha256、byte_size、state、revision、created_at、updated_at | `audit_event` 的 `MODEL_FILE_RETENTION` |

这两类记录分别是上传过程与删除模型后的文件保留事实。`RESERVED` 只证明登记过写文件意图，不能推断文件已存在、摘要已核验或内容版本已形成，因此不为它创建内容资产、版本或关联占位。没有新增业务表、旧表兼容视图或自动 SQL 改写。

上传保持 `RESERVED → FILE_READY → REGISTERED → RETAINED`，只有 `RETAINED` 是终态；没有自动重试、抢占租约、过期删除或定时清理。`FILE_READY` 表示字节写入及摘要计算结束，`REGISTERED` 表示模型登记事务已确认，不能把这两个状态混同。新的工作流 ID 为 `model-file:` 加原 file_id，原 file_id 还保存在 resource_id 和迁移来源键中。

身份、状态、请求、版本与时间使用工作流公共字段。固定的七键 `UploadV1` 只承载文件路径、路径摘要、内容摘要、字节数、历史模型编号和原创建/更新时间。五个明确类型的生成列公开路径、两种摘要、字节数与完整 signed INT 模型编号，并由数据库约束、全局路径摘要唯一索引和模型/状态索引检查、查询。它不是允许任意字段的 Map。

原 `(actor_user_id, request_id)` 唯一约束保持不变；相同请求换了新文件 ID 或路径应失败，不能多写一份文件。所有查阅、上传、登记与保留操作继续核对当前主管权限。登记还复核当前账号、Prepared 原账号、文件 ID、请求、路径、内容摘要和字节数；其他主管可以保留待删除模型的已登记文件，不能因此改写原上传人的身份。

## 保留事实与事务

模型删除后的保留事实使用 `model-retain:` 加原 retention_id 作为事件身份，原 model_id 保存在资源标识中，允许原 signed INT 的负数和零。这里没有指向当前模型的外键，也没有为原 request_id 新增唯一约束：历史事实必须在模型行删除之后继续存在，同一个请求可能包含多条不同保留事实。

内容摘要与字节数进入审计明确字段，固定的七键 `RetentionV1` 保存保留 ID、可空文件 ID、路径、路径摘要、独立的 UTC 更新时间及两项原时间。`RETAINED_LEGACY` 的文件 ID、内容摘要和长度保持未知 NULL，不生成虚假摘要或零长度。`RETAINED` 的文件归属必须能够与登记事实核对。

上传文件与内容校验仍在数据库事务外。登记状态与模型行插入、强制操作审计在同一事务；文件保留事件、上传状态转为保留与模型删除在同一事务。任一步骤未确认时不删除字节，也不把连接异常当作安全重试依据。现有 `OperationsAuditApi` 继续记录原有的 `FILE_RESERVED`、`FILE_READY`、`FILE_REGISTERED`、`FILE_RETAINED` 操作；复制不会编造源库未记录的阶段历史。

`model.file-journal.enabled` 的启用方式不变。启用时验证 compact 协议结构，不再要求两张旧表。对外 DTO 继续不返回路径、文件名或删除命令。接口更新时间按北京时间显示；迁移的原 DATETIME 字符串另存证据，不把源时区当作固定北京时间。Web Jackson 的 NON_NULL 配置不能删除持久化协议里的可空键，仓储使用独立的 ALWAYS 配置。

## 复制及待执行验收

`script/schema/author_model_files_copy.py` 只生成 `sql/mysql/compact/copy/42-model-file-governance.sql`，不连接数据库。复制要求不同的源/目标库、源停写、严格 SQL 模式、外键检查启用和直接源库元数据可见权限。

V53 未显式声明两张表的默认排序规则，脚本要求填入已核实的 `__SOURCE_MODEL_FILE_COLLATION__`，逐表核对，并对未单独声明排序规则的 state 列逐项匹配；显式身份/路径/摘要列继续精确要求 utf8mb4_bin。没有自动容忍列增加、类型/NULL/默认值/索引/触发器/外键/检查约束漂移。

`__SOURCE_MODEL_FILE_OFFSET__` 仅接受明确的 `±HH:MM`。创建时间和更新时间各自转换，并验证实际偏移秒差；超范围未转换的时间不能当作 UTC。源 revision、两项时间及全部可空事实均保留，异常行会使整批失败，不过滤，也不猜修。非空 retention.file_id 必须在源上传记录中找到相符的模型编号、路径、摘要、长度及保留状态；不反向要求历史模型行仍存在。

最终检查覆盖数量、每一项源字段、固定 payload、typed 生成列、公共字段的 NULL/固定值以及字节级来源键。失败由同一连接回滚；脚本不修改源表或文件。

`ModelFileGovernanceMySqlTest` 必须同时提供 ECS 项目 work 目录下的私有配置属性 `model.file.copy.source-config` 和 `model.file.copy.target-config`。两库均须事先准备为空库，使用既有 `EcsIsolatedMysql` 机器/实例/账号/端口/数据目录校验；测试不创建数据库、不授予权限、不回退到本地或业务库。目标使用实际 compact 30、37、39，源使用实际 V53 声明。

待执行用例包括：完整字段与不同创建/更新时间、无父模型的历史保留、负数/零模型编号、同请求多条保留、NULL 原事实；实际写文件后登记和模型删除仍保留字节；审计失败全事务回滚；请求/路径唯一约束竞争；撤销权限与 Prepared 账号变化；源结构漂移及非法历史；相同行数下的来源尾空格/原时间/额外摘要注入；UTC 偏移与重复复制拒绝。需要真实 ECS 结果后才能给出迁移或业务验收结论。
