# 协同登录会话与账号权限实施

本次沿用模块化单体、Spring Security、MyBatis Plus 和现有 29 表目标结构。以下为源码实现及启用约定；本地仅完成跳过测试的编译与 SQL 源码编译，真实 HTTP、MySQL、并发和迁移结果由固定提交的 Jenkins ECS 流水线提供。正式 131 表库未升级或切换。

## 登录资格和旧角色

所有生产认证路径均重新读取 `users.enabled`、账号角色及绑定员工当前事实。`INSPECTOR` 必须绑定在岗 `DETECTION` 员工；已绑定员工的主管也必须对应在岗 `DETECTION` 或 `SUPERVISOR` 岗位。未绑定员工的 `SUPERVISOR` 可作为初始组织管理账号登录。采集、维修、离职或不存在的人员不能凭残留 JWT 取得登录资格。

最终角色只有 `SUPERVISOR`、`INSPECTOR`。不将未知值默认降为检测员。历史别名必须按账号作出明确决定：`ADMIN` 只可映射到 `SUPERVISOR`，`OPERATOR` 只可映射到 `INSPECTOR`，且映射后仍校验岗位。配置 `collaboration.sessions.legacy-role-accounts` 默认为空；没有已审定的真实账户清单，因此本次不添加任何生产例外。迁移保留原始角色，不猜测或批量提升权限。主管可通过账号权限接口把经过核对的目标账号改为最终角色；原 `ADMIN` 管理账号须先有明确兼容决定，或先使用现有正式角色主管。

示例仅说明配置形状，实际用户名必须逐个核实：

```yaml
collaboration:
  sessions:
    enabled: true
    legacy-role-accounts:
      "[reviewed.admin]": SUPERVISOR
      "[reviewed.operator]": INSPECTOR
```

## 独立会话

`collaboration.sessions.enabled=true` 时，每次登录创建新的随机 `sid` 和页面 `accountContext`。访问与刷新 JWT 均携带相同账号和 `sid`，用途明确分为 `access`、`refresh`。`runtime_state` 仅存 `SHA-256(sid)`、刷新令牌摘要和受约束的版本化元数据，不存原始 JWT、密码或 `sid`，不使用 SDK 专属的 `session_id/state_key`。

刷新凭据在该会话固定期限内保持一致；刷新在同一数据库行上以 `revision` 串行更新，避免标签页迟到响应覆盖新刷新凭据。账号行先于会话行加锁，与账号权限变更顺序一致。访问 JWT 的到期不超过会话到期，刷新 Cookie 的剩余期限也不因刷新而重新增加 30 天。过滤器只把已验签访问 JWT 的实际到期时间写入 `doorhandle.auth.accessExpiresAt`，SSE 不得使用较长的刷新期限代替。

退出只撤销当前 `sid`。账号停用、角色变更、员工绑定变化及员工状态/岗位变化在业务事务内撤销相关会话，事务回滚则保留原会话。`LoginEligibilityChanged` 和 `EmployeeLoginEligibilityChanged` 在提交前完成持久撤销；`LoginSessionRevoked`、`AccountAccessChanged` 供提交后关闭相应 SSE 连接。过期扫描每次最多处理 500 条，保留已撤销元数据，不删除业务记录；`ix_runtime_login_expiry` 支持按命名空间、状态及到期时间扫描。

关闭会话开关时仍校验当前账号及岗位，`accountContext` 返回服务端稳定的账号摘要；提供旧上下文时仍拒绝串号。该模式没有独立服务端会话，退出仅清 Cookie，不宣称已撤销历史凭据。

## HTTP 接口

`GET /api/auth/check` 返回 `authenticated/userId/username/role/identity/accountContext/capabilities`。能力包含 `sessionTracking/changeHistory/mutations/realtime`；基础审计关闭时不宣称具备修改记录和变更通知，实时能力还要求会话与历史开关开启。

启用会话后，业务写请求及刷新/退出都必须携带 `X-Account-Context`；缺失或不匹配返回 HTTP 409、`code=ACCOUNT_CONTEXT_CHANGED`，失效凭据返回 401。关闭会话时该请求头可选，提供后仍比较。操作人只来自服务端认证身份。

Cookie 写请求要求精确同源 `Origin` 或 `Referer`。包含 Cookie 时，伪造 `Authorization` 不能绕过来源校验；无 Cookie 的受控客户端可提供 Bearer 或刷新请求头。代理必须保留实际公共主机，并按部署中的可信代理配置解决协议；应用不直接信任任意转发头。登录限流以请求实际 `remoteAddr` 为准，不读取任意 `X-Forwarded-For`。生产 HTTPS 继续配置 Secure/HttpOnly/SameSite Cookie。

主管账号管理入口：

| 接口 | 输入或输出 |
| --- | --- |
| `GET /api/accounts/{userId}/access` | `userId/username/enabled/role/accountVersion` |
| `POST /api/accounts/{userId}/access` | `{enabled, role: SUPERVISOR或INSPECTOR, expectedVersion, requestId}`，返回同上 |

变更以账号版本 CAS，按稳定 ID 顺序锁操作者及目标，禁止停用/降权本人，保留至少一个启用主管。完全相同的值不递增版本或撤销会话。`ACCOUNT_ACCESS` 使用公共 `@BusinessMutation` 参与者、`BUSINESS_COMMAND` 幂等回执及同事务修改记录，不另建命令命名空间或重复手工审计。

## Schema、迁移与验证

`users` 新增 `enabled BOOLEAN NOT NULL DEFAULT TRUE`、`account_version BIGINT NOT NULL DEFAULT 0` 和合法值检查。历史源声明及历史夹具保持原列；`author_core_copy.py` 明确向新目标写 `TRUE/0` 并逐行核对，源库缺少这两列不会被误作缺列迁移错误，也不把目标列伪装成历史事实。已有恢复流程按完整备份 DDL 与快照校验，保留新列及会话；不得在未验收的生产源库直接开启候选功能。

`author_login_session_schema.py` 生成 `LOGIN_SESSION` 闭合 JSON Schema、字段约束和到期索引，同步根 SQL 与完整 classpath 镜像。目标表数保持 29。

ECS 用例包括 `LoginSessionFilterTest`、`LoginEligibilityServiceTest`、更新后的角色拒绝用例、`LoginSessionMySqlTest`，以及 `CoreCopyMigrationMySqlTest` 新增的历史缺列/显式目标默认值核对。MySQL 套件复用 `doorhandle.operations.mysql.config` 和已有 ECS 隔离夹具。源码编译通过不表示这些用例已执行，也不表示数据库迁移、生产发布或性能目标已经通过。
