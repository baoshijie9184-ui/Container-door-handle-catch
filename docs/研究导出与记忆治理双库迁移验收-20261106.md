## 双库与执行前提

两个库须位于同一已准入 ECS 隔离 MySQL 实例且名称不同。夹具拒绝非 Linux 执行、未绑定当前 ECS 的私有配置、非隔离端口或账号，以及非空库。沿用 `EcsIsolatedMysql` 的机器 ID、实例 ID、server UUID、端口和数据目录核对。

需要外部已准备好的两个空库和权限。测试代码不执行 `CREATE DATABASE`、`GRANT`，不回退到业务库或本机数据库。目标账号须已具有源库的直接 `SELECT`、`TRIGGER` 元数据访问权限，防止无权查看触发器却误判为不存在。夹具结束时只清理由本次空库夹具登记的表；两侧身份变化或出现未登记对象时拒绝清理。

## 对账与待执行用例

- 正常复制核对每条原身份、哈希、显式 payload 字段和 UTC 时间。研究导出只保存数量、格式版本、字节数和摘要；不复制正文。旧限流记录没有创建/更新时间，继续保留 NULL。
- 原记忆变更保存当时的状态快照，不伪造缺失的状态转换历史。偏好更新的原时间独立保留，未知操作结果继续为 UNKNOWN。
- 所有 `legacy_source`、`legacy_key` 关联使用 `BINARY`，避免 `utf8mb4_bin` 的 PAD SPACE 规则将尾空格当成相同身份；加入目标插入触发器篡改尾空格的回滚用例。
- 分别构造“只有源 run 归属正确”“只有目标 run 归属正确”“目标 run 缺失”。不能只凭源或目标之一匹配就允许导出审计迁移。
- 对源新增字段、改变类型、NULL、排序规则、默认值、删除唯一键/普通索引、删除或改为级联外键、添加 CHECK/触发器分别拒绝，并检查目标仍为空。
- 保留相同行数但哈希改变、payload 字段丢失的逐行对账失败用例，以及重复复制、事务回滚、并发限流和并发记忆操作的原验收代码。

尚需根代理统一 Java 编译；之后由 ECS 隔离 MySQL 实际执行正常和破坏路径。真实源库结构与闭合契约若不一致，应先调查并明确新增事实的归属，不允许靠放宽门禁或填默认值跳过。全量复制顺序、其他领域数据、最终外键安装、应用联调与恢复演练仍属正式迁移的后续验收。
