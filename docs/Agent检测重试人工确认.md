# Agent 检测重试人工确认

分支：`java-cloud`。更新日期：2026-10-21，UTC+8。当前为未发布实现，生产开关保持关闭。

## 使用流程

1. 用户明确提供有权访问的任务编号并要求重新检测。员工通过 `detection-task`，主管通过 `detection-quality` 调用 `propose_detection_retry`。
2. 工具只保存待确认提议，不派发检测。提议固定任务版本、原图数量、检测模型、阈值、上次派发编号和重试影响，十分钟内有效。模型及聊天中的口头同意不能批准。
3. 用户在 Vue 操作确认页、聊天确认区或独立 React 的工作区核对卡片，选择确认、拒绝或取消。修改任务后必须重新生成提议。
4. 确认时重新检查账号、资源范围、运行状态、任务版本和上次执行回执。通过后创建新的 `dispatchId`，清空当前检测结果和复核/处置状态，再保存命令回执、事务消息及必要审计。
5. 页面显示“已提交检测”，实际推理进度仍以检测记录为准。重试不会自动复核、放行或审批报告。

原有主管质检分配卡片和接口保持兼容。普通员工可以提出自己有权访问任务的重试提议，不能获得主管的质检分配工具。等待确认不占用 Agent 执行槽。

## 事务与恢复

- 复用 `/api/agent/actions` 及原确认/取消接口，不增加模型可调用的批准工具。确认请求只携带决策和版本；业务参数从已持久化提议读取。
- 确认动作编号同时作为业务请求编号和提议编号。重复确认返回原结果；不同提议竞争同一任务版本时只接受一个派发。
- AI 模块通过 `contracts/DetectionExecutionApi` 调用检测模块，不直接访问检测业务表。提议、命令回执、任务更新、事务消息及审计使用单体数据库事务；失败回滚，不能以吞掉异常方式显示成功。
- 保存业务回执前先核对派发消息确实存在。完成回执重新校验内容摘要与任务/派发/状态绑定；缺失、损坏、运行中或待核对的旧结果不能触发新的检测。
- 恢复未知的 SDK 提议调用时，只查询原提议登记状态，不自动批准或重新派发。确认响应丢失后需要显式刷新核对，两入口不自动重发写请求。
- 重试卡片的历史读取重新核对业务可见范围；撤销访问后不再返回原授权快照。取消本人提议不等于取消其他检测执行。
- MyBatis-Plus 默认忽略 null 更新，因此重试改为显式 SQL 清空旧结果、复核和处置字段，避免界面显示新任务却仍读取旧结果。

worker 的原事件去重及未知结果限制见 [检测执行回执与事务消息](检测执行回执与事务消息.md)。

## 启用前提

需要已有 V19 确认表、运行日志、V42 检测回执/事务消息，以及人工确认、业务审计和检测执行所需配置。`DETECTION_EXECUTION_COMMANDS_ENABLED` 必须同时控制后端事务消息和 worker 回执，不能只打开一侧。没有可用检测执行门面时，不注册重试工具，也不退回旧的无回执派发方式。

本轮没有开启生产开关、修改部署数据或触发真实检测。界面支持参数和版本核对，原图缩略图/完整授权资料展示仍待补齐；“从当前会话文件创建新检测任务”的受确认工具仍未完成。
