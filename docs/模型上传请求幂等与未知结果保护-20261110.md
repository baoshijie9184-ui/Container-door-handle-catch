# 模型上传请求幂等与未知结果保护

`POST /api/models/upload` 的重试继续使用同一个 `X-Request-ID`。本轮沿用 `workflow_instance` 中的 `MODEL_FILE_UPLOAD` 和公共 `BUSINESS_COMMAND`，没有新增表、命名空间、云端上传或文件删除操作。实现仍属于模块化单体。

## 同一请求的处理

先有界读取收到的文件，核对实际大小及 SHA-256；以带版本前缀、明确空值和长度边界的编码，对当前稳定账号、请求编号、文件摘要/大小、模型名称/版本/说明生成意图摘要，保存在现有 `request_sha256`。不把客户端文件名当作服务端文件身份，也不保存原始模型内容到数据库。

在生成新文件前，按账号和请求查现有文件登记。只有意图摘要匹配且状态为 `FILE_READY` 或 `REGISTERED`，才读取原 `fileId`、受管路径和原内容摘要；随后重新核对受管路径、实际长度及完整字节摘要。复用时不创建文件、不追加预留/就绪记录、不替换内容。并发新请求由现有永久唯一键裁决，竞争者不能写到另一条随机路径。

| 已有状态或证据 | 处理 |
| --- | --- |
| 没有已有登记且模型名称/版本可用 | 先提交预留，再于 SQL 事务外用 `CREATE_NEW` 写文件；强制落盘、再次比对收到的原内容，再提交就绪证据 |
| `FILE_READY` 且证据一致 | 复用原文件；调用原注册事务完成模型登记及必要审计 |
| `REGISTERED` 且证据一致 | 不重新执行模型验证；进入原注册切面，只允许公共业务回执返回原模型和版本/审计响应头 |
| `REGISTERED` 但业务回执缺失或无效 | HTTP 409；注册方法在任何 INSERT 前拒绝，不猜测成功，也不重新执行 |
| `RESERVED` | HTTP 409；可能是部分写入或提交结果未知，保留原登记和文件供核对 |
| `RETAINED`、实际文件被改、路径/账号不一致 | 拒绝复用，保留原件；不重新上传或复活已移除模型 |
| 相同账号/请求但文件或模型元数据不同 | HTTP 409；不创建额外文件，不把该请求改作其他内容 |

旧迁移和早期上传使用原路径/文件身份摘要，没有完整客户端意图证据。本轮不改写其摘要，不把旧登记猜测为可安全重试的请求；读取仍保留，重试时明确冲突并要求人工核对。

## 不确定结果

文件 IO 始终在业务 SQL 事务外；预留、就绪和注册分别有原有持久证据。模型登记、`REGISTERED` 状态、修改记录和 `BUSINESS_COMMAND` 回执同事务提交。响应丢失后，显式重试只能从已提交证据确认原结果。事务未成功时就绪文件保留，可在确认仍为 `FILE_READY` 后沿原注册事务重试；`RESERVED` 不能直接恢复写入。

原有明确 INSERT 编号冲突重试仍只重试已知回滚的 SQL 登记，不重放文件写入。网络、审计或提交异常不自动重试，也不删除文件。上传接口将冲突返回真实 HTTP 409、未确认返回 500，响应禁止缓存；请求编号继续通过原响应头提供。
