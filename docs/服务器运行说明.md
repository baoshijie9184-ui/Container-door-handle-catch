# 服务器运行说明

`java-cloud` 用于部署在北京 ECS 的模块化单体。日常使用连接服务器，本机用于编辑、测试和运行 Jenkins。服务器部署的业务代码版本以发布记录为准。

## 访问系统

在项目根目录执行并保持终端运行：

```powershell
ssh -F work/cloud/ssh-config -N -L 127.0.0.1:18088:127.0.0.1:8088 doorhandle-bj
```

- 主站登录：<http://127.0.0.1:18088/#/login>
- 独立 Agent UI：<http://127.0.0.1:18088/agent-ui/>
- 本机 Jenkins：<http://127.0.0.1:18080/>

隧道只转发 Web 入口，不会在本机启动业务服务。SSH 配置、公有证书、known_hosts 和私钥均在忽略目录内；新克隆仓库须另行配置。节省停机后先查询公网 IP，并更新连接配置及 Jenkins 的 `DEPLOY_HOST`。当前 TLS 连接须同时通过证书与 SSH 主机公钥检查，具体见 [SSH 连接说明](../script/jenkins/README.md#当前网络-ssh-连接修复)。

通过 [OOS 任务详情](https://oos.console.aliyun.com/cn-beijing/execution/detail/exec-d8e4d9bfb21640ccaeb7) 查看“历史执行”“即将执行”和“执行日志”。夜间需要持续使用时，先在此处取消或调整任务；取消定时任务不会释放 ECS。默认不自动开机，日间按需手动启动。

节省停机保留实例、系统盘、Docker 镜像与持久数据，计算资源停止计费，**保留的云盘仍计存储费**；OSS 保持原状，独立计费。再次开机后重新核对公网 IP 和上述连接配置。不能用操作系统内 `shutdown` 替代云端节省停机。计费与支持条件参见 [阿里云节省停机文档](https://help.aliyun.com/zh/ecs/user-guide/economical-mode)。

OOS 控制台的模板权限检查使用 `Resource=*`，会对只授权单台实例的 `ecs:StopInstance` 提示缺失；已核对实际保存的策略为目标实例 ARN，不扩大为所有实例权限。定时配置已生效，首次真正的零点触发结果仍应在上述历史执行中核对。

## 服务检查

```powershell
ssh -F work/cloud/ssh-config doorhandle-bj
```

连接到服务器后执行：

```bash
docker ps -a --filter label=com.docker.compose.project=doorhandlecatch-monolith \
  --format 'table {{.Names}}\t{{.Status}}'
curl -fsS http://127.0.0.1:8088/nginx-health
cat /home/ecs-user/doorhandle-ci/state/current-directory
```

八个常驻服务为 `backend`、`nginx`、`mysql`、`redis`、`kafka`、`mem0`、`chroma`、`detection-worker`。初始化容器正常退出不等于服务故障。常驻服务配置 `restart: unless-stopped`，操作系统正常启动后通常由 Docker 恢复；主动停止的容器需要显式启动。

2026-10-15 已启用 AI 网关，另有 `higress`、`mcp-runner`、`mcp-egress` 三个常驻容器，共 11 项；临时 Fetch 容器在调用结束后销毁。ECS 公网 IP 发生变化时，还须更新私有配置的 `MCP_SERVER_PUBLIC_IPS` 并重新生成出口规则，见 [网关部署说明](../deploy/mcp/README.md)。

已存在的容器可通过 `docker start <容器名>` 恢复，随后等待健康检查。排查单项服务使用 `docker logs --tail 100 <容器名>`。代码更新走 Jenkins 发布，不用启动旧目录中的 JAR，也不根据旧镜像标签重建已有服务。

## 构建与发布

保留 `Jenkinsfile`、`script/jenkins/`、三个 Compose 文件、`deploy/`、全部源码和测试。完整流程和凭据配置见 [Jenkins CI/CD](../script/jenkins/README.md)，发布证据见 [服务器演示部署记录](服务器演示部署记录.md)。

现有 Jenkins 任务名仍为 `doorhandle-java`，SCM 分支为 `*/java-cloud`，`Jenkinsfile` 只允许 `java-cloud` 与 `origin/java-cloud`。本机编辑器切换分支不会改变它的构建来源；提交并推送到 `java-cloud` 后，任务每五分钟轮询并构建发布。包含 `[skip ci]` 的提交跳过轮询触发，也可手动构建。

首次推送使用 `git push -u origin java-cloud`，之后使用 `git push`。原 `java` 分支保留，不需要覆盖其历史。任务参数、凭据和既有构建历史继续复用，首次切换记录见部署验收文档。

现有流水线更新 Java 后端和两套前端。修改 Mem0 或检测 worker 后须单独构建、发布和验收相应镜像。数据库迁移也需另行备份、核对与执行。

AI 网关采用可选 `compose.ai-gateway.yml`，首次按 [网关部署说明](../deploy/mcp/README.md) 构建并验收独立运行器。显式标记启用后 Jenkins 合并此 overlay；Higress、MCP 运行器和出口代理只开放容器内网，主站访问方式不变。它们的镜像升级同样独立验收，不随普通 backend/nginx 发布重建。
