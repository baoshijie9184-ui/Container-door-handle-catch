# 模型调用路由追溯

更新日期：2026-10-16。分支：`java-cloud`。归属开发进展 P10、D14 的调用观测部分。

## 功能与入口

进入“Agent智能系统 → Agent执行追溯”，选择本人运行，再打开“模型路由”。主站和独立 Agent 的运行共用记录。执行过程也显示模型候选事件；事件详情可跳转到同一模型请求的其他事件。

一次 Agent 推理步骤对应一个模型逻辑请求。路由可能先尝试默认模型、因余额不足或超时转向备用，也可能跳过仍在熔断冷却或已有恢复探测的候选。页面分别统计逻辑请求、已记录候选调用和备用选择，不把跳过当成实际调用。备用选择数量只计失败后的 `MODEL_FALLBACK_SELECTED` 事件，熔断跳过独立展示。候选序号对应配置列表的位置，中间有跳过时允许不连续。

旧运行没有这些元数据时明确显示未采集，不从 `defaultModel` 推断历史供应商。分页尚未读全时，仅展示已加载部分；导出仍要求服务器事件序号完整。

## 采集设计

继续使用 AgentScope Java 2.0.4、已有 `AgentModelService` / `ManagedAgentModel` 和运行日志，不增加供应商客户端或替换 SDK 推理循环。参考 Apache-2.0 的 [AgentScope Java 2.0.4 Middleware](https://github.com/agentscope-ai/agentscope-java/blob/v2.0.4/docs/v2/en/docs/building-blocks/middleware.md)，沿用 `onModelCall` 包装模型逻辑请求；候选尝试在本项目模型路由层记录。本轮没有复制上游代码或增加依赖。

`AgentJournalMiddleware` 在每次订阅时创建 UUID `modelRequestId`，将 `ModelAttemptTrace` 放入 Reactor Context。模型包装层在订阅时取出对应接收器。共享模型实例和熔断器不保存用户、运行或轨迹接收器，不使用 ThreadLocal；异步换线程和专业 Agent 委派仍保留当前请求范围。

| 事件 | 含义 |
| --- | --- |
| `MODEL_STARTED / COMPLETED / ERROR / CANCELLED` | SDK 模型逻辑请求；现在附带请求编号 |
| `MODEL_ATTEMPT_STARTED` | 即将调用一个可用候选的适配器 |
| `MODEL_ATTEMPT_COMPLETED` | 候选适配器成功完成流 |
| `MODEL_ATTEMPT_ERROR` | 候选失败；仅保存分类和可用的 HTTP 状态 |
| `MODEL_ATTEMPT_CANCELLED` | 候选订阅取消；运行已进入终态时不追加迟到事件 |
| `MODEL_CANDIDATE_SKIPPED` | 熔断拒绝许可，没有调用该候选适配器 |
| `MODEL_FALLBACK_SELECTED` | 失败后转向下一个候选；下个候选仍可能被熔断跳过 |

新增白名单字段为 `modelRequestId`、`modelId`、`provider`、`model`、`attempt`、`firstContentMs`、`failureReason`、`httpStatus`、`nextModelId`。沿用 `agent`、`parentCallId`、`elapsedMs`、`durationMs`。数据继续写入既有 `agent_run_event.payload_json`，**无需数据库迁移**。账号范围、事件上限和游标读取规则保持一致。

错误分类只包括 `QUOTA`、`AUTH`、`TIMEOUT`、`EMPTY_RESPONSE`、`TRANSIENT`、`OTHER` 和跳过原因 `CIRCUIT_OPEN`，不写入异常消息、响应正文、请求地址、密钥、输入输出或思考正文。首段内容包含文本、思考块或工具内容，缺失时间与明确的 0 ms 分开展示。

日志写入失败终止请求，不将其作为供应商故障，不更新供应商失败计数，也不触发备用付费调用。开始事件失败时不调用供应商；成功结束事件失败时不再重放。取消尽力记录，且始终释放恢复探测许可。取消后终态不可追加时保留已有终态，不绕过现有日志限制。

## 统计与准确性边界

- `provider` 是已选择候选的应用接入标识。`openai` 也可代表灵算等自定义 Responses 上游，不代表请求一定发给 OpenAI 官方。
- `model` 是候选适配器请求的模型名；没有采集供应商内部转发或服务端实际权重名称。
- 候选开始表示适配器调用尝试，不保证请求已到达供应商。网络握手失败也属于该尝试。
- SDK 内部 HTTP 重试没有逐次采集。启用备用时已有配置限制 SDK 为单次尝试；关闭备用时不能把候选事件数量视为 HTTP 请求总数。
- Token 总数继续只汇总 `MODEL_COMPLETED` 的 SDK 用量，不将候选事件重复相加。失败请求的供应商可能已计费但未返回用量，页面不推算费用。
- 候选在开始事件写入后取消、或者取消晚于运行终态时，可能没有候选结束记录；页面显示未记录终态，不伪造失败或成功。

## 验证与交付

`ModelAttemptTraceTest` 覆盖余额不足后的备用身份、熔断跳过、部分输出后禁止重放、取消、日志开始/完成失败、订阅隔离与空回复。`AgentJournalIntegrationTest` 使用真实 Harness/ReAct SDK、脚本模型和隔离 H2，验证主 Agent → 专业 Agent → 业务工具的四次模型逻辑请求：请求编号独立、父委派正确、元数据落库、其他账号返回 404。此验证不调用付费生成模型。

前端测试覆盖请求关联、跳过、历史缺失、并行上下文、零值和 Token 不重复计数。浏览器验收扩展原追溯脚本，检查实际模型候选卡片、HTTP 状态、备用选择、详情跳转、手机界面与旧记录降级。浏览器采用隔离 API 数据，无生成调用。
