# 本地测试用户账号

登录页面：http://127.0.0.1:3001/#/login

当前单体项目使用员工和主管两种用户类型，各准备两个账号。以下账号已在本机业务库 `doorhandledb` 中就绪，用于本地开发与测试。

| 用户类型 | 角色标识 | 用户名 | 密码 |
| --- | --- | --- | --- |
| 员工 | `INSPECTOR` | `inspector.demo` | `123456` |
| 员工 | `INSPECTOR` | `inspector.demo2` | `123456` |
| 主管 | `SUPERVISOR` | `supervisor.demo` | `123456` |
| 主管 | `SUPERVISOR` | `supervisor.demo2` | `123456` |

员工账号对应 `employee-main` Agent，主管账号对应 `supervisor-main` Agent。角色由后端读取数据库并校验，不由前端选择。切换账号时先退出登录，再使用另一账号登录。

账号和员工资料是不同数据，四个账号不会按名字猜测绑定。主管在“产线资源 → 账号与组织”选择在岗员工保存关联，员工可在同页查看本人身份。新增员工前先创建部门。关联不改变账号密码、角色或任务数据范围；细节见 [账号员工部门关联](账号员工部门关联.md)。

独立 Agent UI 地址为 http://127.0.0.1:3003。先在上述主站登录，再在同一浏览器打开 Agent UI；两端均使用 `127.0.0.1`，以共享后端登录 Cookie。

本机保留原有员工、主管演示账号，本次仅新增 `inspector.demo2` 和 `supervisor.demo2`，没有修改原有账号。数据库保存 BCrypt 密码摘要。

其他本地开发库可使用项目已有 [V18 测试账号 SQL](../sql/mysql/migration-V18-test-users.sql) 准备四个账号。该脚本会将同名账号的密码和角色更新为上述值；统一启动脚本不会自动导入这些账号。
