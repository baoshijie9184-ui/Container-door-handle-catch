# 厂家与员工额度

主管在“LLM模型管理”的“厂家预算与个人限额”面板登记期初预算和模型单价。“分配对象”默认选中“我自己”，主管可直接设置自己的累计限额，也可选择员工分配限额。员工可查看自己的用量流水和限额。

启用厂家额度后，主管和管理员也须先分配本人限额。每次调用同时检查厂家可用额度和调用者的个人限额。主管可直接修改自己的限额，无需申请，其他主管的个人限额由其本人设置。修改累计上限会保留已有消耗和预留。启用前主管仅在厂家账本产生的用量和预留，仍按原回执结算。

| 厂家 | 厂家额度 | 个人额度（含主管） |
|---|---|---|
| 阿里云百炼 | 每个具体模型独立的 token 池 | 每人每个模型单独分配 token |
| OpenAI | 同一接入账户的多个模型共用 USD | 每人在该账户下的模型共用美元限额 |
| DeepSeek | 人民币账户的多个模型共用 CNY | 每人在该账户下的模型共用人民币限额 |

目前每个厂家对应一个接入账户。登记总额时同时填写已核对的期初已用，之后本站用量从调用回执累加。厂家可用额度为总额减去期初已用、本站已用和进行中预留。个人可用额度为该账号的累计限额减去个人已用和预留。员工既有的单模型 token 审批仍可作为附加限制。

受管 Agent 路由按服务端登录身份、实际模型和每次供应商尝试编号记账，输入、输出、缓存命中和采用的单价可追溯。预留在发送请求前完成；同一事务检查厂家和员工两份额度，已确认的调用结算一次。不同供应商尝试分别记账。金额按已登记的每百万普通输入、缓存输入和输出 token 单价计算，以十进制保存。适用阶梯、服务档位、工具费或其他费率的模型，须核对登记单价的适用条件；本站按单价计算的金额与厂家最终账单分别标识。站外使用同一密钥、独立记忆或嵌入调用的费用不能直接归属某个员工。

异常、用量不完整或无法按回执确定缓存价格时保留预留。主管在对应账号的“调用流水”选择“只看待核对”，输入账单编号、核实用量和金额后确认。恢复时沿用该次预留的账户和模型。缺少终态且超过一天的尝试也会进入核对列表。每条人工结算留有主管身份和依据，重复提交原决定不会再次记账。个人或厂家可用量不足时，后端在供应商请求前拒绝消费。

百炼表格按完整的接入模型 ID 分行，支持按名称筛选。通过百炼使用 DeepSeek 或 Kimi 系列模型时，该模型仍使用百炼的独立 token 池。评审站的额外模型由 `DASHSCOPE_ADDITIONAL_MODELS` 配置。主管登记的是本站预算，供应商控制台的免费余额需要另行核实。

直连 DeepSeek 按最高适用单价预留人民币。收到用量回执后即可查看输入和输出 token，人民币流水保持待核对。主管凭厂家账单确认扣费时，系统一次性结算厂家和员工账本，并释放原预留。其价格随时段变化，维护预留单价时应查阅[官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

## 个人服务器启用

1. 使用固定提交构建后端和前端镜像，对已恢复 29 表的隔离库执行以下扩展。已有部署先留存旧镜像、配置和可用的 MySQL 备份。
2. 执行 `python3 script/shell/apply-provider-budget-schema.py --container <项目MySQL容器> --schema <目标库>`，随后用相同参数加 `--check` 读回。两个表分别执行原子 ALTER；中断后从同一固定提交重试即可。旧 token 行使用兼容默认值。
3. 在既有后端环境设置 `APP_MODEL_BUDGET_ENABLED=true` 和 `APP_PROVIDER_LIMITS_ENABLED=true`。按本机 Docker 发布入口更新现有服务，检查后端健康、普通登录、员工隔离和额度回执。
4. 发生发布故障时保全当前库和流水，优先修复当前服务。继续使用旧版本前须先暂停受管调用，否则旧版本无法执行员工分配规则。保留新增列以供后续恢复；不删除未结算预留。
