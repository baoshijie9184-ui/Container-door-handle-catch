# 历史文件入口权限与交付审计

日期：2026-10-22，UTC+8。分支：`java-cloud`。

本轮只新增和调整源码，未编译、测试、构建、迁移、启动服务或部署。覆盖旧本地文件入口，不替代 OSS 浏览器直传/读取记录，也不表示五类单体功能已经全部完成。

## 资源编号来自业务模块

旧 `/api/files` 与 `/api/direct` 入口继续保留，读取时先由资源所属模块建立授权映射，基础设施层不查询检测或模型业务表。检测与模型权限门面移到 `contracts/files`，Infra 新增 contracts 依赖，Detection 不再通过 Infra 自定义接口实现这一跨模块能力。

| 路由 | 业务映射与权限 | 交付审计域 |
| --- | --- | --- |
| `/api/files/images/{folder}/{fileName}` | 可访问任务的本地原图目录 | DETECTION_IMAGE |
| `/api/direct/images/{folder}/{fileName}` | 与原图入口相同 | DETECTION_IMAGE |
| `/api/files/annotated/{folder}/{fileName}` | 可访问任务的标注目录 | DETECTION_ANNOTATION |
| `/api/direct/annotated/{folder}/{fileName}` | 与标注入口相同 | DETECTION_ANNOTATION |
| `/api/files/results/{folder}/{fileName}` | 可访问任务登记的结果文件或结果目录 | DETECTION_RESULT |
| `/api/files/models/{fileName}` | 当前主管、唯一关联的模型登记及统一模型根目录 | DETECTION_MODEL_DOWNLOAD |

检测文件沿用员工本人及分派任务、主管企业业务的规则。账号先由 System 门面依据受信认证主体的稳定 ID 重新核对；任务读取是否切换到稳定 ID 授权，仍受原 V40 回填与激活门槛控制，本轮不自动激活。多个可访问任务同时映射同一请求位置时拒绝，避免随便挑一个任务记入审计。

模型文件现在需要唯一对应 `model_management` 中的实际模型 ID，单纯登录、猜到文件名或磁盘存在都不能下载。已删除登记、未登记、位置不一致或映射不唯一均拒绝。历史数据若只保存 URL 而没有可靠的本地位置，需要先核对登记；不根据 URL 尾部猜测所属模型。读取目录统一使用 `model.upload-dir`，不再把独立的 `file.upload.path.models` 当作另一个未登记文件出口。

授权门面返回实际任务/模型 ID、服务端文件引用及已有整数版本。当前历史任务和模型没有可用的统一整数修订版本，返回 null，页面显示未知；不把模型的语义版本或文件修改时间伪装成整数业务版本。文件引用是资源、文件类型和相对位置的 SHA-256 编号，不是文件内容摘要，也不证明文件自登记后没有变化。

## 写出前再次鉴权

`AuthorizedLocalFileResource` 承载服务端元数据，Controller 的交付注解读取 `result.body.id/fileId/version`，不把文件名当作业务资源 ID。每个 HTTP 别名各自声明注解；别名内部调用不会依赖 Spring 自调用拦截，也不会重复登记同一个响应。

准备 Resource 时核对目录包含关系、符号链接和真实路径，要求普通文件；打开输入流前再次调用所属模块授权，比较授权资源、文件引用和版本，并核对文件键、长度及修改时间。读取通道复用相同核对逻辑，不通过另一个不鉴权的通道打开文件。根目录变更、目录链接越界、账号撤权及资源映射变化均拒绝。

这是基于可信服务器目录和现有 Servlet 同步写出流程的保护，不声称长度/修改时间是内容哈希，也不声称能抵抗宿主机已被控制时所有路径替换竞争。文件已被打开后，不会因一次读取失败自动重试或重新下载。

标注目录列表先核对目录权限，再过滤每个文件的业务归属，排除符号链接及无法核对的文件；返回的 Unicode 路径按 URL 路径段编码。列表是目录元数据，不冒充一次文件正文交付。实际文件响应保留 `no-store`，增加 `nosniff` 与禁止执行内容的 CSP；HTML/SVG 不设置可执行的媒体类型。

实现复用项目已有 Spring Resource、Servlet 输出流及 AOP。参考 Spring 6.1.5 的 [ResourceHttpMessageConverter](https://github.com/spring-projects/spring-framework/blob/v6.1.5/spring-web/src/main/java/org/springframework/http/converter/ResourceHttpMessageConverter.java) 和 [消息转换处理器](https://github.com/spring-projects/spring-framework/blob/v6.1.5/spring-webmvc/src/main/java/org/springframework/web/servlet/mvc/method/annotation/AbstractMessageConverterMethodProcessor.java)，未复制其实现或引入新执行框架。

## HEAD、Range 和字节含义

复用默认关闭的 `OPERATIONS_FILE_DELIVERY_AUDIT_ENABLED`，依赖 V40/V52 与业务审计，不增加迁移。权限收紧始终生效，关闭审计不会恢复未登记模型文件读取。

- GET：沿用授权、写出、服务端完成、中断及未知状态。
- HEAD：新增 `HEAD_AUTHORIZED`、`HEAD_COMPLETED`；没有文件正文，不根据 GET 表示长度误判传输中断，也不登记文件流开始事件。结束回执丢失时仍保持未知。
- 206：记录当前响应的服务端写调用下界，可能包含多段响应边界；不是完整文件长度。
- 304 或原 Controller 返回失败响应：没有新文件正文交付，不伪造成功传输记录。
- OSS 重定向：继续仅记录外部读取授权，不假装观测浏览器与 OSS 的实际传输。

若响应异常后转为错误正文，写调用计数可能包含错误响应内容，因此它是响应表示的观测下界，不是文件净字节、公网计费量或客户端接收量。成功状态也不证明浏览器已经收到或保存文件。

原审计页面增加文件编号、请求关联编号、资源版本，以及 HEAD 状态提示；React 继续链接同一权限页面。刷新只读取审计，不重放文件请求。

## 旧的未登记上传入口

`POST /api/upload/model` 之前只写文件并返回 URL，绕过模型校验、登记事务和必要审计。源码中已停用该写入行为，主管请求返回 HTTP 410，提示使用原有 `POST /api/models/upload`，同时提交模型名、版本和文件；员工不获得该主管入口权限。本轮源代码搜索没有找到 Vue/React 对旧上传地址的调用，不代表真实环境的外部客户端已经迁移。

这个改动不删除历史文件，不补造模型登记或新确认，也不恢复 Skill ZIP 上传。现有受控模型上传和 V53 文件记录继续保留，见 [模型文件登记与保留](检测模型文件登记与保留.md)。
