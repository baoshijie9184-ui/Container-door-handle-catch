# 个人长期记忆治理

更新日期：2026-10-14。当前 `java` 分支，继续完善 Java 模块化单体。

## 已开发功能

主站“Agent智能系统 → 个人记忆”，地址 `/#/agent/memory`。聊天抽屉头部和独立 React 页面提供管理入口。员工、主管均只管理本人的长期记忆，主管企业业务权限不能查看或删除员工私人记忆。

页面支持分页查看本人记忆、分别设置“允许读取长期记忆”和“自动保存新的长期记忆”、编辑预览确认、确认删除，以及本人最近 50 条治理操作记录。每批默认读取 50 条，“读取更多”追加下一批，可继续读取超过 100 条的数据。编辑或删除完成后重新读取首批记录。

读取开关只控制模型参考中的长期记忆，保存开关控制后续自动提取；聊天历史继续保留。关闭读取不删除已保存记忆，关闭保存不停止读取旧记忆。删除长期记忆不删除原聊天记录；继续开启自动保存时，相同信息仍可能从后续对话重新提炼。

设置按稳定用户 ID 保存，两个聊天入口立即使用同一策略。未创建设置的账号默认沿用此前读取与保存开启的行为，本轮未静默清空记忆或改成全部默认关闭。更新设置带修订号，陈旧版本返回 409，设置变更与审计在同一个 MySQL 事务中保存。

`Mem0Client` 在每次检索和异步保存执行时重新读取设置，避免排队任务沿用旧开关。设置存储不可用时跳过记忆读取与写入，不恢复为默认开启。已进入模型上下文的记忆、已开始的 Mem0 保存和原聊天历史不能被开关撤回；设置对后续检查生效。

## 账号隔离与删除

浏览器接口不接受账号选择器，身份由 Spring Security 的 `TenantPrincipal` 取得。记忆列表只查询当前账号和 `doorhandlecatch` 应用，输出正文、时间、来源会话和版本摘要，不暴露原始 metadata 或其他账号的内容。服务不可用时返回 503，页面清除旧数据并显示错误，不将失败当作“没有记忆”。

删除过程：

1. 用户核对选中记忆的正文并明确确认；取消不发送删除请求。
2. Java 校验记忆编号、摘要、确认及请求键，先将本人删除请求记入 MySQL 审计。
3. Python 桥接层通过原生 `Memory.get` 再次核对 `user_id`、`agent_id` 和当前摘要，再调用 `Memory.delete`。
4. 记忆不属于本人或已不存在均返回 404，版本变化返回 409；成功记录 `SUCCEEDED`，同一成功请求重试不再次删除。

审计不保存记忆正文，只保存账号、动作、编号、版本摘要、设置及结果。预先审计失败时不调用远程删除。网络或结果记录异常不能与 Mem0 组成分布式事务：可能已经删除的请求保留 `UNKNOWN` 或 `DISPATCHED`，提示刷新核对，不伪称成功、不自动重放。失败/未决请求使用相同请求键返回 409；重新操作需刷新核对并再次明确确认。

未向 Agent Toolkit 注册删除或修改个人记忆的工具；模型不能通过新页面能力替代用户确认。删除只影响长期记忆，不改变 Skill、任务、质检或报告。

## 私有桥接认证

Java → Python 的 `/memories` 接口现在要求 `X-Doorhandle-Memory-Token`，配置来自本机忽略的 `.env` 的 `MEM0_BRIDGE_TOKEN`。密钥只用于内部请求，不进入浏览器、记忆正文、审计或健康返回值；未配置返回 503，缺失或错误认证返回 401。`/health` 仍提供无密钥的健康检查与认证配置布尔状态。

原无所属权的列表及删除路径已退役，认证后返回 410；Java 旧的字符串用户查询和无账号删除方法已移除。原保存、搜索客户端同时携带内部认证。启动入口沿用回环地址，直接运行两个 Python 入口也使用 `127.0.0.1`。

## 2026-10-14 编辑、分页与冲突核对

记忆卡片新增“编辑记忆”。弹窗同时显示原文与可编辑正文，输入范围为 1–4000 字，空白和未修改内容不能提交。用户先预览，再点击“确认保存”；取消和预览本身不产生写请求。新能力未注册为 Agent 工具，模型不能绕过页面确认修改私人记忆。

`GET /api/agent/memories/{id}` 读取本人当前版本；`POST /api/agent/memories/{id}/update` 接收原版本摘要、目标正文、请求键及确认标记。账号始终来自登录身份，主管不能通过参数指定其他账号。内部桥接重新校验账号、应用和摘要，再调用 Mem0 原生 `update(text=...)`，保留来源会话并更新向量。实际服务会使用已配置的 Embedding 供应商；自动测试使用隔离替身，不调用收费模型。

编辑与删除共用 V26 审计表，无新增 SQL 迁移。编辑请求的 `content_digest` 保存“原版本摘要 + 目标正文”的 SHA-256 指纹；审计同时核对动作与记忆编号。成功重放只返回已完成，不重复调用 Mem0；同一请求键更换正文、版本、记忆或操作类型返回 409。预先审计失败阻止远程写入，远程结果或完成审计失败不报成功，未决请求不自动重放。审计列表仅展示状态，不保存正文；Mem0 自身的原生历史库仍可能保存修改前后正文，需要作为私人数据一同保护。

409 冲突和 503 未决结果在弹窗中保留草稿并停止提交。用户必须主动“重新读取当前版本”，核对新原文与保留草稿，再预览确认；不会静默更新摘要后覆盖。若最新正文已与草稿一致，保存按钮保持禁用。账号切换或离开页面会清除临时私人状态，迟到的接口结果不回填到其他账号的页面。

列表新增 `offset` 和 `nextOffset`，单批范围仍为 1–100。当前 Mem0 2.0.19 的 `get_all` 无偏移参数，因此桥接使用现有 Chroma `collection.get` 的 `limit/offset`，同时限制 `user_id` 和 `agent_id`，不逐页全量拉取。返回内容再次检查所属范围并采用白名单，摘要与原生 `get` 保持一致。其他向量库需要单独实现分页适配，缺少能力时返回 503。分页不提供一致性快照；并发新增或删除可能改变位置，应刷新重新核对。分页加载失败保留已读列表，整页刷新失败则清除旧列表并展示错误。

本地桥接以单进程运行，人工编辑、删除与自动提炼使用同一进程锁；不将其声称为分布式比较并交换。迁移服务器保留 HTTP 边界和认证，先运行一个进程。多副本、跨进程写入及数据库级版本协调仍属后续任务，见 [Mem0 服务器迁移准备](Mem0服务器迁移准备.md)。

开源依据：复用 [Mem0](https://github.com/mem0ai/mem0) 和现有 Chroma。核对了本机 2.0.19 源码的 `get/update` 签名及存储适配，并复核 [Apache-2.0 许可证](https://github.com/mem0ai/mem0/blob/main/LICENSE)。未复制第三方源码到本仓库，也未升级本机 Mem0。原依赖仓库存在既有修改，后续迁移需保留这些差异，不能仅用版本号推断兼容性。
