# Agent 输入区与模型选择

2026-10-17，`java-cloud`。参考项目内 DeepSeek Harness（MIT）的 `QueueDock.tsx` 和 `ComposerAttachments.tsx`，在现有 Vue、React 和 AgentScope Java 上实现交互，未引入其执行运行时。按用户补充的 GPT 样式采用大圆角输入框、紧贴的消息队列、底部左侧加号/账号权限说明、右侧模型及会话上下文，以及发送/需确认的停止按钮；保留白色主调。任务操作折叠显示，保留暂停、引导、排队设置和历史导航。

- 空闲且没有待发消息时，隐藏整块队列控制区；历史交付回执不会让空队列重新出现。运行、暂停、等待审阅或回答、异常状态仍展示所需控制，不隐藏错误。
- 输入区加号打开原生文件选择器。上传到本人会话工作区，显示文件卡片，发送时携带服务端 `@file:编号`；取消附件只移除本次消息的引用，已上传文件仍在工作区。上限为每条消息 8 个附件、单文件 25 MiB，并受后端配额限制。HTML/SVG 不执行，不开放任意路径或脚本。
- 模型下拉框只提供服务器已配置的模型及“系统默认”。选择按账号与会话保存，使用预期版本、请求编号和事务审计；不接受供应商地址、凭据或任意模型标识。当前逻辑任务未结束时禁止修改；排队的新任务在开始执行时固定会话当时的选择，子任务及恢复沿用该选择，供应商备用策略仍生效。
- 选择并不改变全系统默认配置。实际使用及备用切换以模型请求轨迹为准；模型偏好保存在 AI 工作台既有 JSON 工作项中，不新增数据库迁移。

模型接口为 `GET/POST /api/agent/conversations/{sessionId}/model-selection`。POST 包含 `modelId`、`revision`、`requestId`，要求 `X-Agent-Action: workbench`，拒绝跨站请求，读写都核对当前账号及会话归属。

本轮同时修复两项实际验收问题：待审计划不再向模型展示专业委派、文件生成等执行工具，保留运行时权限校验；已分派且尚未复核的 `REVIEWING` 任务继续提供复核入口。没有通过隐藏报错或自动批准来跳过确认。

Mem0 的同步存储及模型调用改为 FastAPI 同步路由，由线程池执行，健康检查仍使用异步路由。单 ASGI 事件循环回归验证：提炼调用尚未结束时，本人列表和健康检查能够完成。存储写入继续串行保护；超时或结果不明确时不自动重试写入，不伪造记忆已保存。

验证：Java 定向 30 项（27 通过、3 可选 MySQL 跳过）、主站 Node 111 项、记忆相关 Python 15 项及两套前端构建通过；输入区浏览器 16 项通过，无 JavaScript 错误，复核桌面及手机截图。云端发布、真实账号及模型/记忆联调结果待发布后补充，不能用本地替身检查代替。
