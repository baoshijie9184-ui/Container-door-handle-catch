# 检测模型训练与评估字段

2026-10-25（UTC+8），`java-cloud`。训练时间按用户最新选择，只保留训练完成日期时间，不增加训练耗时。

| 页面字段 | API / 持久化 | 单位与含义 |
| --- | --- | --- |
| 模型名称 | `modelName` / `model_name`，沿用 | 实际登记名称，版本独立保留 |
| 训练图片数量 | `trainingImageCount` / `training_image_count` | 原始训练集张数，不重复计算增强，正整数 |
| 漏检率 | `noDetectionRate` 为只读派生值，保存 `evaluationImageCount` 与 `noDetectionImageCount` | 整图未检出数 / 成功评估图片数；Normal 检出也算检出，失败不计入分母 |
| mAP 值 | `mapScore` / `map_score`，沿用 | API 输入 0–1，页面显示百分比；mAP（AP）沿用原 AP 口径，不以 AP50/AP75 替代 |
| 训练完成日期 | `trainingCompletedAt` / `training_completed_at` | UTC+8 的实际训练完成日期时间；独立于上传/发布时间，不默认填当前时间 |
| 每秒检测图片速度 | `inferenceFps` / `inference_fps` | 实测张/秒，最多四位小数；不从平均延迟倒推 |

漏检率的计数须来自同一模型版本、数据集及阈值。例如 100 张输入、98 张成功，其中 3 张零目标、2 张执行失败，登记 98 和 3，显示 3.06%。它描述模型输出，不能证明真实目标漏检，也不从训练图片数或 AP 推算。

FPS 复用 `compatibilityNote` 保存测试环境说明，最多 500 字；登记 FPS 时必填，说明设备、CPU/GPU、框架、输入尺寸、批大小、样本范围、阈值及计时是否包含预处理/后处理。页面只登记已有实验结果，不启动训练、评测或测速。

## 页面、校验与兼容

- 模型列表展示名称、训练数量/完成时间、未检出率及计数、速度、mAP；宽列使用表格内部滚动和键盘阅读。
- 模型详情展示相同资料；资料缺失显示未记录，计数矛盾显示待核对，无成功评估图片时无法统计，合法零未检出显示 0.00%。
- 主管通过原“评估”操作打开“训练与评估资料”，复用 `/api/model-info/{modelId}/evaluation`、既有权限、审计和回执核对。模型名称沿用原编辑入口。未新增通用管理接口。
- 新字段留空/省略表示保留已有登记，不提供以空值清除的操作；旧客户端不发送新字段时不擦除已有事实。表单明确提示此语义。
- 图片数量必须是整数，拒绝 JSON 小数/字符串，避免静默截断；训练数须为正，评估计数非负、成对存在，未检出数不能超过成功数。FPS 大于零、在 DECIMAL(12,4) 范围内，并有环境说明。
- 两套 Agent 卡片共用 mAP、整图未检出率和实测 FPS，展开查看训练数量及完成时间；通过 `ModelAgentReadApi.Evaluation` 白名单传递，不向 Agent 交付服务器路径、操作者或兼容性自由正文。原六参数构造器保留源码兼容。
- 模型登记评估与业务任务结果独立；不自动将某个业务批次统计写回模型，不覆盖历史 `missDetectionRate`。

## V62 迁移与发布

`migration-V62-detection-model-facts.sql` 在 `sql/mysql` 与 Model 模块 classpath 各保存相同副本，只增加五个可空字段。模型名称和 mAP 复用原列，未检出率从计数派生，不保存另一份可能失配的比例；不猜测或回填历史训练、日期或性能资料。

发布前须核对前置模型表及 V6，备份数据库，检查新增列是否存在及其类型，执行 V62 后再启动新应用。新查询读取新增列，不能先升级应用再迁移。脚本按列存在性幂等，但不修正已存在的错误类型；迁移中断须核对并补齐缺失列。应用回滚保留新增字段和资料。真实 MySQL 升级、回滚、重新升级及缓存序列化兼容性仍待验证。
