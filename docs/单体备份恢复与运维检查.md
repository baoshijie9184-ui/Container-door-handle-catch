# 单体备份、恢复演练与运维检查

2026-10-18，`java-cloud`。复用现有 Docker、MySQL 8.4、Jenkins 和 Ubuntu systemd；备份工具仅使用 Python 标准库，不安装新的数据库、管理后台或外部备份平台。代码入口为 `script/docker/monolith-ops.py`。

## 发布前备份

Jenkins 的服务器部署助手在构建镜像和替换应用前调用备份，继承已核对 inode 的发布锁，避免嵌套抢锁或并发维护。备份未成功则终止发布；原服务的恢复健康检查也必须通过，才会创建 `COMPLETE` 回执。

为同时保存数据库和文件状态，工具先暂停 Nginx 入口，再停止当前运行的应用与中间件写入者，保留 MySQL 运行。这是当前单机演示的维护窗口，会短暂中断访问；没有改为多实例或零停机部署。停止、导出或校验任一步失败，均尝试按依赖顺序恢复原容器，只启动维护前已运行的容器，不重建中间件。

停止服务前先估算数据库导出及卷归档所需空间，并预留默认 2 GiB；导出子进程有输出文件大小限制，SQL 压缩期间持续核对余量，避免备份占满源盘。存在正在运行的 Compose one-off 任务时拒绝维护，避免停止后重放一次性操作；存在启用的 MySQL 定时事件时也拒绝，需先协调专门备份窗口。当前流程只支持每服务一个容器的单机单体。

快照位于发布根目录的 `backups/ops-北京时间-随机编号/`，包括：

- MySQL 逻辑导出，包含表、数据、存储程序、事件和触发器；记录各业务表准确行数与 `CHECKSUM TABLE ... EXTENDED` 结果。
- 当前项目已运行服务的非 MySQL 命名卷，例如上传、Agent 工作区、Mem0、Chroma、Kafka 和 Redis；卷在停止写入后归档。
- 私有 `cloud.env`、实际运行镜像摘要、外部绑定引用和 SHA-256 清单；快照目录权限 0700，文件权限 0600，不输出凭据正文。

MySQL 物理数据卷不重复复制。OSS 对象与只读绑定模型仍由原存储保留，清单明确记录其外部依赖；这不是 OSS、模型镜像或异地灾备的完整副本。源代码发布目录和镜像来源仍需保留。同盘快照能用于发布恢复，但不能应对整块系统盘丢失；外部副本应在另行确定私有存储及加密方式后配置。

备份中断时，`state/maintenance.json` 保留需要恢复的原容器编号、专业服务身份和镜像摘要。`recover` 只恢复身份未变化的原容器；已换镜像或容器编号时拒绝自动处理，保留待核对状态。它不重新执行 Agent、模型请求或业务写入。

## 命令

以下命令在 ECS 上执行，使用当前已发布代码中的工具路径。示例目录与现有部署一致；不要把未核对的本地环境覆盖服务器私有配置。

```bash
python3 script/docker/monolith-ops.py backup \
  --root /home/ecs-user/doorhandle-ci \
  --runtime /home/ecs-user/doorhandle-release-20261014

python3 script/docker/monolith-ops.py verify \
  --root /home/ecs-user/doorhandle-ci \
  --snapshot /home/ecs-user/doorhandle-ci/backups/ops-实际快照目录

python3 script/docker/monolith-ops.py restore-drill \
  --root /home/ecs-user/doorhandle-ci \
  --snapshot /home/ecs-user/doorhandle-ci/backups/ops-实际快照目录

python3 script/docker/monolith-ops.py recover \
  --root /home/ecs-user/doorhandle-ci

python3 script/docker/monolith-ops.py check \
  --root /home/ecs-user/doorhandle-ci \
  --runtime /home/ecs-user/doorhandle-release-20261014
```

恢复演练创建随机命名的独立 MySQL 容器，数据库放在临时内存文件系统，不开放端口、没有生产网络或生产卷挂载。恢复数据库后比较所有业务表行数及表校验值；文件恢复到新建演练卷，逐项比较目录、链接和文件 SHA-256。演练结束仅清理带有本次随机所有权标记的演练资源，报告保存到 `state/restore-drill-编号.json`。

表校验值受 MySQL 版本及行存储格式影响，因此演练使用原 MySQL 镜像摘要；校验差异应核对数据与行格式，不能直接解释为业务数据已损坏。归档 SHA-256 是独立的文件完整性检查。若旧后端镜像已按保留策略清理，演练可用 `--helper-image sha256:当前受信后端摘要` 指定具有 tar/Python 的本地辅助镜像；它只执行文件工具，不启动该镜像的应用。

该命令提供隔离恢复演练，不提供对生产库的覆盖入口。生产数据恢复仍需先核对目标、维护状态、版本和快照；不能把演练成功直接当作已恢复生产。

## 监测、镜像保留与凭证

`check` 在 `state/operations-health.json` 保存 UTC+8 检查时间、可用磁盘、使用比例、备份年龄和完成回执摘要、私有配置权限及必要凭据是否配置。默认磁盘使用达到 85%、可用空间不足 2 GiB、无有效备份或备份超过 48 小时，均返回异常状态。周期检查只校验完成回执与清单摘要，不逐次重新读取整个备份内容；完整性检查使用 `verify`。

凭据检查只返回配置状态：数据库账号密码匹配、JWT 和桥接密钥基本长度、Redis 密码以及模型密钥是否存在。不返回值、前后缀、文件正文或供应商错误；配置存在不证明密钥有效或供应商可连接。本轮不实现浏览器密钥输入或云 KMS，也不自动替换现有密钥。

凭据轮换继续使用现有服务器私有环境文件和 Jenkins 文件凭据：先在供应商生成新密钥，在服务器维护窗口修改 `cloud.env`，保持 0600，再通过配置该密钥的服务重新部署并验证实际选定供应商，避免备用成功掩盖新密钥失败。DashScope 同时用于 Mem0 时还需受控重建 Mem0 容器，当前流水线已将版本化 Mem0 私有桥接纳入同一次发布，启动健康后才替换后端，并在失败时一起回滚。确认新密钥生效后再撤销旧密钥；历史备份含旧配置，必须继续按私有文件保护。SSH 私钥与 known_hosts 继续由 Jenkins 文件凭据传入，不放入仓库或命令正文。

应用发布成功后自动保留 backend/web/mem0 各最近 3 个 CI 镜像，并额外保护所有运行或已停止容器引用的镜像、已记录回滚摘要及运行时固定摘要。只删除符合本项目不可变 CI 标签的旧应用镜像，不删除数据库镜像、命名卷、备份、模型或业务文件。

默认只查看清理计划，加 `--apply` 才执行；流水线在应用健康检查通过后执行受限清理，清理失败不把健康应用标为回滚：

```bash
python3 script/docker/monolith-ops.py prune \
  --root /home/ecs-user/doorhandle-ci \
  --runtime /home/ecs-user/doorhandle-release-20261014 --keep 3
```

## 定时单元

工具先生成并使用 `systemd-analyze verify` 检查五个单元，`--apply` 才安装到系统目录。遇到不属于本项目的同名单元会拒绝覆盖。服务使用运行目录所有者身份及原 Docker 组，私有写入权限为 0077。

```bash
sudo python3 script/docker/monolith-ops.py install-timers \
  --root /home/ecs-user/doorhandle-ci \
  --runtime /home/ecs-user/doorhandle-release-20261014 --apply
```

备份默认北京时间 23:30；设置 `Persistent=false`，实例关闭期间漏掉的备份不会在开机后补跑。磁盘/备份/凭据检查在开机两分钟后及每 15 分钟执行，异常体现在 systemd 失败状态及日志，不擅自向邮件、Slack 或其他渠道发消息。开机恢复单元和备份的 `ExecStopPost` 会核对中断维护记录。并发发布或维护占锁时返回 75，按“本次跳过”处理，不误报备份成功。

这组单元只维护已运行主机上的 Docker 容器，不启动 ECS，也不修改既有阿里云 00:00 节省停机任务。
