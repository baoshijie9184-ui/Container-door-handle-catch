# 聊天可选接口兼容与版本核对

2026-10-25（UTC+8），`java-cloud`，本地 `14ef8377` 加未提交改动。只读复核 ECS `182.92.133.162`，没有改容器、环境变量、数据库或服务状态。

## 实际原因

先前把聊天中的“核对状态暂不可读取”归为会话控制异常，这次定位修正：

- 会话控制能力和快照接口返回 HTTP 200。检查的 12 个本人会话，其状态、版本及消息枚举符合现有契约；没有发送消息或命令。
- 报错来自 `DetectionCreationReview`，它访问 `/api/agent/conversations/{session}/detection-creations`。服务器返回 HTTP 200、业务 `code=404`，旧前端没有识别该错误包装，而按无效数组显示通用故障。
- 只读 `docker ps` 确认服务器 web/backend 使用 `ci-22-54e59613408f` 镜像，当前本地源码尚未统一发布。模型配置和业务审计也返回业务 404，需要在最终版本升级时核对，不在前端伪造成功。
- 本次记忆 preferences 接口返回正常结构，不能沿用旧记录声称所有记忆接口都不可用；其他记忆操作没有因此得到验收。

## 实现

1. 现有 `/api/agent/workbench/capabilities` 增加 `detectionCreationReviews`，按工作台开关及 `DetectionCreationApi` 是否装配返回。只声明服务装配，不代表数据库、OSS、执行器或业务链路健康；实际读取和写入仍重新鉴权。
2. Vue/React 核对组件先读能力。明确关闭时不查询核对列表；旧后端没有新字段时继续兼容读取原接口。能力读取/会话切换使用原中断与代次保护，旧请求不能覆盖新上下文。
3. 共用 `transferPayload` 处理原始 DTO 与 `Result` 包装；HTTP 200 不再被当作业务成功。正常回执仍须通过原字段、版本和命令编号校验。
4. 404 不作为空列表成功，也不擅自判断为关闭功能。界面显示可展开提示“接口未提供或当前会话不可访问”，要求核对后端版本和账号范围；空资料时不再用常驻大块通用红色告警挤占聊天空间。
5. 401/403/404 清除旧核对资料；服务故障可保留旧快照，但标记只读且不可确认。新发起的未知结果保留请求编号，不自动重做原操作。未读回有效状态前不能确认完成或终止。
6. 任何已有未核对请求编号仍在界面保留；不会因为功能未启用提示而伪装为操作完成。原业务确认、请求编号、版本校验、费用说明和写操作重新鉴权保持。

本修复没有新增迁移，不增加通用工具或执行框架，也没有部署后端。当前整个分支的迁移、密钥/运行器兼容、候选验收和统一发布要求仍保留。

## 验证与限制

采用已授权的现有 Vite 预览及只读浏览器：

| 场景 | 两套入口观察 |
| --- | --- |
| 能力明确关闭 | 折叠说明，无核对列表请求 |
| HTTP 200 / 业务 404 | 明确不可用提示，不显示空历史成功 |
| HTTP 200 / 业务 403 | 清除资料、显示无权读取 |
| HTTP 503 | 保留错误提示，未启用业务操作 |
| Result 包装的正常回执 | 正常显示核对记录；`canFinalize=false` 时完成按钮禁用 |
| 先正常读取，再刷新得到 403 | 已读记录清空，操作按钮消失，不重发写请求 |

六种场景选择了 12 张实际可见截图，React 的核对区域在右侧工作面板内，复核时已展开面板。浏览器没有未处理页面异常或整页横向溢出；只点击读取/展开，不执行 CHECK、FINALIZE、ABANDON，也未发送模型请求。

真实服务器补拍两套入口的桌面及手机面板，原通用告警消失，保留明确的接口不可用说明。**这只验证前端兼容与只读展示，不证明服务器缺失接口已实现或业务核对完成。**
