# 固定 Fetch MCP 安装取消与队列回收

更新：2026-10-16，`java-cloud`。本次完善 P09 中固定 Fetch 的安装生命周期，沿用现有 AgentScope Java、V25 注册表及账号文件目录。

后续更新：已完成的安装可以先停用，再确认 [移除安装登记](MCP安装登记移除.md)；文件保留。下文为取消安装阶段的验证记录。

## 页面操作

在“Agent 智能系统 → MCP 工具”中，排队或执行中的安装显示“取消本次安装”。确认框说明撤销安装登记、尽力中断后台执行、保留已有文件；选择“继续等待”不发送取消请求。打开确认框时暂停自动刷新，确认使用打开时的安装编号及版本。

取消成功后显示“已取消安装”，工具保持未启用。页面保留重新安装入口，必须重新确认固定版本、来源及 MIT 许可证，使用新的安装编号。已完成的安装不能再取消，需使用现有停用操作。

取消结果不明确时显示核对提示，不自动重发写请求；允许只读刷新获取实际状态。离开页面关闭尚未提交的取消确认，避免离开后误发取消。旧接口没有返回安装编号时，页面不提供取消入口。

## 接口和一致性

`POST /api/agent/mcp/fetch/install/cancel`，需要登录及 `X-MCP-Action: update`，响应沿用 `Cache-Control: no-store`。

```json
{
  "operationId": "00000000-0000-0000-0000-000000000001",
  "expectedRevision": 1,
  "confirmed": true
}
```

服务端重新读取当前账号身份，仅锁定本人的 Fetch 注册行。安装编号须与当前登记一致，版本须匹配，状态须为 `INSTALLING`；其他账号、主管身份均不能取消别人的安装。

同一事务完成 `CANCELLED`、禁用、清空租约、版本递增和 `CANCEL_INSTALL / SUCCEEDED` 审计。审计只记安装编号、版本和 `registrationRevoked/filesRetained` 等元数据。事务失败回滚，不发送后台中断。相同安装编号已经取消时重复请求返回当前状态，不重复写审计；新安装产生新编号后，旧取消请求被拒绝。

事务提交后才取消本进程保存的 `FutureTask`，发送线程中断，并移除等待队列里的任务以回收队列位置。安装工作开始前、进入原生安装及启动本地命令前检查中断；已有本地子进程等待流程收到中断后尝试清理该进程及其后代。

撤销与安装完成争用同一注册行锁：取消先提交时，迟到的成功或失败不能覆盖 `CANCELLED`，也不能覆盖后续新安装；完成先提交时，取消返回 409。提交安装登记与加入本地执行器之间，也会复查登记，避免已经撤销的任务继续排队。

## 执行和存储边界

取消成功代表注册和授权已撤销，后台中断是尽力执行。忽略中断的 Java 调用、操作系统或远端网关任务可能继续运行到自身超时。网关模式同样撤销本人的安装登记，但不保证远端容器在响应取消接口前已经退出。已有工具调用取消与运行器回收规则继续适用。

取消不会删除安装目录、下载包、日志、版本清单或审计，不释放磁盘空间，也不卸载其他已登记的工具。部分下载保留在原安装编号目录；重新安装使用新目录。

本轮没有增加持久任务队列。多实例共享数据库撤销结果，但只向接收取消请求的进程内任务发送中断；其他实例无法登记迟到结果，物理执行仍可能持续到超时。进程重启后的队列恢复、通用卸载/升级、孤立目录清理、真实 MySQL 并发及云端网关取消验收仍在 P09。

## 发布和开源依据

沿用 V25 的字符串状态列和既有审计表，无新增迁移、依赖或环境开关。需要发布匹配的后端和前端；仅更新源码不会改变当前 ECS。回退到旧版本后，旧页面可能无法识别 `CANCELLED` 并提供重新安装入口，应恢复支持该状态的版本后操作，保留原有数据及审计。

实现前核对了官方 [Fetch 源码及说明](https://github.com/modelcontextprotocol/servers/tree/main/src/fetch)：固定包版本沿用 `2026.10.10`、MIT，未替换 SDK 或复制新依赖。取消语义参考 [JDK 17 FutureTask](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/FutureTask.html)：线程中断是取消尝试，不保证底层计算立即终止。
