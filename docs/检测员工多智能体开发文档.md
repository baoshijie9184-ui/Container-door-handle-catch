# 检测部门普通员工多智能体开发方案

## 1. 目标与范围

本阶段只面向“检测部门普通员工”设计智能体。普通员工可以查询本人有权限的检测任务、查看检测结果、分析缺陷、生成草稿报告和提交复核，但不能管理用户/角色、修改模型、发布最终质量结论或访问其他部门的敏感数据。

实现基于 AgentScope Java 2.0.1、Spring Boot 模块化单体和 AG-UI。Agent 代码归属 `doorhandle-module-ai`，检测业务数据通过 `doorhandle-module-detection` 暴露的 API/Facade 获取，禁止 AI 模块直接访问检测模块 Mapper 或数据库实体。

## 2. 总体架构

```text
Spark Design React UI
        │ AG-UI /agui/run
        ▼
AgentScope Gateway（会话、鉴权、限流、审计）
        │
        ▼
员工助手 Orchestrator
   ┌────┼────────┬─────────┐
   ▼    ▼        ▼         ▼
检测分析  图像解释  报告草稿  知识检索
 Agent    Agent    Agent     Agent
        │ Tool/Facade（权限校验后调用）
        ▼
检测任务、设备、模型、文件、知识库模块
```

编排器负责理解意图、选择专用 Agent、合并结果和向用户回复；专用 Agent 只处理明确领域问题。所有工具调用都经过统一的 `EmployeeToolPolicy`，即使模型产生了越权参数，也必须在工具层拒绝。

## 3. 专用智能体清单

### 3.1 员工助手 Orchestrator（`employee-assistant`）

- 入口 Agent，负责意图识别、任务拆解、调用专用 Agent 和最终答复。
- 默认只读；涉及提交、导出、标记等写操作时必须请求用户确认。
- 不直接查询数据库，不直接拼接 SQL。
- 对外只暴露一个稳定的 Agent ID，便于未来拆成独立服务。

### 3.2 检测任务分析 Agent（`inspection-analysis`）

- 查询任务状态、批次、检测数量、失败原因和进度。
- 对异常率、缺陷类型分布、置信度区间做统计解释。
- 输出数据来源、时间范围、样本数量和计算口径，禁止编造指标。

### 3.3 图像/缺陷解释 Agent（`defect-vision`）

- 根据已保存的检测结果和标注图解释缺陷位置、类别、置信度。
- 只引用系统已有的图片 URL/对象存储签名 URL，不把本地绝对路径暴露给模型或前端。
- 不负责训练、修改或发布模型；低置信度结果必须标记为“需人工复核”。

### 3.4 报告草稿 Agent（`inspection-report-draft`）

- 根据检测任务、缺陷统计和员工补充说明生成报告草稿、整改建议和复核清单。
- 草稿必须带 `draft=true`、数据时间和来源任务 ID。
- 只能保存草稿到当前员工可见的会话/任务空间，最终报告发布由主管流程完成。

### 3.5 检测知识 Agent（`inspection-knowledge`）

- 检索检测标准、作业指导书、缺陷字典和系统操作手册。
- 使用 RAG 返回引用片段、文档版本和更新时间。
- 知识库无匹配时明确回答“未找到依据”，不得用模型常识替代企业标准。

### 3.6 安全与路由 Agent（`employee-safety-router`）

- 在编排器前后执行敏感信息过滤、提示词注入检测、工具权限检查和输出脱敏。
- 拦截用户要求查看他人账号、跨部门数据、API Key、内部路径、模型配置等请求。
- 记录拒绝原因和策略版本，供审计和后续优化。

## 4. 工具列表与权限

工具命名采用 `<domain>.<resource>.<action>`，参数使用 DTO，不传递 Entity。每个工具都必须接收当前 `RuntimeContext(userId, sessionId, tenantId, roleCodes)`，禁止由模型自行提供用户身份。

### 4.1 普通员工允许工具

| 工具 | 类型 | 说明 | 权限 |
| --- | --- | --- | --- |
| `detection.task.list` | 读 | 查询本人/本部门授权任务列表 | 允许，强制数据范围 |
| `detection.task.detail` | 读 | 查看任务、批次、状态和设备信息 | 允许，强制数据范围 |
| `detection.result.summary` | 读 | 获取缺陷数量、比例、置信度统计 | 允许 |
| `detection.result.items` | 读 | 分页查看单张图片的检测结果 | 允许 |
| `detection.image.signed-url` | 读 | 获取短时有效的图片访问地址 | 允许，默认 5 分钟 |
| `detection.device.status` | 读 | 查看授权设备的在线/运行状态 | 允许 |
| `model.catalog.list` | 读 | 查看可用模型名称和版本 | 允许，只读 |
| `knowledge.search` | 读 | 检索检测标准和操作手册 | 允许，返回引用 |
| `report.draft.generate` | 计算 | 生成报告草稿 | 允许，必须标记草稿 |
| `report.draft.save` | 写 | 保存个人草稿 | 允许，仅限本人会话/任务 |
| `detection.review.submit` | 写 | 提交人工复核申请 | 允许，幂等 |

### 4.2 明确禁止或需主管权限的工具

`system.user.*`、`system.role.*`、`model.upload`、`model.publish`、`model.delete`、`detection.task.delete`、`report.publish`、`report.quality-signoff`、跨部门数据导出、修改检测阈值、修改设备配置均不向普通员工注册。未来为主管增加独立 Agent 和独立工具白名单，不在员工 Agent 中通过提示词“隐藏”实现权限控制。

## 5. Skills 设计

Skills 是可版本化的业务知识与操作约束，放在 AI 模块资源目录，不等同于 Java 工具。建议目录：

```text
doorhandle-module-ai/src/main/resources/skills/
├─ employee/base/SKILL.md                 # 员工通用边界、输出格式、安全要求
├─ inspection/task-analysis/SKILL.md      # 任务查询和统计口径
├─ inspection/defect-interpretation/SKILL.md
├─ inspection/report-draft/SKILL.md
├─ inspection/knowledge-rag/SKILL.md
└─ safety/prompt-injection/SKILL.md
```

每个 Skill 至少包含 `name`、`version`、适用角色、触发条件、允许工具、输入/输出 JSON Schema、禁止事项、示例和变更记录。Skill 版本随提示词和知识规则一起审计；会话中记录实际使用的 Skill 版本，避免同一报告无法复现。

推荐输出统一为：

```json
{
  "answer": "面向员工的自然语言说明",
  "facts": [{"source": "detection.result.summary", "taskId": "...", "value": "..."}],
  "warnings": ["低置信度结果需人工复核"],
  "nextActions": [{"tool": "detection.review.submit", "requiresConfirmation": true}],
  "skillVersions": ["inspection/task-analysis@1.0.0"]
}
```

## 6. 用户、会话与数据隔离

### 6.1 身份来源

- 用户身份只来自 Spring Security 已认证的 `Authentication` 和当前用户上下文。
- 将 `userId`、`tenantId`、`departmentId`、`roleCodes` 写入 AgentScope `RuntimeContext`。
- 普通员工角色建议权限码：`detection:task:query`、`detection:result:query`、`detection:review:submit`、`report:draft:write`、`knowledge:search`。
- 工具层再次调用现有 RBAC/数据权限服务，不能只相信 Agent 入口鉴权。

### 6.2 会话键与存储

会话主键使用不可猜测的 `sessionId`，Redis/数据库键必须包含租户和用户：

```text
agent:session:{tenantId}:{userId}:{sessionId}
agent:message:{tenantId}:{userId}:{sessionId}:{messageId}
agent:run:{tenantId}:{userId}:{sessionId}:{runId}
agent:audit:{tenantId}:{userId}:{sessionId}:{runId}
```

查询会话时必须同时匹配 `tenantId + userId + sessionId`；禁止仅凭前端传入的 sessionId 读取历史。会话标题、消息、草稿、工具结果默认只对创建者可见，主管审批通过后才产生可共享资源。

### 6.3 并发、重放与生命周期

- 同一 `sessionId` 同时只允许一个 active run；重复请求使用 `runId` 幂等处理。
- AG-UI 断线时中断 run，工具调用设置超时和取消信号。
- 消息保留期建议 30 天，审计记录按合规要求单独保留；删除会话要级联清理向量索引和临时文件。
- 附件使用对象存储签名 URL，下载和预览都校验用户数据范围。

## 7. AgentScope Java 2.0.1 落地方式

建议在 `doorhandle-module-ai` 中分层：

```text
com.ruanzhu.doorhandle.module.ai
├─ agent/          # Agent 定义、编排和生命周期
├─ tool/           # Tool 实现与 EmployeeToolPolicy
├─ skill/          # Skill 加载、版本和匹配
├─ context/        # RuntimeContext、会话和租户上下文
├─ guard/          # 输入输出安全、限流、超时
├─ api/            # 对外门面和未来远程契约
└─ config/         # agentscope.ai、agentscope.agui 配置
```

使用 AgentScope 2.0.1 的 `HarnessAgent` 和 AG-UI Spring Boot Starter 注册 Agent Bean。建议固定 Bean/Agent ID：`employee-assistant`，专用 Agent 作为内部子 Agent；自定义模型、工具和 workspace 均从配置注入。`server` 只引入 AI 模块，不实现 Agent 业务逻辑。

## 8. 典型请求流程

1. Spark Design 前端携带登录态调用 `POST /agui/run`，提交 `threadId/runId/messages`。
2. AG-UI 入口解析当前登录用户，生成不可伪造的 `RuntimeContext`。
3. 安全路由 Agent 扫描输入并加载 `employee/base` Skill。
4. Orchestrator 判断意图，例如“分析任务 20260801 的缺陷分布”。
5. 检测分析 Agent 调用 `detection.task.detail` 和 `detection.result.summary`。
6. Tool Policy 校验员工角色、部门范围、任务归属和参数，记录审计事件。
7. Orchestrator 汇总事实、引用和风险提示，通过 AG-UI 流式返回。
8. 发生写操作时先返回确认卡片；用户确认后再用同一 `runId` 的受控后续请求执行。

## 9. 可观测性与审计

每次 run 至少记录：`traceId、tenantId、userId、sessionId、runId、agentId、skillVersions、toolName、resourceIds、policyDecision、latency、tokenUsage、errorCode`。日志中不得记录 API Key、完整图片内容、身份证明或未脱敏的提示词机密。

指标建议包括：Agent 成功率、工具拒绝率、平均响应时间、超时率、低置信度占比、人工复核转化率和 Token 消耗。接入 OpenTelemetry/Langfuse 时只发送脱敏后的 trace 和元数据。

## 10. 分阶段开发计划

### 第一阶段：可用闭环

- 完成 `employee-assistant`、`inspection-analysis`、`inspection-knowledge`。
- 实现 6 个只读工具和统一 `EmployeeToolPolicy`。
- 接入会话键隔离、AG-UI 流式响应、审计日志和基础限流。

### 第二阶段：检测复核辅助

- 加入 `defect-vision`、`report-draft`。
- 支持图片签名 URL、草稿保存、人工复核提交和幂等控制。
- 增加低置信度提醒、敏感信息过滤和工具级集成测试。

### 第三阶段：平台能力

- 接入 Redis 会话持久化、向量知识库、OpenTelemetry/Langfuse。
- 增加主管 Agent，但使用独立角色、Skill 和工具白名单。
- 将 `api` 和事件契约稳定后，再按负载把 AI、知识检索或检测分析拆成微服务。

## 11. 验收标准

- 普通员工无法通过修改 `sessionId`、`taskId` 或提示词读取他人/其他部门数据。
- 所有写工具都有显式权限、二次确认、幂等键和审计记录。
- Agent 回复中的关键数字均可追溯到工具事实；无数据时明确说明。
- 无 API Key 时项目可以启动；启用 AgentScope 只需配置环境变量。
- `doorhandle-module-ai` 不依赖检测模块的 Mapper/Entity，未来可替换为 HTTP/gRPC 客户端。
