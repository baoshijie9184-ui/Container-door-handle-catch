# ECS 单体运行说明

本页用于查看已部署的 ECS 单体。实验室 Ubuntu 开发见[配置方案](配置方案.md)；Ubuntu 沙箱不使用 ECS 的运行目录、凭据或数据卷。

## 访问系统

先通过授权渠道核对当前公网地址和既有 SSH 主机公钥。采用 TLS 传输时同时核对原证书，参见 [SSH 连接说明](../../script/jenkins/README.md#当前网络-ssh-连接修复)。更新私有 SSH 配置后，在 Windows 仓库根目录执行并保持终端运行：

```powershell
ssh -F work/cloud/ssh-config -N -L 127.0.0.1:18088:127.0.0.1:8088 doorhandle-bj
```

- 主站：<http://127.0.0.1:18088/#/login>
- 独立 Agent：<http://127.0.0.1:18088/agent-ui/>

该命令只转发远端网页，不在 Windows 启动业务。实际版本以发布回执为准；本机 Jenkins 地址不是业务登录地址。

## 开机与收尾

ECS 使用时按北京时间 09:00 至 24:00 保持开机。由用户决定启停，不因一次测试结束关机；助手和流水线不创建或执行定时启停。若还有旧 OOS 定时任务，先由维护者核对实际状态和执行窗口，不把历史调度记录当作现行规则。本页不表示已查询、修改或取消任何云端任务。

## 服务检查

连接已确认的 ECS，执行只读检查：

```bash
docker ps -a --filter label=com.docker.compose.project=doorhandlecatch-monolith \
  --format 'table {{.Names}}\t{{.Status}}'
curl -fsS http://127.0.0.1:8088/nginx-health
cat /home/ecs-user/doorhandle-ci/state/current-directory
```

从运行清单、健康状态和发布记录判断当前环境，不用源码推断生产已经升级。当前源码的完整栈为后端、Nginx、MySQL、Redis、Kafka、Mem0、Qdrant、Detection Worker；AI 网关按需叠加。旧部署可能仍有 Chroma，不能按新清单删除旧服务或数据卷。初始化容器成功退出不等于故障。

单项排障用 `docker logs --tail 100 <容器名>`；不要因为查看状态而重做初始化、启停业务容器或覆盖私有配置。公网地址变化后，若影响固定 Fetch 的出口限制，再按[网关部署说明](../../deploy/mcp/README.md)核对私有配置。

## 更新与恢复

现行 ECS 入口是 [Jenkinsfile.ecs-monolith](../../Jenkinsfile.ecs-monolith)，测试与发布按[统一验收和发布](README.md#ecs-统一验收与发布)执行。SCM 轮询可触发验证，不等于自动生产发布；先确认固定提交、触发规则和门禁。需要切表、恢复或更换运行镜像时，先按相应协议保全数据和证据，不手工运行旧目录中的 JAR。
