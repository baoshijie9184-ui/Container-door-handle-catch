# 稳定身份授权与显式操作关联

日期：2026-10-22，UTC+8。分支：`java-cloud`。

本轮新增和调整源码，未编译、测试、构建、执行迁移或部署，没有启动 ECS 或切换生产授权模式。本文记录稳定身份实现的续开发，不是整个身份迁移已经完成的证明。

同日继续新增目标账号 ID/角色/资料摘要确认、V55 不可变批次与逐条回执、共享锁、预览修订冲突及只读核对页面；不再自动选中同名候选，原账号失效时保留待核对。独立开关默认关闭，源码未运行，详见 [历史回填确认](历史账号回填确认与批次回执.md)。已有映射的全面来源证明与最终迁移仍未完成。

## 认证 ID 与名称快照

新增 contracts 中的 `BusinessPrincipal`，由服务器认证主体 `TenantPrincipal` 实现，提供已有账号 ID 与名称。检测授权策略从认证主体读取稳定 ID，调用账号所属模块重新核对账号及当前角色，不再先拿认证用户名、再查一个可能属于后来同名账号的 ID。

HTTP 请求与后台 Agent 使用不同的受信输入：前者读取认证主体，后者使用服务端已有的 `AgentActor(userId, username, role)` 并重新核对当前账号。调用方提供的角色标志不是业务授权依据。旧 `canAccess(task, username, supervisor)` 签名保留为受限兼容方法，只能对应当前 HTTP 账号，不接受它凭名称构造其他账号身份；生产文件和报告调用点已改用明确的身份重载。

任务列表、JDBC 统计与仪表盘范围、旧本地文件、OSS 预览和报告任务权限复用该策略。ID 模式的 MyBatis 查询使用绑定参数；不再通过名称查 ID 后拼接到子查询。报告后台读取使用传入的稳定 Actor，不需要伪造 HTTP 登录上下文。

## 授权模式的边界

仍保留原 `DETECTION_STABLE_IDENTITY_ENABLED`、V40 预览和主管确认激活流程。本轮不自动启用新模式。模式尚未激活时，任务范围仍沿用原创建人/责任人名称规则；不能宣称这一阶段已经消除了历史同名账号的全部归属风险。完成必要历史映射、候选验证和统一发布前，不应把新授权模式直接打开。

ID 模式中，创建人和责任人必须同时满足稳定 ID、记录的身份名称快照与现有业务名称逐字节一致。旧版本若只改变任务人员名称、没有更新身份关联，该行不会因为大小写、重音或空格折叠而继续通过授权，保留为待核对；当前账号改名后重新登录，不要求历史显示快照改成新名称。

SQL 使用 `CAST(... AS BINARY)` 作精确比较，保持 null 不匹配；激活检查同样拒绝名称快照缺失或不一致。参考 [MySQL 8.4 官方转换与比较说明](https://dev.mysql.com/doc/refman/8.4/en/cast-functions.html)，未使用已弃用的独立 `BINARY` 运算符。

## 新业务操作显式保存 ID

| 操作 | 身份来源 |
| --- | --- |
| 创建上传任务、旧单图/批量检测任务 | 插入任务后，读取当前受信账号的 ID，核对任务创建人快照并登记 |
| Agent 确认创建 | 使用已重新鉴权的原 Actor ID，不依赖后台线程的用户名或伪造认证 |
| 新的质检分派 | 主管明确执行分派后，对当前选定员工账号做精确唯一匹配、角色检查，保存责任人 ID 与快照 |
| 人工复核、处置、返工 | 使用当前实际执行人的受信账号 ID，与刚写入的操作人名称核对后保存 |

这些关联方法要求调用者已有业务事务（`MANDATORY`），不在事务之外悄悄补写身份。新任务与角色关联同事务，已接入的必要业务审计继续沿用原事务；必要步骤失败不能只提交业务记录。旧直接检测入口的完整业务审计覆盖仍需核对。原创建人 ID 已有关联且不一致时拒绝覆盖。

这里的新分派是对本次明确选择的当前账号建立关联，不是把历史任务按同名重新认领。后续同日已新增 v2 固定责任人、V54 独立分派操作人/身份版本及表单选择器代码，尚未验证或启用，见 [分派固定账号与操作人](质检分派固定账号与操作人.md)。

## 历史记录不顺便自动回填

原通用 `sync(task)` 会在进度、完成事件或普通业务更新时按名字查 ID。现在不再如此：未映射的非空历史身份保持原状，等待主管在预览页确认；已有非空关联不因当前同名账号存在而重建。通用同步只清理业务字段已明确清空的非创建人关联，并以数据库实际字段为准，避免把 ORM 忽略的 null 当作已经清空。

回填页面继续提供精确同名候选及手动用户 ID，补充展示原关联 ID 和原身份快照，并增加说明：候选并不证明历史归属。用户须确认映射；不会按姓名、部门或新一轮检测完成事件自动分配旧数据。原用户名、冻结报告和历史审计正文不改写。
