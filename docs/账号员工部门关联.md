# 单体账号、员工与部门关联

更新：2026-10-13，实施分支 `java`。这是现有 Spring Boot 单体中的组织身份基础，不拆分微服务。

## 已实现

`users.id → account_employee_binding.employee_id → employee.department_id → organization_department.id`。

账号角色继续由 `users.role` 和 Spring Security 决定。员工岗位类型、部门和账号角色分别维护，关联员工不会授予主管角色，也不会扩大员工任务读取范围。员工仍读取本人创建或当前分派任务，主管读取当前企业业务数据，私人聊天、记忆、运行与确认仍按账号隔离。

新增页面 **产线资源 → 账号与组织**，地址 `/#/organization`。员工查看自己的账号、员工编号、姓名、当前状态、部门与数据范围；主管可以搜索账号、关联或更换员工、解除关联、查看最近 50 次关联变更、创建部门。员工不能列出账号、修改关联或读取其他账号的关联审计。人员表单从部门主数据选择，服务端使用规范部门名称覆盖客户端提供的文本。

一名员工只关联一个账号，数据库唯一约束防止并发重复绑定。只允许关联在岗且已设置部门的员工；绑定后的员工休假或离职，身份接口实时反映当前状态，资料仍可查看和编辑。已关联员工禁止删除，必须先解除关联。员工资料接口原先将休假、离职员工的详情也拒绝返回，本次修正为允许读取资料；分配设备仍按原服务规则拒绝非在岗员工。

员工详情、按类型和按设备查员工直接读取数据库，避免旧无类型 Redis JSON 缓存命中后把员工对象还原为 Map 导致重复读取报错，也避免身份资料复用旧部门或状态。员工统计仍沿用原缓存；本次未更换全局 Redis 序列化配置。

保存关联必须携带读取到的 `bindingVersion`。账号行锁处理首次绑定与后续修改；员工行锁与外键防止删除竞态。解除关联后保留版本行，旧页面不能覆盖后续新关联。相同版本重复保存相同关联不新增审计。关联变更和审计在同一事务提交，审计失败则回滚关联。

## 模块与接口

系统模块维护账号、关联、部门、审计；设备模块维护员工。通过 contracts 的 `EmployeeDirectoryApi`、`OrganizationDirectoryApi` 调用，不引用其他模块实体或 Mapper。部门当前支持列表与创建，名称及 ID 创建后保持稳定，暂不提供改名、删除、停用或树形结构。

| 接口 | 权限与行为 |
| --- | --- |
| `GET /api/organization/me` | 当前登录账号的身份，无可指定其他账号的参数 |
| `GET /api/auth/check` | 增加当前账号 `identity` 字段，原认证字段保留 |
| `GET /api/organization/departments` | 登录用户读取部门选择项 |
| `POST /api/organization/departments` | 主管创建唯一部门名称 |
| `GET /api/organization/accounts` | 主管分页搜索，最多每页 100 项，响应不含密码、手机、邮箱和 Token |
| `PUT /api/organization/accounts/{userId}/employee` | 主管提交 `{employeeId, version}`；`employeeId: null` 解除关联 |
| `GET /api/organization/accounts/{userId}/audit` | 主管读取最近 50 次关联变更 |

组织写请求要求 `X-Organization-Action: update` 和 JSON 请求体，服务端 CORS 沿用现有允许来源配置。缺少标记返回 400，越权返回 403，不存在返回 404，版本、重复绑定或约束冲突返回 409。业务服务再次检查当前数据库角色，不能仅靠前端按钮隐藏或旧登录角色授权。

登录后前端重新请求认证状态，刷新角色和员工身份；退出清理内存角色、身份及本地显示缓存，避免同一浏览器切换账号仍沿用上一个账号角色。

## 数据库与本地启动

在已有业务 schema 和员工版本迁移基础上执行 [V20](../sql/mysql/migration-V20-account-employee-department.sql)，classpath 副本位于 App 模块 `src/main/resources/db`。新增三张表及员工部门 ID、外键；按已有员工部门文本建立部门并回填 ID，不猜测账号对应员工，不改变历史任务归属、账号密码和角色。回填保留员工原更新时间。空部门的员工保持待完善状态，主管编辑后才能关联。

本机已执行迁移并重复执行验证幂等。其他本机开发库可运行：

```powershell
& 'D:/ruanjian/anaconda3/envs/leetcode/python.exe' script/shell/migrate-local-organization.py --apply
```

脚本只允许 `.env` 中的本机 `doorhandledb`，不打印凭证；省略 `--apply` 只检查迁移状态。统一启动脚本的 MySQL 就绪检查会核对组织表与部门列，缺少迁移不报告全部就绪。数据库迁移不在业务 seed 中自动执行。

部署前先备份并检查目标库。此迁移包含 MySQL DDL，不能把整个脚本当作可回滚事务；可重复执行恢复中断。应用回退应保留新增表与列，不自动删除组织身份或审计数据。四个现有演示账号不会根据姓名、手机号或账号名自动匹配已有员工，主管在页面明确关联即可。
