# 长期记忆提炼回执与超时治理

适用：`java-cloud` Java 单体及 Mem0 私有桥接。时间使用 UTC+8。本轮为代码与本地验证，尚未发布云端；七项整体任务继续保持未完成。

## 请求与回执

1. 对话已保存后，Java 使用本人账号、会话及助手消息编号生成稳定的 SHA-256 请求编号。相同轮次的时间戳变化不会生成新的保存任务；内容变化仍须通过指纹检查。
2. 自动提炼先写入现有 V26 `agent_memory_audit`，动作 `AUTOSAVE`、状态 `DISPATCHED`，只保存编号和摘要，不保存正文。审计失败不派发 HTTP；相同未决请求不会再派发。
3. Python 在既有 Mem0 持久卷的 `bridge_receipts/write-receipts.sqlite3` 中先提交请求指纹与运行状态，再调用 Mem0。回执只保存状态、时间、结果编号和事件，不存会话正文、记忆正文、凭据或异常原文。目录权限 0700，数据库文件 0600，适用于 Linux；Windows 测试不代表已验证 POSIX 权限。
4. SDK 返回后逐项读取实际记忆，核对账号、应用、正文及增删事件；观察到 Mem0 主日志的警告/错误或无法核实的结果，保留 `NEEDS_REVIEW`。这也覆盖原生 SDK 内部捕获提炼错误后返回空数组的情况。
5. 已成功的相同请求读取原回执；处理中或待核对的相同请求只返回现状。编号被用于不同内容时拒绝。旧 Java 客户端未提供编号时，桥接按账号、应用、会话及内容生成兼容指纹，新 Java 客户端使用明确的轮次编号。

`SUCCEEDED` 表示已报告的结果通过本轮存储核对，不代表记忆语义正确、没有遗漏或原生 SDK 的所有内部历史都已独立审计。空结果不计作新增记忆。当前 Mem0 日志观察器在单写期间保守处理主日志的警告；并发读取产生的同名日志也可能令该写入保持待核对，不把这种保守判定称为已确认失败。

## 超时与并发

- Mem0 初始化后，在现有 OpenAI 协议客户端上设置 `timeout=15` 秒及 `max_retries=0`，保留原供应商、API 地址、模型和凭据。该限制针对单次网络请求，不能当作整个 Mem0 管线的硬截止；SDK 内部可能有多阶段请求和嵌入回退。
- HTTP 首次最多等待 3 秒；仍未完成返回 202。Java 不把 202 当作保存成功，聊天回复不等待整个提炼完成。
- 运行超过默认 120 秒后，查询将其显示为待核对，**不声称工作线程已被取消**。实际工作未退出时继续占用唯一写入槽；不同请求立即拒绝，并明确操作未开始。相同请求仍能读取回执，健康与本人读取不排在写入锁后等待。
- 回执提交失败时不执行 SDK；完成回执无法可靠保存时，拒绝新的自动提炼，原结果保持未知。修复持久存储并重启后，原运行标记待核对，不自动重放。
- 存储目录持有操作系统文件锁，防止同一目录上同时启动两个写入实例。重启只有取得真实文件锁后才将遗留 `RUNNING` 改为 `NEEDS_REVIEW`，不依据 PID 文件判断进程是否死亡。不同服务器或不同数据卷不构成分布式协调；当前仍按单桥接进程运行。
- 人工编辑/删除沿用原确认与 MySQL 审计，并与自动提炼共用写入槽。读取不取得写入槽。关闭保存开关只阻止后续尚未开始的保存，不撤销正在执行的操作。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `MEM0_PROVIDER_TIMEOUT_SECONDS` | 15 | 单次供应商网络超时，范围 0.1–120 秒 |
| `MEM0_WRITE_RESPONSE_SECONDS` | 3 | 首次 HTTP 等待，范围 0.01–4 秒 |
| `MEM0_WRITE_REVIEW_SECONDS` | 120 | 转入待核对的运行期限，范围 1–1800 秒，不是强杀期限 |

内存、CPU 或第三方库内部无法让出的长操作尚无独立进程硬隔离；不能用这些超时设置证明任意故障下的进程内硬时限。

## 本人核对

个人记忆页的“本人最近操作记录”显示自动提炼状态。处理中或未知记录可点击“核对提炼结果”，也支持键盘触发；只查询原请求，不重新提炼。成功后展示核对条数；处理中或结果未知时 affectedMemories 返回 null，无法取到可靠回执时仍提示待核对，不把未知结果记为零。

浏览器调用 `POST /api/agent/memories/operations/{requestId}/verify`，带 `X-Agent-Action: memory-verify`。账号来自登录身份，先核对本人 MySQL 审计，再经私有认证访问 Python `POST /memories/operations/get`。响应只返回编号、状态、条数和更新时间；不向浏览器交付 SDK 状态、文件路径或内部令牌。已完成回执可将 MySQL `DISPATCHED/UNKNOWN` 收敛为 `SUCCEEDED`，不覆盖另一操作的记录。

编辑、删除、设置仍是原独立流程；没有向 Agent 注册记忆修改、删除或回执重放工具。元数据限制为来源、时间戳和轮次编号，不允许经元数据覆盖账号、应用或会话身份。

## 发布与回滚

Jenkins 的最终统一发布会构建后端、网页及版本化 Mem0 桥接，先等待 Mem0 健康，再替换后端与网页；失败回滚同时恢复原 Mem0/后端/网页镜像。数据库、Chroma 与 PTH worker 镜像继续固定，数据卷保留。发布前的一致性备份包含新回执子目录。镜像保留扩大为 backend/web/mem0 各最近三份 CI 镜像，并继续保护容器及回滚记录引用。

不需要新建业务表，复用 V26 审计；桥接 SQLite 只新增独立文件，不迁移或删除既有向量和原生历史。旧应用回滚后可忽略新增回执文件，不能删除它后以相同编号重新执行未知操作。Docker 上下文及 Git 已排除本机回执目录，许可证和既有 SDK 版本保留。
