已移除 `anthropics/skill-creator` 硬编码 GitHub 映射。此次公开详情中的源码地址与旧映射不同，原生归档因此不再被当作旧 GitHub 包的别名。

源码下载在账号私有隔离目录中进行，不进入 SDK 自动技能发现路径。仍需规则 Eval、本人提交和另一名主管独立审核。脚本、HTML 和附件仅存档，既不执行市场安装命令，也不执行下载包脚本。

只允许固定公开站点和严格链接形式；逐跳校验重定向站点、HTTPS 与公网地址。认证未配置、来源无法访问、目录不唯一、许可缺失/不符及字节变化会明确失败。跨市场升级以实际 Git 仓库和目录核对；原生市场没有可证明的 Git 对应关系时作为新技能安装。旧版本、独立审核、差异比较和回退流程继续保留。

默认仍为 64 MiB 账号下载存储配额。单文件最多 1 MiB、技能文件最多 96 份、正文资源总计最多 4 MiB；原始归档、元数据和清单计入每次 5 MiB 的完整存储上限。过大或不适用的包明确拒绝，不通过删减许可或静默丢文件满足上限。

## 持久配额、租约与清理

V46 新增账号锁、下载租约和转换审计三张 AI 表，根目录与 classpath 副本同步。原有下载及技能记录不改写。

发起下载时在数据库账号锁下同时保存请求与配额预留，每个账号最多两个未结束/待核对下载。多进程不再依赖 `synchronized` 判断配额。正在写入的目录按完整 5 MiB 上限计费式占位，其已写字节不再重复加一次完整预留；已结束包和孤立文件继续按实际占用计入。

领取执行先持久化实例归属和五分钟租约，启动后记录 PID 及进程开始时间。正常退出、文件核验、创建私人草稿和释放预留在同一导入事务中完成；角色、技能修订号及来源仍重新核对。旧执行的迟到结果不得覆盖新状态。

尚未领取的过期排队任务可明确失败并释放预留，因为数据库状态证明尚未执行。已领取任务过期、重启后没有可信退出回执，或终止不能确认时进入 `NEEDS_REVIEW`：保留目录和配额，不自动下载、不导入、不清理。旧下载缺少租约和进程回执时同样保守处理。当前还没有面向用户的跨重启进程核对处置入口；不能把已记录 PID 当作已证明退出。

清理先核对归属、当前状态、所有技能版本引用和未结束租约，持久化清理意图，再由数据库账号锁串行执行有界文件删除。相同请求跨进程恢复时复核清理命令，不同时删除同一包；提交后连接异常不能把已完成回执改写为失败。历史版本引用的包拒绝删除，失败或中断仍保存清理回执，不声称已经回滚物理删除。

配额预留、领取、进程登记、完成、退出核对及过期转换与必要审计同事务；审计失败不继续推进状态。浏览器只接收账号自己的来源和结果，不返回进程参数、服务器路径或凭证。
