## 2. 实际接口与开关核对

| 入口 | 已核对的实际契约 | 前端对应实现 |
| --- | --- | --- |
| `GET /api/auth/check` | `Result.data` 包含 `authenticated/userId/username/role/identity/accountContext/capabilities`；稳定账号来自服务端，顶层 `userId` 使用十进制字符串 | `stores/user.js`、`utils/accountContext.js`、独立 Agent `AccountBoundary.jsx`，不从本地显示缓存恢复认证 |
| 登录、刷新、退出 | HttpOnly Cookie；启用会话时绑定独立 `sid`，刷新和退出校验当前上下文；刷新令牌不能用于业务请求 | 两入口不保存前端可读令牌；退出先清页面，撤销未确认时不声称服务端已经退出 |
| 所有受保护 unsafe 方法 | 会话功能开启时，JWT 过滤器对 `GET/HEAD/OPTIONS` 以外的方法要求 `X-Account-Context`；不局限于 `/api`，同时覆盖 AGUI、工具和 MCP 路径。登录/刷新/退出另按认证服务规则处理 | Axios 和 `accountFetch` 统一携带服务器确认的上下文，缺失时阻止业务写入 |
| 旧模式的上下文 | 会话关闭时服务器仍返回稳定 legacy 上下文；对已提供的旧上下文执行比较，兼容未提供新请求头的旧客户端；这不等于具有服务端 `sid` 撤销能力 | 新两入口仍发送上下文；无安全上下文仅允许读取，不伪造本地上下文 |
| 上下文冲突 | HTTP 409，顶层 JSON `code: ACCOUNT_CONTEXT_CHANGED` | 与普通版本 409 分开处理：旧连接、页面、请求生命周期和私人内存缓存失效；重新确认身份 |
| `GET /api/operations/audit/changes` | 直接返回 `{items,nextCursor}`；参数为 `domain/resourceType/resourceId/actorUserId/actorRole/action/occurredFrom/occurredTo/before/size` | `ResourceChangeHistory.vue` 支持上述筛选；北京时间输入转换为带时区的查询值；历史游标不用于可靠事件补发 |
| `GET /api/operations/audit/changes/{id}` | 路径使用列表的 `id`；详情另含 `eventId/changes/diffAvailable`，每次按当前资源及字段权限判断 | 列表与详情分开读；旧历史不补造字段、角色或姓名；字段缺失、NULL、空字符串、布尔值和保护字段分别呈现 |
| `POST /api/operations/audit/changes/latest` | 请求为最多100项 `{domain,resourceType,resourceId}`；当前授权后按资源批量查询最新已提交 V2 记录，拒绝越权资源且不补造旧历史 | 只发送当前页编号，账号或读取代次变化即清除旧摘要；并发版本取业务行，摘要版本不同则分别展示 |
| 版本化业务写入 | `expectedVersion` 或 `X-Expected-Version`/`If-Match`，结合 `X-Request-ID`；回执头为 `X-Resource-Version/X-Audit-ID/X-Change-Event-ID` | 员工/设备用 `version`，检测任务用独立 `task.version`，模型用 `rowVersion`；模型的 `version=v1` 等业务文本不用于并发判断 |
| `POST /api/detection/tasks/{id}/claim` | `{expectedVersion,requestId}`；仅当前已有访问范围内无人负责、检测完成且 `PENDING_REVIEW` 的任务，服务端确定领取账号；不是全企业任务池 | 主检测页与质检队列提供本人领取，检测人员不获得主管分派入口；按钮要求 `capabilities.mutations=true` |
| `GET/POST /api/accounts/{userId}/access` | 仅主管；响应版本名是 `accountVersion`；写入 `{enabled,role,expectedVersion,requestId}`；新响应账号及版本输出字符串 | `AccountAccessEditor.vue` 兼容 `accountVersion`，保留读取时版本；仅会话和协同写能力同时开启时允许修改 |
| `GET /api/realtime/changes` | 同源 Cookie 原生 EventSource；命名事件 `resource-changed/heartbeat/resync-required`，载荷含 `schemaVersion:1/accountContext` | 同账号、同登录上下文通过 Web Locks 与 BroadcastChannel 共享一条流；缺少仲裁能力时分配零条 SSE，改用定期核对 |
| SSE 资源事件 | 仅定位元数据：事件/审计编号、域、资源、版本、动作、请求号、时间；无字段差异或业务正文 | 按事件去重、按资源版本拒绝倒退，跳版本或未知版本触发重读；不把通知当保存回执 |
| SSE 权限变化和漏通知 | 企业变化先给合法会话发送不含资源标识的 `BUSINESS_CHANGED` 重同步；实际资源事件发送前重新鉴权；拥塞使用 `NOTIFICATIONS_DROPPED` | 通用重同步也会核对已打开任务的 `/trace`；403/404 关闭并清除无权详情、草稿及本地任务，普通更新保留草稿和原版本 |

实际类型/域对应为 `DETECTION_TASK/DETECTION`、`QUALITY_REPORT/QUALITY_REPORT`、`DEVICE/DEVICE`、`EMPLOYEE/EMPLOYEE`、`DEVICE_USAGE/DEVICE_USAGE`、`DEVICE_ALERT/DEVICE_ALERT`、`DETECTION_MODEL/DETECTION_MODEL`、`DEPARTMENT/ORGANIZATION`、`ACCOUNT_BINDING/ORGANIZATION`、`ACCOUNT/ORGANIZATION`；账号权限修改的动作名为 `ACCOUNT_ACCESS`。已有专项配额申请、技能和模型配置仍沿各自既有命令及审计契约，不据通用通知实现推断其每项事件均已完成真实联调。

开关及依赖以服务端 `CollaborationFeatureDependencies` 与 `/auth/check.capabilities` 为准：

| 开关 | 作用和依赖 | 关闭时的边界 |
| --- | --- | --- |
| `operations.audit.enabled` | 基础审计；协同写和新修改历史依赖它 | 不能启用依赖它的新功能后无审计执行 |
| `collaboration.sessions.enabled` | 独立登录会话、服务端撤销和上下文强制栅栏 | 保留 legacy 身份兼容，不宣称独立会话撤销有效 |
| `collaboration.mutations.enabled` | 版本、摘要、幂等回执及新领取入口；启动时要求基础审计 | 不能据开关关闭的旧写兼容路径声称新并发能力已经验收 |
| `collaboration.change-history.enabled` | 新修改历史；启动时要求基础审计 | 既有基础审计与手动刷新继续承担原有能力 |
| `collaboration.realtime.enabled` | 要求会话、新修改历史及基础审计；不满足依赖则启动失败 | 客户端停止建流，使用可见页面定期核对，不循环重试不存在的接口 |

这些开关表示应用能力，**不表示生产发布、迁移或旧库演练已经获准**。现有 `DOORHANDLE_COMPACT_RELEASE_READY` / `DOORHANDLE_COMPACT_REHEARSAL_READY` 门禁继续独立生效。

## 3. 异步账号隔离和持久缓存专项

仅在发送请求时读取“当前账号”不足以保护旧闭包。已明确覆盖以下入口：

| 入口 | 起始身份及跨 await 保护 |
| --- | --- |
| Axios 调用 | 默认入口在调用时同步捕获 stamp，避免等 Axios 拦截器排队时绑定到新账号；现有直接调用 Axios 的 Vue 组件在 setup 使用 `captureAccountRequest()` 绑定完整组件生命周期 |
| Vue MCP、技能确认 | `AgentMcp.vue`、`AgentSkills.vue`、报告及其他直接写入组件统一使用组件生命周期绑定的 Axios；即使旧确认框迟到返回，也不能作为新账号开始 unsafe 请求 |
| 共享 AGUI 工作台、对话控制、附件和执行记录客户端 | 默认传输使用 `accountFetch.capture()`，创建时绑定原账号 epoch；文件读取和 hash 等 await 后的第一次 POST 也不能改用新账号。工作台上传另校验原会话代次 |
| Vue 聊天 ready/流回调 | `ChatAssistantDrawer.vue` 在等待控制器就绪前捕获身份，之后再次检查；`streamChatMessage` 每个事件分派前检查，旧流的catch不回填新账号；store身份重置同时停止旧轮询和执行关联缓存；语音录制作用域包含账号epoch/context |
| 独立 React 会话和执行 | `main.jsx` 的会话列表后新建、会话新建及等待 `ready()` 后执行，绑定起始传输并再次检查；`DynamicResults.jsx` 在解析动作回执后、发起后续问题前再次检查 |
| 批量上传和断点续传 | `uploadStore.js` 在入口捕获上下文与 epoch；创建、上传池、迟到 catch、缓存提交和后续 `mark-uploaded` 均属于原操作。账号改变后不继续排队上传，不写入新账号缓存，也不改变新上传状态 |
| 单图多步骤检测 | `singleImageKafkaDetection.js` 的创建、OSS PUT、确认上传和轮询使用同一捕获身份，阶段转换前再次检查；不把旧图提交给新账号 |
| 上传及检测版本 | 创建或续传步骤返回的 `X-Resource-Version` 优先，其次 DTO 版本；后续 `uploaded/mark-uploaded` 固定该步骤版本；旧任务启动和续传固定所选任务版本，不临提交读取最新版本替换旧意图 |
| 任务及文件持久缓存 | 只操作 `doorhandle:<编码accountContext>:taskList` 和该上下文的 `task_files_*`。退出/切换清理明确旧上下文，保留其他上下文及其他应用的键；文件写入、删除与延迟任务缓存提交还校验原 stamp |

账号重置时的缓存清理在 Vue 和独立 React 启动入口注册，任务 store 尚未实例化时也执行。只清理可确定归属的旧上下文，不扫描删除所有浏览器数据。页面显示提示、可读账号偏好和既有私人草稿存储不承担认证职责。

本轮源码核对已经修复 `AccountAccessEditor` 误读 `version`、旧上传步骤遗漏 expectedVersion，以及上述跨 await 后首次 unsafe 请求绑定过晚的具体入口。它们的修复有生产构建与专项测试源码，尚无真实跨账号浏览器运行证据。后续新增 unsafe 调用必须在操作起始捕获身份，不能仅凭统一请求头推断所有未来闭包安全。

## 6. 最终验收必须补齐的回执

通过现有 `Jenkinsfile.ecs-monolith` 与 `doorhandle-local-ci`，从已提交推送的固定源码执行。测试选取与最低数量由 [compact-acceptance.json](../script/jenkins/compact-acceptance.json) 管理，不能只运行构建或默认跳过MySQL专项后记录“全部通过”。

每次真实验收至少保留：最终提交、Jenkins构建号、执行身份与环境、功能开关组合、未跳过测试报告、并发HTTP结果、业务/身份/版本/审计/命令回执读回、真实浏览器多用户记录、SSE命名事件/协议/恢复记录，以及约束升级与恢复证据。20用户×2标签和提交到页面更新P95≤2秒仍是设计目标，本轮没有测得该结论。

聊天流解析、记忆请求等既有纯协议用例使用显式注入的传输模拟；账号上下文安全由 FE 专项加载实际 accountFetch 模块核对。两类用例的目的和证据不可互换。

本地生产构建日志只证明源码可打包。源码与测试登记完成、能力开关可设置、Jenkins控制器可连接，均不等于ECS验收完成或生产已经升级。
