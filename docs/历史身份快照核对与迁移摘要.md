# 历史身份快照核对与迁移摘要

更新：2026-10-22 UTC+8，分支 `java-cloud`。本轮仅新增/调整源码和阅读文件，未测试、编译、构建、运行核对程序、执行 SQL、连接 ECS 或发布。

## 用途和观察范围

新增 V57 身份核对报告，供历史回填和旧版本运行后重新升级时查看关联差异。它读取任务的创建人、责任人、复核人、处置人、返工人，结合当前账号安全快照及 V56 当前来源记录，保存计数、资料摘要和差异明细。

报告不判断具体哪一个旧版本造成了变化，不修复任务、不分派账号、不激活授权，也不是后续操作的审批材料。激活和业务变更继续按当前状态重新鉴权、校验版本与必要来源。

| 差异 | 含义 |
| --- | --- |
| `MISSING_NAME` | 必要的历史名称为空 |
| `UNMAPPED` / `INVALID_ID` | 非空人员记录没有稳定 ID，或 ID 无效 |
| `SNAPSHOT_MISMATCH` | 业务显示名称与已保存身份名称快照不同 |
| `ACCOUNT_UNAVAILABLE` | 原 ID 对应账号已不存在或不具备支持的业务身份 |
| `STALE_BINDING` | 人员字段已空，仍残留 ID 或身份快照 |
| `SOURCE_UNVERIFIED` / `SOURCE_INVALID` | 缺少可核对来源，或来源结构/关联不完整 |
| `SOURCE_MISMATCH` | 来源仍指向别的 ID/名称，或字段恢复后仍引用失效观察 |

账号当前改名不直接等于原任务归属错误。核对使用稳定 ID 与历史名称快照，并保留账号当时的安全资料；不把当前名称与历史显示不同直接判为越权。一个职责位置可以有多个原因，所以原因计数之和可能大于差异关联数量。

## 一致快照与原子保存

生成操作在独立、最长 30 秒的 MySQL `REPEATABLE_READ` 事务中运行。当前单体共享数据源与事务管理器，任务、来源及账号门面读取使用该事务快照。服务重新锁定主管身份和 V40 控制版本，分页读取每次最多 100 个任务、批量读取来源，并以一页为单位写入差异。

统计覆盖配置范围内的全部任务，每个任务固定检查五个职责位置，包括空位置；空的非必要职责且没有残留关联时不算差异。遍历数量必须与同一快照的任务总量一致，否则整批回滚，不保存部分报告。

报告、差异明细和必要业务审计同事务提交。页面超时或网络结果不明时，只按原请求编号核对；未查到记录也可能仍在处理中。相同编号和范围复用原结果，不再次扫描；同号异范围、异操作人或陈旧预览版本拒绝。新观察需要用户明确发起独立请求，不自动重跑。

报告以 UTC+8 保存观察开始和完成时间、控制修订及来源模式。时间范围用于追溯这次观察，不声称资料一直保持不变。报告只记录自身算法协议，不伪造实际镜像、提交或生产验收编号；最终验收仍须由流水线绑定对应版本。

## 摘要和前次比较

SHA-256 资料摘要逐条覆盖任务/职责、原 ID 和名称快照、账号安全快照、当前来源和差异原因。编码固定字段顺序并使用长度前缀，不包含请求编号或观察时间，便于相同协议下比较资料是否变化。摘要不是外部签名或不可篡改存证。

与最近一次相同协议报告比较时，保存新增、变化、相同的差异关联，以及“上次差异本次未再观察到”的数量。后者可能来自修复、任务删除等，不能标成已经修复。资料变化也可能来自账号资料更新，不能据此推断由旧程序写入。比较数量与两份差异总数不一致时拒绝保存。

报告读取时再次核对明细数量。摘要损坏、未知差异代码或不完整明细返回待核对错误，不把缺失部分当成零。

## 页面、权限与操作入口

主站“任务账号关联”新增“历史身份核对摘要”：生成、只读查询、已保存列表、摘要对照及游标差异明细。差异行的“重新预览此任务”只传递任务编号，服务端重新读取当前资料，页面不从旧报告填入目标或恢复确认。

任务预览支持精确编号定位。历史名称缺失及空人员字段残留关联也能被显示；无法确认归属的空名称保持只读，不能按当前同名账号猜测。该类记录的受控补正仍需继续开发。

地址只保留核对请求编号和任务定位编号，刷新后只查询报告，不保存私人正文、不重新生成或改写任务。所有报告、明细和账号查询重新核对主管权限；企业身份元数据不对员工开放，也不包含私人聊天、记忆、凭证或服务器路径。

复用 `/api/detection/identity`，新增 `POST/GET /reconciliations`、`GET /reconciliations/{request}` 和 `GET /reconciliations/{request}/items`。生成请求携带编号、预览修订及来源范围；不存在的结果只返回当前未记录，不是重做业务操作的授权。

## 配置、配额和兼容

`DETECTION_IDENTITY_RECONCILIATION_ENABLED=false` 默认关闭，依赖 V40/V55/V56/V57、稳定身份、回填确认、来源服务及必要审计。默认每份最多 20,000 个任务，最多保存 20 份报告；超出时明确拒绝生成，不声称完成部分覆盖，也不自动删除历史。当前源码限制配置任务数最高 20,000、报告数最高 100，需更大规模时另行设计运行和归档方式。

V57 根目录与 Detection classpath 由同一迁移文本维护，只增加报告与差异表，不执行回填。发布保护在启用该功能时检查前置配置和必要列；完整类型/约束/索引签名核对仍待完成。

报告属于附加元数据，没有增加新的身份授权格式下限。回滚保留报告及明细；早于此功能的应用可能暂不提供报告入口，升级后再读取，不清空数据或降低既有来源保护。
