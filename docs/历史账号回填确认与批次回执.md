后续 V61 已补入缺失名称的逐条资料确认、v3 回执及明确撤销源码，原 v2 请求摘要和回执继续保留；新能力默认关闭，未运行。见 [缺失历史名称确认](缺失历史名称的受控账号确认.md)。

## 选择与确认

旧回填只检查目标用户 ID 存在，预览也不固定目标账号资料。新增 `BusinessAccountLookupApi.Account`，只返回 ID、账号名、业务角色及资料摘要；不读取或返回密码、邮箱和电话。摘要沿用现有责任人快照的长度前缀算法，包含账号创建和更新时间，但不是单调版本号。

“任务账号关联”页面不再自动填入同名候选。主管可明确选择候选，或搜索现有账号名、用户 ID；为选中记录选择核对依据，确认历史归属，再查看包含任务、职责、原名称、目标账号、ID 和依据的确认清单。没有依据、没有账号快照或未勾选历史归属确认时，不允许提交。

同名只是候选，不证明任务属于当前账号。原关联 ID、历史名称、当前账号资料及名称重用风险分别显示。原账号删除或失去业务角色时，即使 ID 与历史名称仍对齐，也进入待核对列表。可勾选“同时核对已有 ID 关联”查看原有映射；普通新预览不会宣称这些映射已经证明历史归属。

## 事务与重复请求

客户端携带 `identity-map-v2` 对应的映射内容、请求编号、预览修订号、目标账号资料摘要和历史确认标志。旧五字段映射请求仍可反序列化，但不能绕过新确认要求继续写入。

确认事务按受信 ID 重新核对主管并持有账号共享锁，锁定控制版本，再按 ID 顺序锁定目标账号，按任务编号锁定源记录。任何账号资料、角色、原名称、任务快照或控制修订变化都拒绝提交。所有目标直接使用已确认的 ID，不在提交阶段按名字重新选人。

V55 保存批次与不可变逐条映射：原 ID/身份快照、源摘要、目标 ID/账号/角色/摘要、核对依据、主管、修订和结果数量。任务更新、批次、逐条记录、必要业务审计和原 V40 命令回执同事务提交；任一步失败全部回滚。业务名称、冻结报告和既有审计正文不改写。

批次成功后推进控制修订。同一编号和相同规范内容返回原批次结果，不再次写入；同号不同内容或不同操作人拒绝。摘要固定 Map 字段顺序，避免跨进程重启时依赖 JVM 的无序 Map 排列。

## 未知结果

提交发生网络错误或结果无法确认时，页面保留原编号及原内容，冻结继续编辑，并提供只读回执查询。未查到已提交回执仅表示当前没有可见记录，不能证明原请求终止；不会自动再次提交。

用户可以在未查到回执后明确确认重试同一编号、同一版本、同一内容。服务端先核对原回执并串行去重，不生成新批次；不接受把未知请求改成另一批映射。页面刷新不会自动发送写请求；当前尚未持久化浏览器中的未提交表单或未知请求草稿，刷新后的完整回执导航仍需继续完善。

## 接入与开关

复用 `/api/detection/identity/preview`、`apply` 和 `activate`，新增同一路径下的主管只读 `accounts` 与 `commands/{request}`。账号和回执响应不缓存，员工无权读取；它们属于企业业务映射资料，不包含私人聊天或记忆正文。

`DETECTION_IDENTITY_REVIEW_ENABLED=false` 默认关闭。启用需稳定身份服务、必要业务审计、V40 和 V55。开关关闭时仍能读取旧预览，但拒绝新回填写入和授权激活；不能使用缺少新快照的旧写入路径作为回退。V55 根目录和 Detection classpath 各保存一份相同迁移文本，不执行回填、账号创建或模式切换。

后端镜像新增 `io.doorhandle.identity-review=1` 声明。发布门禁增加回填协议下限，检查 V55 元数据及已有批次，并考虑已启用写入者；已经产生新回执后不能回到不声明读取能力的镜像或关闭回执读取接口。原三维 pin 按新增 review 维度 0 读取，新 pin 保留四维下限。该声明不是验收成绩。
