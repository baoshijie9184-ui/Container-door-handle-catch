# 记忆有效期与停用清理

2026-10-18，UTC+8；`java-cloud` 模块化单体。代码及本地验证完成，未发布 ECS。七项系统完善任务仍未全部完成。

## 用户操作

个人记忆页每条记录增加“有效期与停用”。先重新读取本人当前正文及版本，选择正常使用或停用，设置北京时间有效期；留空表示长期保留。预览本次设置后明确确认，才写入控制记录。到期自动删除默认不勾选，旧记忆没有新默认期限，不自动清空或改写正文。

停用或到期的条目停止用于后续检索，但仍可在个人记忆页查看、编辑、延长有效期或恢复。编辑正文不会自动取消停用，也不会续期；需要重新核对控制设置。已送入上下文的内容及原聊天记录不能由本功能撤回。

勾选“到期后自动删除这条记忆”须同时设置未来有效期并再次确认。清理调用原生 Mem0 删除检索记忆，并核对实际不存在；不是销毁聊天、Mem0 原生历史库或备份。完整数据销毁需要独立的保留与删除策略，不能把本功能当作全量擦除。

“有效期与清理记录”展示本人最近 50 条控制记录和清理结果。未知结果可手动“核对清理结果”，只读取原条目是否仍存在，不再次删除。其他账号看不到此页的私人记录，主管也不能替员工设置期限。

## 存储与权限

- Java App 模块沿用 V26 MySQL 审计，动作 `LIFECYCLE`，在私有桥接 HTTP 之前持久化请求编号和内容摘要；审计失败不派发。成功的相同请求只读取当前控制状态，未决请求禁止重放；更换状态、期限、正文版本或控制版本的同编号请求返回冲突。
- Python 在现有受操作系统锁保护的 `bridge_receipts/write-receipts.sqlite3` 增加 `memory_lifecycle` 与 `memory_cleanup_event`。控制、修订号和控制变更审计同事务保存；只存所属账号、记忆编号、摘要、期限和状态，不复制私人正文或异常原文。
- 控制记录与原生记忆分开，避免 Mem0 更新正文时丢失控制字段。无记录的既有记忆保持原状。控制修改同时核对正文摘要和控制修订号，不假定其中一项版本能够代替另一项。
- 浏览器使用 `POST /api/agent/memories/{id}/lifecycle`、`GET /api/agent/memories/lifecycle` 和 `POST /api/agent/memories/{id}/cleanup/verify`。身份从登录主体取得，修改要求确认；核对要求 `X-Agent-Action: memory-verify`。私有桥接再次校验当前记忆的账号、应用和摘要。没有注册给 Agent 的控制或删除工具。
- 服务端校验未来十年以内、带偏移的期限，归一化为 UTC+8。个人列表、清理记录和编辑框显示北京时间，浏览器时区变化不改变保存的时刻。

## 检索与自动调度

原生向量存储采用轻量委托包装，在 Mem0 检索及提炼读取既有记忆时排除停用、过期或清理未决的条目；桥接搜索返回前再次核对。存储不可用则失败，不退回未过滤读取。管理列表始终允许本人查看仍存在的停用/过期条目。原始聊天和 Mem0 内部会话历史仍可能包含同样的信息；本轮不声称抹去原会话上下文，或阻止后续新对话生成一个新编号的相似记忆。

FastAPI 生命周期启动一个默认每 60 秒的调度器。它沿用单写入槽、唯一执行线程及同目录进程锁，与自动提炼、编辑、删除串行；忙时本次调度跳过，不累计后台队列。每批最多 5 条、开始下一条前检查 2 秒软预算；这不是原生操作的硬取消期限。尚未勾选自动删除的到期记忆只排除检索。

清理先持久化 `READY → RUNNING` 与事件，再读取当前原生记忆。账号、应用或正文版本与确认时不一致时进入 `NEEDS_REVIEW`，不删除新版本。删除后实际读取不存在且没有 SDK 错误信号，才记 `SUCCEEDED`；异常或无法核实的结果记 `NEEDS_REVIEW`，不会进入下一轮自动删除。完成审计也无法保存时暂停新的自动提炼/清理，保留未知状态。

进程重启取得文件锁后，把遗留 `RUNNING` 转为 `NEEDS_REVIEW`。核对只可在原条目已经不存在时收敛成功；仍存在则继续待核对。用户可重新读取现有正文、调整未来期限并重新明确确认，建立新的控制版本。不同数据卷或不同服务器不受同一文件锁协调，本轮仍是单桥接进程方案。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `MEM0_LIFECYCLE_CLEANUP_ENABLED` | `true` | 允许调度本人已经确认的自动删除；关闭不取消检索端的停用和到期过滤 |
| `MEM0_CLEANUP_INTERVAL_SECONDS` | `60` | 调度间隔，允许 10–3600 秒 |

关闭调度只延后清理，不撤销已经在执行的删除。ECS 停机期间不运行调度，重启后继续检查到期且未尝试的条目，不自动重做未知结果。

## 兼容与依据

复用 [Mem0 官方开源示例中的应用层到期清理方式](https://github.com/mem0ai/mem0/blob/main/docs/cookbooks/essentials/building-ai-companion.mdx) 与现有 Apache-2.0 依赖；核对本机固定 SDK 的 `get/delete` 和 Chroma 向量存储接口，不新增运行依赖、不替换 AgentScope 执行框架。没有把托管平台的 `expiration_date` 功能当作当前开源 SDK 的现成功能。

本轮没有新 MySQL 迁移，Java 审计仍在 V26；桥接控制表通过现有私有 SQLite 连接非破坏性创建。Dockerfile 同步包含 `lifecycle.py`，最终 Jenkins 发布会与上一轮 Mem0 回执协议统一构建/回滚。备份须同时保留整个 Mem0 卷中的向量、历史和桥接回执；不能仅还原向量后删除控制回执，绕过未知操作保护。新代码回滚不会删除新表。后续已补齐跨版本回滚保护：目标 Mem0 过旧时保留兼容桥接，仅回滚后端和网页；新旧客户端通过私有协议头兼容，检索控制不降级。无兼容桥接或无法核实时保持后端停止，见 [回滚兼容保护](Mem0跨版本回滚兼容保护.md)。该门槛已有代码与本地验证，真实 Linux/Docker 回滚演练仍须在统一发布前通过。
