# 旧 45 表与当前 131 表的列演进对账

本项仅解决两张表的列结构差异，不代表旧数据已经合入业务库，也不授权删除本地原件或切库。

已认证的只读结构核对显示，旧 45 张表均存在于 131 表源中。43 张表的完整有序列定义及主键相同；`detection_task` 从 63 列尾增至 77 列，`model_management` 从 27 列尾增至 32 列。没有旧列缺失、旧列类型属性变化或主键变化。核对元数据 SHA-256 为 `5fedf7fd1e1d95a0533d5ee201aad2e2a7489f5950d56519137e4494ffb94e0f`。

分类器保留原有 131 表完整列、完整行摘要和完整主键索引。针对这两张表，只有旧、新完整列向量的固定 SHA-256、旧列有序前缀、列数及 `id` 主键均完全符合已审定规则时，才允许额外采集旧列投影。新增列本身仍参加 131→29 整库迁移及恢复验收，不会从源快照或业务迁移中排除。

`preserve-local-mysql.ps1` 在原 45 表独立双恢复成功后调用 `collect-local-mysql-legacy-projection.py`。采集使用本轮已经准入的隔离源副本及 `whole-migration.json` 中现有迁移账户，不新增账户、授权或生产连接。采集前校验：

- 原始完整 131 表快照与隔离源副本的完整快照、元数据相等。
- 本轮实际 MySQL 项目 PASS 的原报告目录同时绑定执行回执与整库迁移摘要。
- 该摘要绑定真实整库迁移回执、双恢复证明及最终源/目标读回；现有 runtime 继续核验迁移回执的完整证明链。
- 迁移配置与整库验收使用的已审阅配置一致，源容器、服务器 UUID、端口、数据目录及源副本身份吻合。

采集使用既有 `MYSQL_LOCK_TABLES_READ` 机制锁定隔离副本的全部 131 表，在完整源快照及元数据的前、后两次检查之间读取两张表的完整旧列向量。投影复用现有行哈希和有序主键编码。任一源变化、配置或证明变化都拒绝发布最终回执。

PowerShell 通过固定认证 SSH 另行取得投影回执原字节摘要，并收集无业务行的回执；分类器按该外部摘要重新验证完整投影成员、逐行摘要链、原完整源索引及主键集合。对账结果会明确标记 `SAME_BUILD_FULL_131_FROZEN_SOURCE_CLONE`，只证明该次冻结源快照中的包含关系，不宣称此后生产源没有变化。

43 张结构一致的表继续使用原完整行索引比较。没有投影、未经审定的任何列属性或主键变化均阻止切库；旧键缺失或真实旧列值冲突仍返回 `NEEDS_REVIEW`。全表结构分类依旧如实显示两张表的完整列差异，逐键比较另行说明使用了经审定的完整旧列投影。

新增代码仅做静态检查，尚须在已提交的固定源码上由本地 Jenkins 调度 ECS 验证。`tests_python.test_local_mysql_source_classification` 的合成契约从 112 项增加至 130 项；新增的源码归档契约直接执行 PowerShell 内嵌读取器，并核对采集器全部依赖的真实路径，防止模拟 runtime 掩盖 `script/schema` 与 `scripts` 的接线错误。CI 最低计数需在合并时同步更新。整库迁移、前后端及运行验收门保持不变。
