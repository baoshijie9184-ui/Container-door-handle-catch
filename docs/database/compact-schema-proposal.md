# 当前 29 表业务模型候选

2026-11-05，源码实现中，尚未完成 ECS 建库、迁移或业务验收。针对中国铁路集装箱公司的单企业、多角色、多用户场景，当前候选为以下 29 张业务表。计数包括公共流程、审计和运行状态，不通过另设活动业务库、兼容视图或保留旧表规避上限。MySQL 系统表不属于业务模型。

此前 28 表建议把独立复查工单归入公共流程，复核现有查询和状态后撤回这项合并，保留专表，得到 29。这个数字不是已部署表数，也不是最少表数证明。现行 `compact-schema-contract.json` 与 `sql/mysql/compact/baseline/` 表达此候选；第一版 30 表清单仅作为历史审查材料，不再用于建库。

## 为什么这次共用有依据

### 一个操作协议，保留不同业务规则

幂等回执、一次后台工作、人工审批和工作台事项都具有稳定身份、输入、状态转换和结果，可以使用同一操作协议。共用的是持久化与并发机制，业务资格、状态机及保留期限由具体类型定义。需要实际实现这一层，不能只将旧表改名为 workflow。

- 重复图片复查使用独立 `detection_duplicate_ticket`：原有两侧任务、图片证据、负责人、结论和审核人保持明确字段。它没有后台领取租约，也不需要虚构一个数字 owner 才能适配通用流程；通用领取器不能接管人工判定。
- 额度申请仍由主管审批。审批实例记录过程，`llm_quota` 是额度当前值的权威来源，`llm_usage` 是变动流水；审批、入账和审计在同一事务内完成。
- 逻辑任务每个任务一行，不再覆盖同一会话主工作项中的旧 logicalTaskId；每次实际 Agent 执行关联独立 `agent_run`。
- 永久幂等信息独立于执行正文的清理，资源删除后请求号仍不能重用；不同类型各自保留原有唯一范围。
- 发送与消费是不同实例；发送成功不能代表消费完成。租约到期也不能代表外部进程已退出。

因此，各模块重复的 command/outbox/request 持久机制以及独立对话队列可以复用流程层。独立复查工单、设备领用、设备告警、检测任务和报告仍保留领域表；共享执行机制不能替代它们的业务身份。复查表的 20 列保留、索引、状态约束和迁移边界见 [独立复查工单](compact-duplicate-ticket.md)。

### 一个内容版本协议，保留权限和用途

知识、技能、附件、来源证据都有稳定内容身份、版本或快照、原文/文件、摘要和引用，可共享四张内容表。技能审批必须绑定具体版本和摘要；技能角色权限与知识可见性分别校验，不能把普通知识内容当可执行技能。

文件位置、对象版本、摘要和大小属于具体内容版本，本版不另建去重文件目录。跨所有者内容不因摘要相同自动合并业务身份。上传前的路径预留及中断后恢复归上传流程，版本登记在内容层；清理需核对所有历史版本、业务引用、进行中的操作、安装和保留凭据。

文件删除需要先登记删除状态、禁止新增引用，并核验对象版本；路径锁仅解决并发，不能单独证明可以删除。模型删除不能连带删除仍需保留的版本和清理凭据。

调研来源保留 owner/run/call、来源、摘要、有效期和清除证明。允许到期清除内容字节，但摘要及来源身份不变；不能把被清除的正文标成从未存在。上下文历史摘要、工具来源和附件切点使用明确的内容类型或不可变事件；当前指针、bootstrap 和 SDK checkpoint 采用独立状态键，分别定义不可覆盖或 CAS 更新规则。

### 额度账户和流水各司其职

`llm_quota` 保存余额状态，`llm_usage` 保存逐笔变动，LLM 请求根、供应商调用尝试和执行 fencing 由相应流程实例关联，避免在流水表中混装多套执行实体。一次调用涉及企业额度和个人额度时，按账户分别产生流水，并在固定账户锁顺序下同事务提交。

预留、实际结算、释放和授额分别有独立操作键，重试不得重复扣减。存在结果未确认的外部调用时，不能只因超时释放预留。供应商返回的额度观测记录保留时间和来源，不等同于本地可用余额。

个人额度记录缺省时保留已有模型使用权限；显式配置个人额度后才检查和扣减。额度数值、关联账户、操作 ID、状态和唯一键保持结构化，不藏入通用 JSON。

## 不能遗漏的旧功能

- 身份回填批次与条目：批次是流程实例，每条待应用映射也是独立子实例；任务、角色、目标员工、版本和证据版本有明确列及约束。当前可信绑定回到任务相应角色字段，变更历史进入事件；不把整批明细装进 JSON 数组。只读核对报告的每条不可变发现采用独立事件并关联报告实例。
- 日报：计划在 `scheduled_plan`，每次生成在流程表，输出为冻结内容版本；人工审批报告仍在 `quality_report`。
- 连接器：登记在 connector，历次安装及并行执行各有流程实例；镜像/包在内容版本，保留引用在 link。进程退出未确认时不得释放镜像保留。
- 凭证撤销：状态键包含供应商及密钥指纹，禁止通用清理、TTL 和恢复成有效；撤销另有审计。加密密钥不得进入普通内容正文。
- 历史孤儿证据：保留原身份及摘要，禁止猜测归属或过滤掉不匹配记录；迁移遇到无法表达的关系必须解决后再切换。

## 决策与未决项

当前按 29 张继续实现，保留 30 的总上限，不提前创建“备用表”。未来若有不能自然表达的独立关系，应重新论证，不能为固定表数放弃约束或把旧行藏入任意 JSON。

仍需证明流程各类型的键和事务边界、额度预留/结算守恒、内容引用及清理协议。当前已存在部分 DDL、生产适配与迁移源码，不能等同于整库完成。只有字段、约束、查询、迁移和 ECS 验证都通过，才能确认实际交付结构；本轮没有运行数据库或测试，也没有操作 ECS。
