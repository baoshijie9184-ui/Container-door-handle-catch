# LLM 模型管理与额度持久化

2026-11-06。适用中国铁路集装箱公司单企业、多角色、多用户。本文记录 29 表候选中的已落盘实现；数据库迁移、并发行为和界面操作尚未在 ECS 验收，不能作为已部署说明。

## 数据职责

| 数据 | 目标结构 | 约束与用途 |
| --- | --- | --- |
| 企业及个人账户 | `llm_quota` | `MODEL` 表示本企业该模型账户；`USER` 表示指定用户的个人账户。当前使用 `TOTAL` 周期，不自动重置 |
| 预留、结算、退还、额度调整及历史已知用量 | `llm_usage` | 与账户更新同事务提交；请求流水引用实际流程，历史导入流水引用原始审计快照 |
| 模型请求、供应商尝试、额度配置和个人申请 | `workflow_instance` | 独立类型、状态机、请求摘要和版本；永久幂等身份防止同请求再次批准或派发 |
| 供应商核对、申请处置、旧调用和旧配置审计 | `audit_event` | 保留当时操作者、原值与发生时间；供应商核对是人工登记的时点值 |

不存在个人账户时，保留用户原有模型使用权限。存在个人账户时，同次调用同时约束企业账户与个人账户，并分别留下流水；企业总额度不会因为批准个人申请而增加。空上限表示该层未设上限，数值零表示没有该层可用额度，两者不能互换。

个人额度创建以前发生的调用不追扣给新账户。失败或未知的供应商调用不因为退出登录、取消页面或重启就被当作未发生。

## 调用和记账

服务端把实际账号与运行编号放入 Reactor 上下文，主 Agent、专业委派和摘要调用沿现有异步链传递。每次逻辑模型请求有自己的根编号，每个备用模型尝试有独立编号。未取得已提交的准入回执前不发送供应商请求。

准入按企业账户、个人账户顺序锁定，核对到期、可用量与历史未核实状态，原子预留。没有个人账户时，只写企业账户流水；之后新建个人账户不改变既有尝试的记账对象。SDK 内部重试限制为一次，受管备用尝试单独准入。

预留量根据消息、工具和输出上限估计，不是精确 tokenizer 计数或供应商账单的绝对上界。服务端限制实际输出参数，并拒绝覆盖模型、凭据、端点和额外历史的请求参数；OpenAI Responses 在准入前使用当前 SDK 映射器检查不支持的字段。多媒体无法取得必要上下文上限时拒绝准入。

只有成功完成且输入、输出 token 均完整报告时，才按报告的实际量结算。实际消耗超过预留仍完整入账，账面可用量允许为负，后续准入停止。失败、取消或用量不完整保留预留并进入核对状态；相同完成回执重放幂等，矛盾回执拒绝。记账失败不启动备用调用，也不伪装为供应商成功已记账。

当前尚未交付人工核对未知尝试、释放有证据支持的预留及清除旧未知计数的完整协议。不存在通过调整总额度或登记供应商余额直接抹平未知用量的入口。

## 个人申请与审批

主站入口为 `/agent/model-quotas`，导航名称“LLM 模型管理”；独立 Agent 页面链接到同一管理页。原检测模型管理页面继续管理检测模型，企业模型额度页面供主管登记企业上限和供应商核对记录。

| 接口 | 行为 |
| --- | --- |
| `GET /api/agent/model-quotas/mine` | 返回实际模型目录、本人的账户情况、预留/已用/可用量及企业阻断原因 |
| `GET /api/agent/model-quotas/applications` | 本人申请或主管可见的企业申请，按游标分页及状态筛选 |
| `POST /api/agent/model-quotas/applications` | 提交模型、申请追加的 token 数量、理由及请求编号 |
| `POST /api/agent/model-quotas/applications/{id}/decision` | 当前企业主管批准或拒绝；必须提供读取到的版本、理由和请求编号 |
| `POST /api/agent/model-quotas/applications/{id}/cancel` | 本人取消尚未处理的申请，提供版本及请求编号 |

申请数量表示追加量。首次批准创建个人账户，后续批准增加总量，保留已用、预留和既有到期时间。申请与批准时都核对模型仍有有效配置；已有个人无限额配置时不接受重复额度申请。后端严格接受 JSON 整数，单次申请上限为 1,000,000,000,000 tokens。

申请状态只有 `PENDING → APPROVED / REJECTED / CANCELLED`。账号按 ID 顺序锁定后重新检查身份，再锁申请、模型配置控制和账户。申请终态、额度增量、流水和审计同事务提交；同一操作者的请求编号不能跨申请重复使用。响应禁止缓存。页面在结果未知时保留原请求编号重试，账号切换清除旧账号的列表和待处理操作。

页面区分没有个人账户、未设个人上限、数据未知、真实零值及实际超用后的负值。企业额度页面单独展示预留量和历史未核实记录；这些记录的已报告消耗属于已知下限，不显示成精确供应商余额。

## 历史迁移及验收

V64 四张旧额度表的处理见 [旧模型额度迁移](compact-model-budget-migration.md)。旧尝试没有用户身份，迁移保存匿名完整快照及企业已知消耗，不伪造用户或历史请求。有限企业账户存在未核实历史时暂停新准入；删除账户或减少未知计数受数据库保护。

新增个人申请、额度双账户记账、并发核对幂等、真实 SDK 上下文和历史双库迁移用例均须在 ECS 执行。本地 `test-compile` 与前端构建仅证明源码可编译，不证明数据库约束、权限竞争或界面交互已经通过。独立记忆、RAG、探测和站外调用不属于当前受管路由的额度覆盖范围，完整交付前须明确这些调用的治理边界。
