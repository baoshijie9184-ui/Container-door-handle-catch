## Redis 缓存

原 Redis 配置将普通 HTTP `ObjectMapper` 交给通用 JSON 序列化器，但没有保存恢复领域类型所需的元数据，模型详情命中缓存后可能得到 `LinkedHashMap`。

现使用独立 mapper 保存类型信息，读取入口固定为 `Object`，由 Jackson 消费类型封装。允许的类型限制在当前模型、设备实体、分页及指定的 JDK 容器和标量；未允许的运行时类型直接拒绝。HTTP mapper 保持原配置。读取入口也避免 `Map.of()` 的类型标记残留在业务 Map 中。配置沿用 Spring Data Redis 的[每缓存序列化与 TTL 接口](https://docs.spring.io/spring-data/redis/reference/redis/redis-cache.html)。

新键前缀为 `<APP_REDIS_KEY_PREFIX>:cache:v2:<cache>::`。旧无类型缓存留在原命名空间并按原 TTL 过期，未执行清库。原每类 TTL、空值限制和事务后缓存操作保留。回滚旧应用时不得把 v2 数据复制回旧空间；旧空间可能仍含旧缓存或旧格式问题，须核对实际 TTL 和指定缓存范围后处理，不能清除 Redis 中的队列、锁或其他业务状态。

回归覆盖模型类型、训练日期、BigDecimal、新计数及派生比例，设备大编号与嵌套列表、统计 Map、不可变集合、告警分页、未知类型拒绝及命名空间/TTL。真实 Redis 检查仅使用随机 `verify` 前缀和 60 秒 TTL，结束后移除自身测试键，不读取或清空应用缓存。

4. 旧字段 SQL 读取和更新后新增事实仍保留，再执行迁移不改变事实；合法零未检出可回读。
