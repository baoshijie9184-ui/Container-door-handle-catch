## 三种材料分别保管

| 材料 | 用途 | 保存位置 |
| --- | --- | --- |
| 模型主密钥 | 解密 MySQL 模型快照及 Mem0 提炼模型信封 | ECS 发布目录、运行目录、源码及数据备份目录之外的专用 Secret 文件 |
| 恢复公钥证书 | 加密独立密钥包、验证离线恢复证明 | ECS 专用目录，按 DER SHA-256 手工核实并写入私有策略 |
| 恢复私钥 | 离线解密密钥包、签署实际恢复证明 | 操作者的可信离线环境；不上传 ECS、Jenkins、Git 或镜像 |

新增 `script/docker/model-secrets.py`，复用现有 Python 标准库及 OpenSSL CMS。密钥包使用 AES-256-GCM，RSA-OAEP/SHA-256 包装，要求 RSA 至少 3072 位。未引入新的 Agent 框架或 Python 加密依赖，也不会自动安装环境。参考 [OpenSSL CMS 官方文档](https://docs.openssl.org/3.0/man1/openssl-cms/)；运行环境需具备支持相关算法的 OpenSSL，实际兼容性仍待后续验证。

主密钥是 Base64 编码的随机 32 字节。文件的宿主机组为 `10001`，权限为 `0640` 或 `0440`，供现有 Java/Mem0 容器的 `10001:10001` 读取。策略与备份文件为 `0600`，备份目录 `0700`。拒绝符号链接、硬链接、异常大小及不安全路径；Secret 与证书的上级目录不允许组或其他账号写入。

Compose 的文件型 Secret 使用宿主机绑定挂载，不能依靠 `uid/gid/mode` 字段重映射文件权限，应先正确设置宿主机权限。见 [Docker Compose secrets](https://docs.docker.com/reference/compose-file/services/#secrets)。

## 私有策略与首次准备

参考 `deploy/model-config-policy.json.example`，实际策略仅放在已有服务器运行目录的 `deploy/model-config-policy.json`，不要复制到开发仓库。字段为 `schema`、`enabled`、主密钥文件、独立备份目录、恢复公钥证书及证书 DER SHA-256。未知字段或不匹配的证书摘要直接失败，不接受策略内的密钥正文。

没有策略时保持现有功能关闭。首次生成主密钥前，必须先确定没有需要保留的既有加密配置；已有配置只能恢复原密钥，不能用新随机密钥替代。运维工具不自动生成、覆盖或轮换主密钥。主密钥更换需要单独的全历史重加密迁移；供应商 API Key 的正常版本化替换仍通过原主管页面完成。

准备过程由操作者在可信环境完成：

1. 在离线环境创建并加密保管恢复 RSA 私钥，仅将公钥证书传到服务器。独立核对证书 DER 摘要。
2. 在服务器创建发布树之外的 Secret 与独立备份目录，放置原主密钥或首次初始化密钥，并设置权限。策略也放置在原运行目录中，不进入 Git、镜像、`cloud.env` 或数据卷。
3. 运行显式独立备份命令生成加密包。此时缺少恢复证明是正常的，工具只报告元数据，不会打印密钥。

```bash
python3 -B script/docker/model-secrets.py backup \
  --root /home/ecs-user/doorhandle-ci \
  --runtime /home/ecs-user/doorhandle-release-20261014
```

4. 将对应备份子目录的 `manifest.json` 和 `master-key.cms` 复制到可信离线环境，保留一份异机副本。仅保存在 ECS 的加密包不能防止同机磁盘丢失，不能称作已完成异机备份。
5. 在可信 Linux 环境恢复到**新文件**。工具交互式隐藏读取恢复私钥密码；自动化时只接受已经打开的密码描述符，不接受命令行密码。Windows 文件权限模型不同，本工具不自动迁移环境，可使用已经具备的可信 Linux 环境。

```bash
python3 -B script/docker/model-secrets.py restore \
  --bundle /srv/offline/doorhandle-bundle \
  --recipient /srv/offline/recovery.crt \
  --private-key /srv/offline/recovery.key \
  --destination /srv/offline/restored-master.key
```

6. 工具确认解密后的实际 32 字节与原摘要一致，写入新文件，并使用恢复私钥签署 `restore-proof.cms`。把证明文件传回服务器对应加密包目录，权限 `0600`；恢复私钥及恢复出的明文密钥不随证明上传。

证明包含包摘要、主密钥摘要、证书摘要和恢复时间，不包含密钥。服务器用手工固定的证书验证签名，拒绝用包内任意证书替代信任来源。`-noverify` 仅用于跳过公共 CA 链，仍验证固定证书的内容签名；证明并非“存在一个文件即可”。

操作只创建新文件，未知结果时先核对已有文件，不自动覆盖。失败后可能留下 `.pending-*` 加密目录或已经恢复的新密钥文件，它们不作为完整备份自动采用；应按原结果核对，不能通过清空文件后盲目重做。

## Jenkins 与回滚

`deploy-remote.sh` 读取原运行目录中的私有策略，按需叠加 `compose.model-config.yml`，backend 与 Mem0 挂载同一个 Secret。`pipeline.ps1` 只传代码工具，Jenkins 不持有或上传主密钥、恢复私钥。

每次应用激活前检查：策略、文件权限、独立加密包、离线签名证明、Compose 实际 Secret 来源、两服务挂载以及目标镜像格式标记。成功后固定主密钥摘要。删除策略、换密钥、静默关闭模型管理或回滚到不支持格式的镜像均被拒绝，且发生在停服务之前。

backend/Mem0 镜像声明 `io.doorhandle.model-config-format=1`。首次启用还要求当前可回滚基线镜像支持该格式；没有兼容基线就拒绝启用。**首次启用的基线切换、完整迁移和最终统一发布仍需后续完成，不能把新增标签当作当前生产已可直接启用。**不兼容的旧镜像不能凭健康接口通过而宣称完成了兼容回滚。

Jenkins 源码默认 `ACTION=verify`，`PRODUCTION_RELEASE_ENABLED=false`，避免开发阶段 SCM 轮询直接发布。发布及回滚要求最终验收后显式启用；本轮没有修改实际 Jenkins 作业或触发流水线。

激活回执仅记录公开格式元数据及摘要，保存到私有服务器状态，并由 Jenkins 归档 `model-secret-transition.json`。主密钥和恢复私钥不会进入日志、浏览器或归档。

## 数据备份、恢复与候选隔离

`monolith-ops.py backup` 在一致性备份前核对并关联独立加密密钥包及签名恢复证明，将 `modelKeyEscrow` 元数据写入快照清单。不会把明文 Secret 混入数据库备份、文件卷或普通 `cloud.env` 副本。相同主密钥及接收证书复用已验证的不可变加密包，证书变化需要重新生成及离线证明。

`check` 只检查已有策略、密钥包和证明，不创建备份。已有 23:00 备份时间和 00:00 节省停机设置不变。定时服务的目录保护仍保留，新的加密包及证明须先显式准备好；不会为了绕过保护去扩大整个宿主机的写权限。

数据库恢复演练遇到加密配置快照时，还需提供原外部策略以匹配密钥证明。它验证的是“数据恢复与密钥证明关联”，不能替代启动后的实际解密和业务验收。Java 与 Mem0 新增启动时已有加密历史检查；错密钥、损坏信封不回退到覆盖历史或重新初始化。

隔离候选只在明确核对策略与快照后，允许 backend/Mem0 读取唯一白名单的文件型 Secret；不复制进候选卷，不允许任意宿主机 Secret、其他服务挂载或清理源文件。数据库、Redis、网络及其他数据卷仍为独立副本。候选旧版本格式不兼容则拒绝启动或回滚，不以关闭配置开关伪造通过。

当前还没有实际创建或恢复任何密钥包。后续需完成首次基线切换、最终迁移/回滚编排，以及真实 Secret 权限、离线恢复签名、错密钥拒绝、候选隔离、两服务重启和发布后的完整验收。五类任务整体仍未完成。
