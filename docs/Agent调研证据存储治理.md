# Agent 调研证据存储治理

更新日期：2026-10-16。分支：`java-cloud`。对应 D34 / P15，建立在 [来源登记与引用追溯](Agent调研来源与引用追溯.md) 之上。

## 已实现范围

| 能力 | 实际行为 |
| --- | --- |
| 账号配额 | 使用稳定 userId 统计所有运行中仍未过期的来源，默认每账号 500 条；员工和主管分别按本人账号计数 |
| 运行配额 | 保留每次运行最多 20 条来源；账号配额与运行配额同时适用 |
| 并发保护 | 同一账号先锁 V32 账号行，再锁本人运行行；READ COMMITTED 事务内查重、检查配额并登记，防止不同运行同时占用最后一份额度 |
| 幂等 | 相同 callId、请求哈希和返回哈希重试，优先返回原编号；额度已满时也不会重复扣减 |
| 到期内容清理 | 单独开启后，后台清空已过期来源的 requested_url、title、excerpt；不清空仍可查看的来源 |
| 清理审计 | sourceId、userId、清除的 UTF-16 单元数和数据库时间与内容更新同事务提交；审计失败则内容更新回滚 |
| 历史引用保留 | 来源行、编号、运行和调用编号、请求/内容哈希、片段长度/范围、抓取/到期时间及回答引用关联均保留；历史页仍可显示过期数量 |

来源可查看期沿用数据库时间起算的 30 天。过期即不再占账号有效来源额度，与清理任务是否运行无关；读取 API 同样不等待后台清理才隐藏内容。没有覆盖未过期来源或自动淘汰最旧来源的行为。

达到配额时，Fetch 返回固定受控错误，未成功登记的网页正文不交付模型，MCP 会话和并发许可仍会释放。额度检查在来源登记事务内执行，网络抓取仍在事务外，所以达到配额的调用可能已经执行了网络抓取。

## 开关和迁移

默认不启用来源登记、存储治理或到期清理。仅使用已有 V31 来源登记的部署，不需要为关闭的治理功能执行 V32。

在目标库备份并确认已有 V16、V31 后，手动执行以下新增表脚本；应用不会自动迁移：

```sql
SOURCE /path/to/sql/mysql/migration-V32-agent-research-storage.sql;
```

V32 只新增 `agent_research_storage_owner` 和 `agent_research_content_purge`，没有删除或清空已有内容的 SQL。相同副本打包在 AI 模块 `classpath:db/migration-V32-agent-research-storage.sql`。

环境示例：

```dotenv
AGENT_RUN_JOURNAL_ENABLED=true
AGENT_RESEARCH_EVIDENCE_ENABLED=true
AGENT_RESEARCH_STORAGE_GOVERNANCE_ENABLED=true
AGENT_RESEARCH_MAX_SOURCES_PER_USER=500
AGENT_RESEARCH_EXPIRED_CONTENT_PURGE_ENABLED=false
AGENT_RESEARCH_CLEANUP_BATCH_SIZE=100
AGENT_RESEARCH_CLEANUP_DELAY_MS=60000
```

这组配置只开启账号配额。需要清理过期展示内容时，再明确设置 `AGENT_RESEARCH_EXPIRED_CONTENT_PURGE_ENABLED=true` 并重启后端。仍需原有 Fetch 安装、启用及权限条件，不会因配置变化自动安装工具。Compose 使用部署环境文件将配置传入后端。

配置范围：账号配额 1—10000、每批 1—500 条、固定维护间隔 1000—3600000 毫秒。默认每批 100 条、间隔 60 秒；首次执行也等待一个间隔。治理启用时，缺少 V32 或参数越界会使后端启动失败，并提示迁移要求或参数问题。

回退可关闭清理开关，或关闭整个治理开关并重启。关闭治理后，仍保留原每运行 20 条限制；已经清空的内容不会因关闭开关自动恢复，表和审计记录均保留。

## 后台执行与边界

维护使用独立的单线程守护调度器，避免占用运行日志的共享租约维护线程；应用关闭时回收该调度器。不提供 Agent 清理工具或公开 HTTP 清理入口。

每批只获取配置上限数量的过期候选，并对候选查询设置 5 秒 JDBC 查询超时。每条使用独立、最多 5 秒的事务，再次锁账号、核对过期状态和既有审计。多实例处理同一条时按相同账号锁串行化，已清理项不重复审计；单条失败不会撤销此前已经成功提交的条目。

获取候选后设置 2 秒的调度预算，超过预算不再开始下一条；这不等于整批严格在 2 秒内完成，已经开始的事务可额外耗时，JDBC 超时效果也依赖驱动和数据库。维护失败只输出固定警告，下个间隔重试；不把网址、摘录或异常原文写入维护日志。

配额按**未过期来源条数**计数，不是磁盘或字节配额。清空展示字段不会删除数据库行，也不保证回收 InnoDB 文件空间；来源元数据、账号锁行、回答关联和清理审计仍会增长。哈希仍是原返回文本的摘要，不改成空字符串的哈希。

本功能不清除备份、数据库日志、已有聊天消息或其他系统保存的内容，不能称为彻底删除个人数据。后续 D35 已补 [本人确认的来源导出与摘要审计](Agent调研来源导出与审计.md)，需单独启用。完整物理归档、元数据/审计保留期、字节配额和备份恢复仍属 P15；最终重定向地址、完整网页快照和语义核实同样尚未完成。

## 开源实现依据

沿用当前 Apache-2.0 的 Spring 事务支持和 MySQL/InnoDB 锁机制，复用现有 AgentScope Java 2.0.4 的来源登记链路，不增加依赖或复制外部源码。实现前核对了 [Spring 编程式事务说明](https://docs.spring.io/spring-framework/reference/data-access/transaction/programmatic.html) 和 [MySQL 8.0 锁定读取说明](https://dev.mysql.com/doc/refman/8.0/en/innodb-locking-reads.html)，适配当前 Java 17、Spring Boot 3.2.4 和 MySQL 8 部署。
