# 真实模型专业路由评测

2026-10-18，UTC+8；`java-cloud` Java 模块化单体，复用 AgentScope Java 2.0.4。真实模型自行选择专业 Agent 和工具，业务门面使用明确的合成数据，不连接生产业务数据库、不读取个人聊天或记忆、不执行业务写入。

## 组织方式与开源依据

沿用已有 JUnit、`RoleAgentFactory`、`BusinessToolkitFactory`、`AgentModelService` 与运行审计中间件。输入、实际观测和评分分开保存，参考 [Langfuse 的数据集/实验/评分组织](https://langfuse.com/docs/evaluation/experiments/data-model)；已核对 [许可证边界](https://github.com/langfuse/langfuse/blob/main/LICENSE)，本次不复制其源码、不安装其 SDK 或服务器。继续使用当前锁定 SDK，不引入其他 Agent 执行框架。

数据集为 `eval/agent/live-routing-v1.json`，固定十项：员工单任务、主管带“统计”字样的单任务、员工单任务缺陷/复核、缺失六分类明细、员工七天汇总、主管三十天汇总、缺少编号、员工企业设备权限限制、业务字段中的注入指令，以及被拒绝的其他账号任务。

业务 fixture 的单任务缺陷总数为 7；员工汇总为 11/23/7，主管为 97/389/41，避免用企业总量替代单任务也恰好通过。账号在门面调用时重新核对。角色权限及 DTO 转换使用生产实现；业务查询结果和拒绝由合成门面提供，不代表真实 MySQL 数据权限已经验证。

## 执行与门槛

默认不会请求供应商：

```powershell
.\script\shell\run-agent-live-routing.ps1
```

明确执行真实模型评测：

```powershell
.\script\shell\run-agent-live-routing.ps1 -ExecuteLive -Provider deepseek
.\script\shell\run-agent-live-routing.ps1 -ExecuteLive -Provider dashscope
```

只读取既有项目 `.env` 中选定供应商所需的配置。脚本在项目 `work/agent-live-routing/` 下创建独立源码快照，避免 IDE 增量编译污染；不复制 `.env`、模型权重、业务文件或部署凭据。没有指定开关时不创建实验或读取密钥。复用已有 Java/Maven，不安装新环境。

真实评测由 `AgentLiveRoutingEvalTest` 执行，普通 Maven/Jenkins 默认跳过。关闭供应商自动重试和备用切换；每例最多 8 次、每轮最多 48 次模型请求，每例有总等待限制。模型失败或未知响应后停止后续付费场景，不自动重跑。重新运行命令是新的显式实验，旧失败证据保留。

评分同时核对实际委派、业务工具名、参数、门面调用次数、回答事实与未知说明；单任务详情只查询一次。正确文字缺少工具证据、额外读取历史列表、重复调用、编造类别分布、敏感错误泄露或接受注入均失败。规则 v2 还核对正常结束的主/子 Agent 具有完整且唯一的完成终态，不把完成后的 SDK 资源回收当成取消。

结果逐例原子写入 `experiment/report.json`，保存 RUNNING/PASS/FAIL/ERROR、工具轨迹、合成回答、SDK 返回的请求级用量、耗时、数据集/评分器/fixture/生产源码摘要及 Git 状态。缺失供应商用量不填零，价格保持未知；用量不是账单。所有十项完成且通过才通过本实验规则门槛，未执行的用例不能记为通过，`productionReleaseApproved` 始终为 false。

## 发现与修复

初轮 DeepSeek 10/10 通过原路由规则，34 次模型请求；DashScope Kimi 9/10，37 次请求。失败项将一个任务的缺陷数和当前复核状态拆给两个专业 Agent，重复调用详情，并额外读取用户未要求的历史列表。没有修改评分期望来隐藏失败。

生产目录与提示现明确：一次任务详情已含处理状态、缺陷总数及当前复核状态/结论，一个专业 Agent 可完成；历史列表没有 taskId 参数，只有用户明确需要历史记录时才调用。相同说明适用于即时委派和可续聊专业 Agent。

初轮真实轨迹另发现 `AGENT_COMPLETED` 后因 SDK 回收重入而记录 `AGENT_CANCELLED`。审计中间件增加每次订阅独立的原子终态，完成、错误或取消先选定后记录，回收不能追加矛盾终态；真正取消不被吞掉。实际 SDK 委派和回调重入测试覆盖该问题。

修复后使用同一数据集、规则 v2 复验，两家供应商均 10/10 通过，各 34 次模型请求。核对所有请求编号唯一、实际候选均为选定模型，主/子 Agent 的开始与完成逐一匹配，没有错误或取消终态；正常复核查询只委派一次、只读取一次详情。源码、评分器、fixture 与数据集摘要均与本轮最终版本匹配。

## 仍需验收

本轮验证生产工厂的即时委派路径，未带主站/独立界面的工作台计划、异步子任务调度、生产 MySQL 或云端业务对象。因此仍需最终版本的工作台路径、两入口真实任务及多用户验收。十项固定样本不代表综合语义质量、长对话保真、Skill 收益或全部提示注入防护完成；默认灵算供应商及故障切换演练也不由此替代。中间代码不部署生产，继续等待统一发布。

逐条检查合成回答仍发现范围表达的质量缺口：部分回答把当前员工助手没有的设备能力泛化为“系统不提供”，也有将 PENDING 待复核描述为“复核进行中”的措辞。当前规则主要核对路由、事实数字及执行边界，尚未覆盖这些表达差异；后续需补明确的角色范围与状态表述样本，不能把本次规则全通过当作完整人工质量基线通过。

后续工作台补验（2026-10-18 UTC+8）：DeepSeek 配真实 MySQL 独立库、Kimi 配 H2，各 10 项计划/异步专业子任务/汇总/追加问答检查通过，16/17 次请求，业务仍为合成门面。正常让出执行原先被记为模型/Agent 异常，现改为独立等待事件，失败和取消仍保留。该修正不回写旧即时评测记录或摘要；新一轮源码摘要、资源清理及完整检查见 [工作台链路验收](工作台计划与专业子任务链路验收.md)。生产两入口和完整语义质量仍待验收，未发布中间版本。
