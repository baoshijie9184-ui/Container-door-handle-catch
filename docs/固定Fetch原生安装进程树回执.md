# 固定 Fetch 原生安装进程树回执

2026-10-22 UTC+8，`java-cloud`。状态：新增源码及文档，未编译、测试、运行脚本、执行迁移或部署。不能据此认为服务器已具备经验证的安装退出能力。

## 设计与范围

继续使用 AgentScope Java 的 MCP SDK 连接、握手和工具发现。只监督项目已有的固定 Fetch 安装器，不接受任意命令、URL、包名或可执行文件。没有引入新的 Agent 执行框架或通用沙箱。

Linux 的 subreaper 会收养后代退出父进程后的孤儿进程；本实现结合 pidfd、启动 ticks 和当前父子关系核对后发出信号，避免仅按旧 PID 或单个进程组猜测退出。参考 [Linux subreaper 文档](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html) 和 [Python pidfd 接口](https://docs.python.org/3.12/library/os.html#os.pidfd_open)。这是针对固定安装树的实现选择，仍须验证目标内核、容器权限和异常退出行为。

## 持久身份与执行顺序

1. 安装仍由本人确认，保存原不可变版本、安装登记、有界队列、额度预留和必要审计。
2. 派发前在本人 `mcp/fetch/runtime/installers.sqlite3` 预留安装编号，生成或读取持久 pool。此时不启动 pip。重复预留不会重放安装，已经封存的编号也不能重新运行。
3. 队列领取成功的 MySQL 事务同时保存 JVM 代次、节点摘要、实际 transport 和 native pool。竞争失败的派发器不能封存胜者的预留。
4. 固定监督进程创建独立会话、开启 subreaper，先提交自身 PID/启动 ticks，再启动同目录的 `install-local-fetch-mcp.py`。运行配置摘要包含两个脚本的哈希；禁止配置另一个安装器路径后仍冒充相同运行环境。
5. 监督进程持续观察撤销、超时及逻辑文件大小。正常安装程序退出后仍有活的后代，按取消收尾；取消时通过稳定进程句柄核对并终止后代，不依赖后代是否改变进程会话。必须回收所有可等待的子进程且不再观察到后代，才记录终态。
6. 读取固定 manifest 并验证后，服务用新的执行编号向 MySQL 登记 `INSTALL_PROBE`，再调用原 SDK 握手。关闭与异常清理沿用执行回执，未知结果保留原编号，不重新安装或重复探测。
7. Java 安装 callable 真正返回时单独保存 `RETURNED`。只有 Java 写入结束、native journal 明确确认安装树已停止、该安装没有未清理协议执行，才释放安装预留。安装登记已经为 READY 而退出回执未保存成功时，也可以通过现有核对入口处理。

Java 超时或中断只提交撤销，不强杀监督进程而丢失对子进程的观察。若监督进程自身被强杀、journal 损坏/丢失、pool 改变或无法取得观察证据，保持待核对。原 JVM 不存在，只能证明 Java 阶段结束，不能代替安装树回执。当前不提供“强制确认已退出”按钮。

重复停止请求不追加同一撤销事件。journal 达到 10000 个安装记录或文件已超过 8 MiB 时拒绝新增预留，保留原记录的查询及停止，不自动清除历史。该阈值只限制新增预留，不是整个 runtime 目录的硬配额。

队列在领取前被撤销，且同事务确认不存在派发证据时，记录 `INSTALL_NEVER_DISPATCHED`；这类任务没有启动安装程序，不能与已经运行的未知进程混用。

## 文件、额度与界面

每次原生安装持久预留 512 MiB，按各安装保存的数值计入占用，切换 transport 后不把旧预留缩成网关的 2 MiB。原生模式还有未核对安装时，拒绝开始另一个安装。监督器超过 512 MiB 逻辑大小时请求取消，但它是定期监测，不是操作系统硬磁盘配额，瞬时超额、同一账号其他文件和宿主磁盘仍需运维保护。最终退出后按实际文件大小计入额度，已超额的目录不会自动删除。

清理先验证完整目录树，拒绝未审核符号链接和特殊文件。唯一允许的 venv 链接是固定 `.venv/lib64 -> lib`，仅删除链接本身，不遍历目标；删除前再次校验。当前版本、回退保留、未退出安装和未清理协议执行继续阻止删除。runtime journal 位于安装目录外，不随目录回收删除；历史 MySQL 审计保留。

现有 Vue MCP 管理页显示两阶段退出状态、安装连接检查和核对入口；独立 React 入口继续复用现有管理跳转，不新增另一套安装器。浏览器不接收 PID、pool、绝对服务器路径、pip 输出或环境变量。

## 接入条件与兼容边界

仅供后续验收配置，当前不开启：

- 顺序执行既有前置迁移及 V58，两份 SQL 位于根目录与 AI classpath；启动不自动迁移。V58 只增加 native 写入者身份与安装预留字节字段。
- STDIO + Linux pidfd，并同时配置 `AGENT_MCP_NATIVE_PROCESS_ENABLED`、`AGENT_MCP_EXECUTION_RECEIPTS_ENABLED`、`AGENT_MCP_DURABLE_INSTALL_ENABLED`、`AGENT_MCP_LIFECYCLE_ENABLED`、`AGENT_MCP_INSTALL_RECONCILIATION_ENABLED`、`AGENT_MCP_NATIVE_INSTALL_ENABLED`。新开关默认 false。
- `AGENT_MCP_STORAGE_QUOTA_BYTES` 至少 536870912；需要保留旧版进行升级时建议预留至少 1073741824，并根据实际已存大小决定能否安装。现有全局默认 268435456 不会被静默修改，不满足条件时明确拒绝启用。
- 备份 MySQL、整个 Agent 持久卷和独立密钥。journal 不能只备份到安装目录中。删除卷或清空 runtime 不能作为退出核对方法。
- 旧安装没有监督进程证据时，不能自动补造“已退出”。保留待核对，需要后续受控运维方案；不能通过重新执行未知安装取得证明。
- 回滚保留 V58 和两类 journal。后续已加入 [原生协议发布保护源码](MCP原生协议发布与回滚保护.md)，包括新执行暂停、镜像声明、持久下限与 Jenkins 接线；尚未运行，第一次兼容恢复基线与真实演练仍待完成。未经核对，不能以旧镜像回滚后重新启用本地安装。
