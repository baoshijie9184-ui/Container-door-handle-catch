# 工作台计划与专业子任务链路验收

范围：`java-cloud`、AgentScope Java 2.0.4、现有模块化单体。沿用已有 `AgentWorkbenchService`、MySQL SDK 状态、审计及有界调度，不引入新的执行框架。本验收补充即时专业委派评测，不能替代两入口浏览器及生产业务验收。

## 链路与边界

员工和主管分别提交 `/plan`，计划批准前不读取业务详情、不启动专业子任务，等待后释放模型和会话资源。测试用户通过版本化接口明确批准计划，调度器继续主任务并创建当前角色的专业子任务；父任务等待，专业 Agent 获取本人授权详情后完成，主 Agent 读取后台结果再汇总。完成后向原专业子任务追加问题，使用持久 SDK 历史回答，不重复读取业务。

真实部分包括生产 Agent 工厂、AgentScope SDK、会话服务、工作台、JDBC 检查点、运行审计和后台调度。账号目录、App 门面和业务详情采用固定合成样本；员工缺陷总数 7，主管 13，用于识别账号串用。真实供应商与真实 MySQL 是独立显式验收开关，不能把脚本模型或 H2 结果记为真实供应商/生产数据结果。

`WorkbenchExecutionFixtureTest` 在普通 Maven 中运行真实 SDK 与脚本模型。`AgentWorkbenchLiveEvalTest` 默认跳过，只有显式启用才读取既有私有 `.env` 和调用模型；每轮最多 28 次供应商请求，无重试、无备用切换，不自动重跑未知结果。报告按新目录保存阶段检查、工具与供应商事件、公开工作台 DTO、请求级用量和源码摘要，不导出 SDK 状态、数据库凭据或服务器路径。费用保持未知，用量不等于账单。

## 等待状态修正

完整轨迹发现：提交计划或委派后，工作台通过 `Yield` 保存并让出执行；审计原来将该正常控制路径记录为 `MODEL_ERROR` 和 `AGENT_ERROR`，页面显示“异常”。现登记为 `MODEL_YIELDED` 和 `AGENT_YIELDED`，主站显示“任务等待中，未请求模型”和“Agent 已保存进度并等待”。真正的失败、权限拒绝和取消仍保留各自证据；等待不代表任务完成，也不作为实际供应商请求计费证据。

会话结果 Future 完成、工作台等待状态提交和会话锁释放是相邻步骤，测试等待资源实际释放后才检验可重新领取，不能仅看 Future 已完成就断言锁已空闲。App 生产续执行仍走原持久消息队列，本测试门面只模拟其授权与续执行入口，不能据此声称队列公平性已经验收。

## 显式执行

先用现有 SSH 配置创建独立数据库和账号，仅授予该随机测试库权限：

```powershell
python script/diagnostics/workbench-live-mysql.py prepare --directory work/workbench-live-mysql-example
./script/shell/run-agent-live-routing.ps1 -ExecuteLive -Suite workbench -Provider deepseek -WorkbenchMySqlConfig work/workbench-live-mysql-example/connection.json
python script/diagnostics/workbench-live-mysql.py cleanup --directory work/workbench-live-mysql-example
```

每次使用新的空测试库和实验目录。创建前记录清理身份，部分失败也保留私有清理信息；清理核对数据库、账号和 SSH 进程身份，仅移除本次测试资源。脚本不启动 ECS、不修改应用数据库、不替换现有网页隧道或部署生产。
